## 2026-11-12 首页切歌转场（列表卡飞进大图 / 旧封面缩回）

## 2026-11-12 倒退转场（⏮）+ 「⏮ 是死键」的存量 bug
- **存量 bug（本轮最大发现）**：`queue/prev` 的 restart 分支用 `player.positionMs === 0` 判断"已在开头"，但 store 的 `positionMs` **只在 seek / 切歌时写，正常播放期间恒为 0**（文件头注释已写明）。结果播过 3 秒按 ⏮ 什么都不发生。修法：删掉守卫（`prevAction` 只在 `at>3000` 给 restart），另加 `player.replaySeq` 脉冲。
- **为什么要脉冲**：`positionMs` 0→0 不构成变化，bootstrap 的 `n.positionMs !== p.positionMs` catch 不到。脉冲同时在两处落地：bootstrap → `engine.seek(0)+clock.seek(0)`；首页 → 180ms `scale(0.975)→1` 压制反馈（用户定"要区分重播"）。
- **双向转场判定**：`tapeRects` 是上一帧快照，新 lead 在里面 → 顺播；不在但旧 lead 出现在**本帧 DOM** 的带里 → 倒退。两者都不是（随机/跨列表）→ 不转场。
- **倒退的落点比顺播准**：顺播旧封面落在环列队尾（屏外）只能淡出；倒退旧封面精确落在新列表第 1 格，走满全程 + 140ms 交接。
- **新封面入场**（用户定）：从大图位左移 72px 推入、宽高直接取大图尺寸、42% 处渐显完。位移不缩放——没有可见起点就别假装有。
- **坑：`.cs-tape:first-child` 命中每一张卡**（button 都是各自 li 的首个子元素），隐藏封面会整排消失。必须 `li:first-child`；判据加 `secondVis: visible` 反向钉住。
- **坑：evalJs 里写 `new Promise(...)()`**（多一对括号）= `(intermediate value) is not a function`，`executeJavaScript` 只报 "Script failed to execute"，不给行号。
- 判据 T6–T8 进 live-shots（倒退两份都从大图尺寸起 / 第 1 格 hidden 第 2 格 visible / 重播标题不变+关键帧在跑）；实测 `[543,593] → {n:0, back:false, coverOp:1, firstVis:visible}`，J1–J10 全绿，669 单测全过。
- 遗留：跳多首的倒退不做整排位移（步长不止一格）；切上一首时最右那格原地消失（React 删节点，300ms 半空）。

## 2026-11-12 随机播放下的切歌（列表改按播出顺序）+ 转场编排升级
- **真根因是数据不是动效**：首页 `upcoming` 取 `program[(leadIndex+k)%total]`（歌单原顺序环列），实际播出走 `orderOf`。实测 8 首 seed=12345：`order=[3,0,1,5,4,6,2,7]`，播 04 时列表第 1 格写 05、实际下一首 01——列表在骗人，随机切歌当然没有可补间的源坐标。
- 随机 = **一次打乱成固定顺序**，然后沿 order 一首首走（`stepForward`），不是每次随机抽。所以列表只要显示 order 切片，切歌仍然左移一格，转场零新增代码。
- `on-air.ts` 新增 `orderProgram()`：order 给的是**队列下标**，必须映射成曲目 id 再对齐 program；对不上就返回 null 回落环列（每日推荐刷新、混音源）。
- **点卡必须传 program 原顺序**，不能传重排后的 view——`queue/set` 会重排 items，同 seed 算出的 order 整个变，列表自己跳。顺序时两者相等，只在随机下暴露。
- **编号语义拆开**：编号 = 歌单位置（随机时乱跳 21→07→13 = 随机生效的可视化），顺序 = 播出顺序。若按播出顺序编号，随机看起来会和顺序一模一样。
- 动效四条（用户"全做"）：列表左移延后 50ms（因果：抽走→补位→落字）；飞行中段 translate3d y −9px 微弧（中间帧**只写 transform**，宽高仍由首尾插值）；`@property --cs-tint` + 700ms transition（原来未注册变量，颜色硬切）；新卡 opacity 淡入（它在位移队列里，只缺透明度）+ 歌名 `.cs-lead-roll` mask 滚动交接（离场层必须**绝对定位**，进文档流会撑高 copy 区 → 封面 flex:1 缩水 → 版面抖）。
- **坑**：①`fill: backwards` 动画 **finish 后会被浏览器移除**，1.8s 后读 getAnimations 必然 0 条（要验"动过"得在 240ms 窗口内采样）；②`animation.startTime` 要等动画 tick，而 tick 排在 rAF 之后，rAF 回调里读永远 null，延 60ms 才准；③`cs-landed` 挂 `.cs-stage`、`cs-flying` 挂 `.cs-home`，读错元素假红；④`cs-swap-copy` 现在被 flying **主动禁用**（封面由副本飞、文案由滚动交接），所有"换档必须播 cs-swap-copy"的断言改成二选一（sawFly → 判 cs-landed / 否则判 cs-swap）。
- J10 老 flaky 顺手修：`if (j10.w === 1024) break` 只等窗口宽度、不等 React 的 `vp.cols` re-render → 偶尔"CSS 4 列、DOM 5 张"假红；改成 `w===1024 && n===4`。
- 判据 T9–T12：T9 随机点前列表第 1 格 == 点后 hero（改前必红）；T10 随机 n=2；T11 lag 50ms；T12 落位后 roll/ghostAnim 在跑、900ms 回收。实测 669 单测 + J1–J10 + 39 张，连跑两次 EXIT=0。
