## 2. 这一版的做法

**一个独立样式层：`app/renderer/lib/stage-l2.css`。**

不改 `press.css` / `reboot.css` 的老规则，只在新文件里用更高优先级覆盖。
放在 `index.html` 样式链最后，加载顺序决定胜负。

### 2.1 排版

```
┌─ 56px ─┬────── 封面 min(78vh, 42vw) ──────┬─ 60px ─┬──────── 歌词 ────────┐
│        │  SIDE A · 01                     │        │  AFEIFEI THEATRE ... │
│        │                                  │        │                      │
```

- 两条 1px 竖线（`body::after` + `#rs-rail` 的 `border-left`）把版面切成三栏

## 3. 踩过的坑

1. **`clamp` 算出的值和实际渲染不一致**
   `clamp(300px, 40vh, 460px)` 在 875 高窗口下应得 350，实测却是 455。
   原因是 `press.css` 里还有两条更高优先级的 `.pr-stage-left { width: ... }`。
   → 新文件里必须写 `width: var(--l2-cover-w) !important`。

2. **`<br>` 收掉后两个词会黏在一起**
   `LIVE<br>TONIGHT` 用 `display: none` 收 `br`，结果渲染成 `LIVETONIGHT`。
   `br { content: " " }`、`word-spacing`、`::after { content: " " }` 都无效。
   → 改 HTML 结构：`programme.js:269` 改成 `<span>LIVE</span><span>TONIGHT</span>`，
   CSS 用 `span + span { margin-left: 0.62em }`。

3. **截图脚本停在登录引导页**
   新 profile 没有登录态，`setPage('stage')` 会被引导页接住。
   → 先 `window.bootDemo()` 跑内置演示曲，再 `setPage('stage')`。

4. **量到的封面是旧元素**
   在引导页上 `document.querySelector('.pr-stage-cover')` 命中的是别的元素，
   `coverShare` 一直是 15.2%。→ 必须先让舞台页真正渲染出来再量。

## 6. 第二轮补完（2026-11-01）

第一轮之后又做了三件事，以及修掉了第一轮留下的一个**假数据**。

### 6.1 修掉「封面 31.4%」是假象

第一轮报告夜间 31.4%、日间 15.2%，其实是**两边都错**：

- 截图脚本停在登录引导页，`document.querySelector('.pr-stage-cover')` 命中的不是舞台元素；
- 真正的宽度一直是 `min(33vw,405px)` → 455px → **15.2%**，我的 `!important` 没赢。

两个真因：

1. **变量被影院块盖掉**：`body` 上常驻 `cinema` 类，`body.cinema.rs[data-page="stage"]` 把 `--l2-cover-w` 改成 `clamp(360px,52vh,620px)`，读出来就是这一条。
   → 变量改挂在 `:root` + `body[data-page="stage"]`，影院档改用**独立的 `html[data-l2-mode="cinema"]`**，不再复用 `body.cinema`。
2. **宽度规则优先级不足**：`reboot.css` 的 `body[data-page="stage"] .pr-stage-left { width: min(33vw,405px) }` 是 0-2-2，我的 `body.rs[...]` 也是 0-2-2，靠顺序取胜但被影院块覆盖。
   → 改成 `html body.rs[data-page="stage"] .pr-stage-left`，并补 `max-width` / `min-width`。

**实测（真实播放，昼夜各一次）**：封面 `654×654`，占比 **31.4%** —— 昼夜一致，这次是真的。

### 6.2 播放进度线

`app/renderer/lib/stage-mode.js` + `stage-l2.css` §12：

- 固定在控制台上沿，1px 高，前景 `--pr-red`；
- 200ms 一次（不是 60fps，省帧给 L3 的 three 场景）；
- 暂停时 `transition: none`，线停住不动；
- 只在 `body[data-page="stage"]` 时可见（`.on`）；
- 影院档把它移到舞台底边（`bottom: 0`）。

这是「状态指示」不是「装饰动画」：没有任何循环、缓动或闪烁，符合 L2「无动画」的规矩。

### 6.3 L1 ↔ L2 的纸面推移

`shell.js` 的 `setPage` 拆成两层：

```
setPage(id) → 判断能否用 View Transitions → applyPage(id)   ← 原来的整套逻辑
```

- 能用：`document.startViewTransition(() => applyPage(id))`，180ms，旧页左退 14px 淡出、新页右进 14px 淡入；
- 不能用 / 同页 / 影院档：直接 `applyPage(id)`，退化成原来的硬切；
- `prefers-reduced-motion: reduce` 时 `animation-name: none`，不做位移。

**方向感是「翻过一页」，不是「换一个房间」**——位移只有 14px，配合 180ms，读者感受到的是纸面被抽走，不是页面切换。
