## 0. 定位与五条取舍

**一句话定位**：一台**能换看法**的本地优先播放器——同一首歌，四种播放页、四种歌词、任意主题，切换成本接近零。

集大成 ≠ 功能并集。十家凑一起有 200 个功能，全做是一坨。**先砍，才有风格。**

| # | 取舍 | 反例（谁这么干过） | 我们的选择 | 判定标准（做没做到怎么量） |
|---|---|---|---|---|
| 1 | **不追"功能最多"，追"切换最深"** | MusicFree 插件多但视觉平平 | 4 预设 × 4 歌词 × N 主题，切换必须无感 | 换预设 ≤1 帧、换主题 ≤200ms、换歌词 ≤100ms（§5.3） |
| 2 | **扩展性分三级，用户源放最高级但必须沙箱** | LX 的用户源直接跑 JS（E2） | 内置 → 官方扩展 → 用户源（utilityProcess + `host.*` 白名单） | 用户源调 `fs` / `require` 必须被拒，杀进程不影响主进程（§2.1 验收） |
| 3 | **取色不许污染结构** | SPlayer 全站跟随封面变色（E2） | 取色只写 `--stage-tint`，只作用于 C0/C1 | 结构层 CSS 里搜不到 `--stage-tint`（§2.5 验收） |
| 4 | **不抄 2.8 万行模组系统，也不抄 15 个可视化模式** | Folia / Folium（E0，`docs/08 §7.3`） | 先 2 个能切的舞台；注册表 + 断言把扩展位留好 | 加第 3 个舞台时**不改任何已有文件**（§3.3） |
| 5 | **性能写成预算，不写感觉** | Mineradio 的"禁止回退"（E0，`docs/07`） | §7 七条硬指标 + 测量脚本 + 降档阈值 | 超阈值 → 脚本非零退出，不是"下次注意" |

> 另有 **12 条反模式**（我们自己踩过的），见 §8。任何新代码动工前先扫一遍。

## 2. 八个维度的可取点

> 每节固定五段：**结论 / 依据 / 落点 / 参数与阈值 / 验收**。
> **落点**统一写在"新底座"目录下（`electron/` 主进程、`src/` 渲染层，分层见 `docs/48` §3）。仍在 `app/` 维护期的能力，同路径改造。

### 2.1 音源扩展（最强：LX 的机制 + Folia 的契约 + MusicFree 的声明）

**结论**：三级扩展 + 能力对象驱动 UI + `sourceRef` 强制。

**依据**：E0（`docs/47` §3，我们的 `caps` 目前是方法名字符串数组，表达不了"能读不能写"）＋ E2（LX 的用户源形态）。

| 级别 | 形态 | 谁来写 | 安全边界 |
|---|---|---|---|
| **S1 内置源** | 编译进主进程 | 我们 | 与主进程同权限 |
| **S2 官方扩展** | 独立文件，按契约加载，可单发版 | 我们 | 同 S1 |
| **S3 用户源** | 用户导入的**单文件 JS** | 社区 | **utilityProcess 沙箱**：只注入 `host.*`；无 `fs`/`net`/`require`/`electron`；限时 8s/调用、限内存 128MB；崩溃不影响主进程 |

**落点**：

```
electron/onlineMusic/
  omni.cjs             唯一对外门面（UI 只认它）
  registry.cjs         唯一注册表 + 启动断言
  capabilities.ts      能力对象与类型（20 项，见 §4.2）
  failure/generic.cjs  通用失败分类（不认识平台）
  failure/<id>.cjs     平台失败翻译
  <id>/                normalize / transport / failure / auth / types
  sandbox/host.cjs     用户源 host API（白名单，逐方法校验）
```

**参数与阈值**：

| 项 | 值 | 理由 |
|---|---|---|
| 单次调用超时 | 8s（搜索/取流）/ 30s（登录轮询） | 超了就是死了，别让 UI 转圈 |
| 连续失败 | 3 次 → 冷却 15s → 再失败 30s | 与现有 `failure.js` 一致（E0） |
| 地址缓存 | 单曲地址 5 分钟 | CDN 票据短命 |
| 并发 | 搜索 4，取流 2 | 别被对方风控 |
| 用户源 | 单文件 ≤ 200KB，方法 ≤ 12 个 | 超了不是"源"，是应用 |

**验收**：

- 装一个第三方源 → 搜索出结果 → 能播 → 崩溃不影响主进程（杀进程）→ 重启后仍列出（源被禁用）。
- 声明 `likesRead: true, likesWrite: false` 的源：收藏按钮**渲染阶段**就不出现（不是点了才报错）。
- 故意让归一化返回缺 `sourceRef` 的曲目 → 报 `source-mismatch`，不默认归属任何一家。

### 2.2 内容层：曲库与缓存（最强：Mineradio，E0）

**结论**：索引持久化 + `mtime+size` 增量 + 原子写 + 上限 LRU + 受控并发。**索引版本不匹配就重建，不写迁移。**

**依据**：E0（`docs/07` 第 3/4/5 条的索引与缓存策略；`app/main/libraryIndex.js` 193 行已有雏形）。

**落点**：

```
electron/library/
  scan.cjs       目录遍历 + 标签读取（并发 3）
  index.cjs      索引读写、增量比对、版本号
  watch.cjs      文件夹监听 → 变更推送
  ops.cjs        忘记曲目 / 缺失重定位
  cover.cjs      封面提取、缩略图、LRU
userData/library.json      索引（version + entries[]）
userData/covers/           封面缓存（sha1(path+size+mtime)）
```

**参数与阈值**：

| 项 | 值 |
|---|---|
| 索引版本 | `version: 2`；不匹配 → 全量重建（不做迁移） |
| 增量判定 | `mtime` 或 `size` 变化 |
| 扫描并发 | 3（机械盘不抖） |
| 进度事件 | 节流 200ms |
| 封面 | 缩略图 320px，单文件 ≤ 40KB，总量上限 200MB |
| 写盘 | `.tmp` + `rename`（原子）；断电不坏 |

**验收**：

- 5000 首：二次启动 **< 300ms** 出列表（§7 测法）。
- 改一首歌的标签 → 下次启动自动更新该条。
- 删一首 → 下次启动自动剔除；缺文件 → 标记"缺失"而不是崩溃。
- 扫描中强杀进程 → 重启后索引不损坏（`library.json` 可解析）。

### 2.3 播放内核：唯一音频图（最强：我们的 EQ + SPlayer 的 crossfade + Mineradio 的取消令牌）

**结论**：**全项目唯一 `AudioContext`**，效果做成可插拔 stage；切歌有淡入淡出与交叉淡化；分析任务有取消令牌与磁盘缓存。

**依据**：E0（`app/renderer/shell.js` 的 EQ/analyser 链、`gapless.js` 的预热是临时手段）＋ E2（SPlayer 的 crossfade 观感）。

```
<audio> → MediaElementSource
        → fadeStage（淡入淡出 + crossfade 增益）
        → preampStage（ReplayGain）
        → eqStage（6 段 Biquad）
        → analyserStage（fftSize 2048）
        → destination
```

**落点**：

```
src/audio/
  pipeline.ts     唯一 AudioContext 与 stage 编排（禁止别处 new AudioContext）
  stages/fade.ts  gain.ts  eq.ts  analyser.ts
  beat/worker.ts  节拍分析（Worker）
  beat/cache.ts   userData/beatcache（sha1(id+size+mtime)，量化 2 位小数）
```

**参数与阈值**：

| 项 | 值 | 备注 |
|---|---|---|
| 淡入淡出 | 切歌 220ms / 暂停 120ms | 沿用现状（E0） |
| crossfade | 0（关）/ 3s / 6s 三档 | 0 即硬切；双 `<audio>` 交替 |
| EQ | 6 段，±12dB，前级 ±12dB | 沿用现状 |
| 分析 | 大 buffer 分批 `requestIdleCallback`，BPM 进 Worker | 主线程同步会卡 1450ms（E0 实测） |
| 取消令牌 | 单个自增 `analysisToken`，每个 `await` 后校验 | 旧结果不许污染新歌 |
| 变速 | `preservesPitch`，**不手写 WSOLA** | `docs/00 §5.7` |

**验收**：

- `grep -rn "new AudioContext" src/ electron/` **= 1 处**。
- 快速连切 5 首：控制台无"旧分析结果应用到新歌"；无爆音（用 1kHz 正弦测）。
- crossfade=6s 时，两首歌交界处无静音缺口。

### 2.4 歌词（最强：我们的解析 + Folia 的排版 + LX 的桌面窗 + Mineradio 的解锁）

**结论**：**解析一次，渲染器插件化**；逐字用 `transform`/`clip-path` 推进；桌面窗穿透态可解锁。

**依据**：E0（`app/renderer/lyrics-pro.js` 769 行，四格式 + 逐字 + 智能重排，34 项回归；`docs/06` 记过"曾经并存 4 套渲染路径"这笔债）＋ E2（LX 桌面窗形态）。

| 层 | 谁最强 | 做法 |
|---|---|---|
| 解析 | **我们** | LRC / 增强LRC / QRC / YRC / TTML → 统一 `LyricDoc`；**解析在主进程** |
| 智能重排 | **我们** | 长句拆行 / 去行首标点 / 末行不单字 / 时间连续（34 项回归兜底） |
| 排版 | Folia | CJK 衬线 + 等宽时间戳；字体**自托管**，不走 CDN |
| 推进 | `docs/10 §5.4`（我们缺） | 逐字高亮用 `transform: scaleX` / `clip-path`，**禁逐帧改 `width`** |
| 桌面窗 | LX | 独立置顶透明窗 + 独立 preload（仅 3 个方法） |
| 穿透解锁 | Mineradio | 状态机 `interactive` / `click-through`，鼠标进入包围盒临时解除 |
| 渲染器切换 | **我们首创** | `press` / `karaoke` / `minimal` / `theatrical` |

**落点**：

```
electron/lyrics/       parse.cjs  formats/{lrc,elrc,qrc,yrc,ttml}.cjs  reflow.cjs
src/features/lyrics/   renderers/{press,karaoke,minimal,theatrical}.ts  index.ts
electron/desktopLyric/ window.cjs  preload.cjs
```

**参数与阈值**：

| 项 | 值 |
|---|---|
| 渲染器数量上限 | **4**（加第 5 个必须先删一个） |
| 时间源 | 唯一 `clock`；渲染器**不准**自起 `rAF` |
| 切渲染器耗时 | ≤ 100ms（只重挂 C3，不重建 store） |
| 动画属性白名单 | `transform` / `opacity` / `clip-path` / `filter` |
| 桌面窗字体下限 | 18px（低于此不穿透） |

**验收**：

- 同一首歌切 4 个渲染器：行数、首行时间、逐字时间**逐项相同**（对拍脚本 diff = 0）。
- 34 项歌词回归全绿（`tools/test-lyrics-pro.js` 搬成单测）。
- 桌面窗：移入可点、移出穿透、中键锁定、位置重启保持。

### 2.5 视觉与主题（最强：Vynody token + Mineradio 材质 + Folia 契约 + SPlayer 取色）

**结论**：token 分三层；玻璃用四段阴影**不用 `backdrop-filter`**；公开部位走 `data-part`；取色只准进 `--stage-tint`。

**依据**：E0（`docs/12` 的四段阴影配方与双轨强调色、`docs/20` 的视觉宪法 `--pr-*`）＋ E2（SPlayer 取色）。

| 来源 | 做法 | 落地规则 |
|---|---|---|
| **Vynody** | token 三层：结构 / 场景 / 玻璃 | `--ink-*`（结构）+ `--stage-*`（场景）+ `--glass-*`（材质）。**结构色永不跟封面变** |
| **Mineradio** | 玻璃 = 外投影 + 强调微光 + 顶部 1px 内高光 + 底部内阴影；112° 三段渐变；双边框 | **禁用 `backdrop-filter`**（成本高；Linux WebKit 上还会坏） |
| **Mineradio** | 强调色双轨：结构用墨，彩色只给场景 | 朱砂 `#d8341c` **仍按 `docs/20` 的 4 种用途**（主操作 / 正在播放 / 进度头 / 句号）；封面取色另开 `--stage-tint`，**不替换朱砂、不进结构层** |
| **Folia** | 注册表 + 启动断言 | 清单与实现不一致 → 启动即抛（§3.3） |
| **Folia** | `data-*-part` 公开部位（6 个） | `data-part="progress.fill"` 等；皮肤只改 CSS 不动 JS |
| **Folia** | 中文衬线自托管 | 补 `--pr-serif` 的字体文件（OFL-1.1，见 `THIRD-PARTY-NOTICES.md`） |
| **SPlayer** | 封面取色 | **只写 `--stage-tint`**，只作用于 C0/C1 |
| **SPlayer** | 频谱 | 接同一 `AnalyserNode`，**单 rAF**，上限 30fps |
| **Twilight Echo** | 可换材质 | token 数值可直接复用（保留声明） |

**落点**：

```
src/styles/tokens.css      唯一 token owner（其余文件不准定义变量）
src/styles/parts.css       data-part 公开部位
src/theme/registry.ts      ThemeRegistry + 断言
src/theme/from-cover.ts    封面取色 → 只产 --stage-tint
src/ui/*                   基础控件（10 个，见 §6.1）
```

**参数与阈值**：

| 项 | 值 |
|---|---|
| token 必填键 | 见 §4.4（缺一个 → **拒绝加载**，不静默回退） |
| 字号 | 12 级（`docs/20`），最小于 10px 仅限等宽时间戳 |
| 裸 hex | 组件层 **0**（tokens.css 例外） |
| `!important` | 新增文件 **0**；旧文件只准减少 |
| 玻璃 | `box-shadow` 四段 + `border: 1px` 双层；**无 `backdrop-filter`** |
| 取色 | 采样 8×8 中心区，量化到 OKLCH，亮度夹在 [0.35, 0.75] |

**验收**：

- 丢一个主题包目录 → 换皮成功，**不动一行 JS**；缺 token → 明确报错（不是半透明糊掉）。
- 结构层（`--ink-*` 消费处）搜不到 `--stage-tint`。
- 任意面板 `box-shadow` 同时含内高光与内阴影。
- 新文件 `grep -c "!important"` = 0。

### 2.6 交互（最强：Folia 六条 E0 + LX 的 Scheme URL E2）

**结论**：L1 输入纪律 + L2 浮层；**不做 L3 排版重排**（`docs/21` 的判定仍成立）。功能入口优先命令面板与快捷键，按钮只留主路径。

**依据**：E0（`docs/21` 六条机制；我们因缺"键盘纪律"已出过两次事故）。

## 3. 目标架构：A0–A5 六层 + 四个注册表

```
┌─ A5 生态 ──────────────────────────────────────────────┐
│ 用户源（沙箱）  主题包  Scheme URL  命令面板  主题分享    │
├─ A4 注册表（四个，每个都带启动断言）─────────────────────┤
│ SourceRegistry  StageRegistry  LyricRendererRegistry     │
│ ThemeRegistry                                           │
├─ A3 表现 ──────────────────────────────────────────────┤
│ 画布 C0 壁纸 / C1 舞台 / C2 封面 / C3 歌词 / C4 控件     │
│ token 宪法（结构色不跟封面变）                            │
├─ A2 状态 ──────────────────────────────────────────────┤
│ 单一 store（state + subscribe + 单写者）                 │
├─ A1 音频 ──────────────────────────────────────────────┤
│ 唯一 AudioContext：fade → gain → EQ → analyser           │
│ 节拍分析（Worker + 取消令牌 + 磁盘缓存）                  │
├─ A0 宿主 ──────────────────────────────────────────────┤
│ 窗口 / 托盘 / 媒体键 / 协议（id 令牌 + Range）            │
│ IPC 守卫 / 外链白名单 / 凭据（safeStorage）               │
└─────────────────────────────────────────────────────────┘
```

**依赖方向（单向，违反即 lint 失败）**：

```
A5 → A4 → A3 → A2 → A1 → A0
（上层可依赖下层；下层**永不** import 上层）
```

**为什么"数据"不是第七层**：曲库索引、设置、缓存的代码住在 `electron/library/` `electron/settings/`，对外只通过契约暴露给 A1/A2 读写。它们在**进程位置上属于 A0（宿主侧）**，**在依赖方向上不构成独立一层**——单列会让"六层"变成七个盒子，而没人能说清第七层该依赖谁。

### 3.1 三条硬规矩

1. **单一写者**：每个域只有一个模块能写 store（照 `player.ts` 的既有做法）。第二个写者出现即 lint 失败。
2. **真实路径不出主进程**：渲染层只见 id；手拼路径一律 404。
3. **平台名不进 UI**：`src/` 里平台名出现次数有上限；界面按能力开关渲染。

### 3.2 四个注册表

```ts
export interface Registry<T extends { id: string }> {
  register(item: T): void;
  list(): readonly T[];
  get(id: string): T | undefined;
  /** 启动时调用：清单与实际实现不一致就抛，防"注册表走散" */
  assert(declared: readonly string[]): void;
}
```

### 3.3 为什么必须有断言

Folia 的注释原话是"手写的表和注册表必然走散"（E0）。我们现状：`app/renderer/stages/index.js` 125 行只有 1 个舞台，加第 2 个时**必然**要改同一个文件加 if。

**断言把"必然走散"变成"启动就炸"**：加舞台只写新文件 + 注册表加一行 + 清单加一行；漏了清单 → 启动抛错，而不是"某个舞台不见了，用户以为是 bug"。

**验收**：加第 3 个舞台时，`git diff --stat` 里**不出现**任何已有舞台文件。

## 4. 四个契约与统一错误码

合并为一份 `src/contracts/plugin.ts`（主进程与渲染层共用类型，运行时各自校验）。

| 契约 | 提供什么 | 谁可实现 | 隔离级别 |
|---|---|---|---|
| `SourcePlugin` | 搜索/播放/歌词/收藏/歌单/每日/电台 | 内置 / 官方 / **用户源** | S3 走沙箱 |
| `StageProvider` | 占哪几层、挂 canvas、成本档 | 内置 | 同进程 |
| `LyricRenderer` | 吃 `LyricDoc` + clock，吐 DOM | 内置 / 主题附带 | 同进程 |
| `ThemePack` | token 全集 + 壁纸 + 动效档 | 内置 / 用户导入 | **纯数据，无代码** |

### 4.1 版本策略（三个契约共用）

```ts
export interface ContractMeta {
  /** 契约版本；破坏性变更才 +1。加载时 !== 当前值 → 拒绝并给可读原因 */
  contract: 1;
  /** 插件自身版本，仅用于展示与排障 */
  version: string;
}
```

- `contract` 不匹配 → **拒绝加载**，提示"该插件需要更新"。
- 允许**新增可选字段**而不升版本；**删除/改名/改语义**必须升版本。
- 主进程侧不做旧版兼容层（`docs/49` §8 反模式第 3 条：不许两套并存）。

### 4.2 `SourcePlugin` 与 20 项能力

```ts
export type Tri = boolean | "read" | "write" | "both";

export interface Capabilities {
  search: boolean;            // 1  搜索
  suggest: boolean;           // 2  联想
  playback: boolean;          // 3  取播放地址
  lyrics: boolean;            // 4  歌词
  wordByWordLyrics: boolean;  // 5  逐字
  album: boolean;             // 6  专辑详情
  artist: boolean;            // 7  歌手详情
  playlistRead: boolean;      // 8  歌单读取
  playlistWrite: boolean;     // 9  歌单写入
  likes: Tri;                 // 10 收藏（Tri 表达"能读不能写"）
  daily: boolean;             // 11 每日推荐
  personalFm: boolean;        // 12 私人电台
  tops: boolean;              // 13 排行榜
  mv: boolean;                // 14 视频
  cloudDisk: boolean;         // 15 云盘
  auth: "qr" | "cookie" | "oauth" | null;  // 16 登录形态
  multiQuality: boolean;      // 17 多音质
  stream: boolean;            // 18 直链（可直接喂 <audio>）
  comments: boolean;          // 19 评论
  share: boolean;             // 20 分享/外链
}

export interface SourcePlugin extends ContractMeta {
  id: string;                 // "netease" | "qq" | "user-<hash>"
  name: string;
  capabilities: Capabilities;
  /** 声明支持的音质档；缺省视为仅 "320" */
  qualities?: ReadonlyArray<"128" | "320" | "flac" | "hires">;
  search(q: SearchQuery): Promise<SearchPage>;
  resolve(ref: SourceRef, quality?: string): Promise<MediaUrl>;
  lyrics?(ref: SourceRef): Promise<LyricDoc | null>;
  login?: AuthDriver;
}
```

> 20 项与 `docs/47` §3.1 的"20 项能力开关"对齐；47 未逐项列名，本文补全。**若两处冲突，以 47 的语义为准并同步修正本文。**

**`sourceRef` 强制**：所有跨模块传递的曲目/集合都必须带 `{ providerId, mediaId }`。缺失 → `source-mismatch`。**永不默认归属某一家**（`docs/47` 记过这个坑）。

### 4.3 `StageProvider`

```ts
export interface StageProvider extends ContractMeta {
  id: string;                              // "paper" | "vinyl" | "spectrum" | "theatre"
  layers: ReadonlyArray<"C0" | "C1" | "C2" | "C3">;  // C4 永远归主题
  cost: "low" | "mid" | "high";            // 降档依据（阈值见 §5.4）
  mount(canvas: HTMLCanvasElement, rt: StageRuntime): () => void;  // 返回卸载
}

export interface StageRuntime {
  /** 频谱；不可用时返回 null，舞台必须能纯几何降级 */
  analyser(): AnalyserNode | null;
  clock: { now(): number; onTick(cb: (t: number) => void): () => void };
  /** 歌词驱动舞台；无歌词时 null */
  lyric: { index(): number; progress(): number } | null;
  theme: Readonly<Record<string, string>>;
}
```

> **`analyser()` 允许返回 `null`**：Mineradio 拿不到 FFT 时会画"假波形"（E0），我们**禁止**——要么真频谱，要么纯几何。假数据比没数据更糟。

### 4.6 统一错误码（失败的"第二层"）

> 原则：**通用层只吐这 10 个码，平台层负责把上游错误翻译成它**。UI 只认码，不认平台。
> 这样"QQ 返回 code=2001"和"网易云返回 301"在界面上是同一句话。

| 码 | 触发 | 用户可见文案 | 可重试 | UI 表现 |
|---|---|---|---|---|
| `source-mismatch` | 曲目缺 / 错 `sourceRef` | 这首歌的来源不明确 | ❌ | 该项置灰，不弹窗 |
| `contract-version` | 插件 `contract` ≠ 当前值 | 该插件需要更新 | ❌ | 插件标"不兼容" |
| `capability-missing` | 调了未声明能力的方法 | 当前音源不支持此功能 | ❌ | 按钮本就不该出现（视为实现 bug） |
| `auth-required` | 未登录 | 请先登录 | ✅ | 拉起登录弹层 |
| `auth-expired` | 会话失效 | 登录已过期，请重新登录 | ✅ | 静默刷新失败后弹层 |
| `quality-unavailable` | 请求音质不可用 | 该音质不可用，已切到 320 | ✅ 自动 | 自动 fallback，仅在控制台记 |
| `upstream-timeout` | 上游超时 | 网络有点慢，重试一下 | ✅ | 行内重试按钮 |
| `upstream-blocked` | 风控 / 403 | 该音源暂时不可用 | ✅（进冷却） | 该源灰 15s |
| `sandbox-denied` | 用户源越权 | 该插件行为异常，已停用 | ❌ | 自动禁用并提示 |
| `sandbox-timeout` | 用户源超时 | 该插件响应超时 | ✅ | 保留上次结果 |

**验收**：断网、改 DNS、让上游返回 403，三种情况下界面文案分别是"网络有点慢"、"该音源暂时不可用"，**不出现任何 `code=xxx` 或英文堆栈**。

## 5. 播放页：C0–C4 五层画布 + 四套预设

"切换播放页效果"= **层的组合**，不是换页面。

### 5.1 层定义与 z-index 台账

| 层 | 内容 | 由谁提供 | z-index | 可关 |
|---|---|---|---|---|
| **C0 壁纸** | 纸纹 / 图 / 视频 / canvas | `ThemePack.wallpaper` | 0 | ✅ |
| **C1 舞台** | 粒子 / 转盘 / 频谱 / 方屏 | `StageProvider` | 1 | ✅ |
| **C2 封面** | 静止 / 呼吸 / 旋转 / 视差 | 预设 | 2 | ❌ |
| **C3 歌词** | 印刷 / 卡拉OK / 极简 / 剧场 | `LyricRenderer` | 3 | ✅ |
| **C4 控件** | 顶栏 / 播放条 / 进度 | `ThemePack.tokens` + `data-part` | 4 | ❌ |

**全局层序（与 `docs/20` 的 `--pr-z-*` 五档对接）**：画布 `0–4` < 浮壳 `20` < 面板 `40` < 模态 `50` < toast `60`。

> 硬规矩：`z-index` 只准用这 9 个值，禁写 `9999`。

### 5.2 四套预设（**带实现参数，可直接照着做**）

| 预设 | C0 壁纸 | C1 舞台 | C2 封面 | C3 歌词 | 切换转场 | 成本 |
|---|---|---|---|---|---|---|
| **纸面剧场** | 纸纹：底色 + 噪点 `opacity .035` | 无 | 静止，1px 细框 + 4px 内边距 | `press` 印刷 | 200ms `ease-out` | low |
| **黑胶唱机** | 深墨纸 + 同心圆暗纹 | 转盘 33⅓ rpm（≈1.8s/圈）+ 唱臂 12° 起落 | 圆形，与转盘同角速度，叠 8% 黑胶纹理 | `minimal` | 320ms `ease-out` | mid |
| **极简留白** | 纯色 `#f6f5f2` | 无 | 大图，62% 宽，无框 | `karaoke` | 200ms `ease-out` | low |
| **电影感** | 封面高斯模糊 `blur 48px`、`scale 1.15`、亮度 `-18%` | 频谱：48 根柱、平滑 `.72`、上限 30fps | 视差：鼠标 ±8px、阻尼 `.12` | `theatrical` | 400ms `ease-in-out` | high |

> 四套预设是"集大成的最小可感证明"。**做不出这四套之间的明显差异，集成就没成立。**

### 5.3 切换成本（硬化成验收项）

| 动作 | 上限 | 允许做什么 | 禁止做什么 |
|---|---|---|---|
| 换预设 | ≤ 1 帧不掉 | 卸载/挂载 C0/C1，改 C2 参数 | 重建 store、重新解码封面 |
| 换主题 | ≤ 200ms | 覆盖 CSS 变量 | 卸载页面、重排 DOM |
| 换歌词渲染器 | ≤ 100ms | 只重挂 C3 | 重新解析歌词、重建队列 |
| 关/开 C1 | ≤ 50ms | 释放 canvas | 阻塞主线程做 GL 清理 |

### 5.4 降档阈值（不是"优化一下"，是自动关层）

| 条件 | 动作 |
|---|---|
| 连续 2s 平均帧间隔 > 20ms（<50fps） | 关 C1 |
| 关 C1 后仍 > 20ms | C0 canvas → 静态图 |
| 连续 5s < 14ms（>70fps） | 逐级恢复 |

> 降档必须**用户可感知地保留布局**：只关视觉层，不动 C2/C4 的位置。降档后出现"界面跳位"= 实现错误。

## 7. 性能预算与测量

**规矩**：不写"感觉挺快"。每条预算必须能**被一条命令打脸**。

### 7.1 七条预算

| # | 指标 | 目标 | 达标手段 / 降档动作 |
|---|---|---|---|
| 1 | 冷启动到可交互 | < 1.5s | 索引先返回，后台增量 |
| 2 | 首页首帧（FCP） | < 300ms | 骨架屏；延迟挂 C1 |
| 3 | 切歌到出声（本地） | < 150ms | 预读下一首前 256KB |
| 4 | 切歌到出声（在线） | < 800ms | 地址预取 + 失败冷却 |
| 5 | 播放页帧率 | ≥ 58fps（10s 均值） | 降档（§5.4） |
| 6 | 内存（1000 首 + C1 开） | < 300MB | 封面缩略图 + 纹理上限 |
| 7 | 长列表 5000 行滚动 | 帧间隔 p95 < 20ms | 虚拟化（只渲染可视区） |

### 7.2 每条怎么测（现在就能写）

| # | 测法 | 落点 |
|---|---|---|
| 1 | 启动打点 `performance.mark('boot:interactive')`，跑 5 次取中位数 | `scripts/perf-boot.mjs` |
| 2 | `PerformanceObserver` 取 `first-contentful-paint` | 同上 |
| 3 | `audio.play()` → `playing` 事件之间打点 | CDP 冒烟断言 |
| 4 | 同上 + 网络 mock（固定 200ms 延迟） | `test/perf-online.spec.cjs` |
| 5 | CDP 采 10s 的 rAF 间隔，算均值与 p95 | `scripts/perf-fps.mjs` |
| 6 | 主进程 `process.memoryUsage()` + 渲染进程 `Performance.getMetrics()` | `scripts/perf-mem.mjs` |
| 7 | 注入 5000 行后滚到底，采帧间隔 p95 | `scripts/perf-list.mjs` |

### 7.3 怎么进 CI

`scripts/perf-budget.mjs` 输出 JSON 并**超阈值非零退出**；先只把 **#1 冷启动** 与 **#5 帧率** 接入 CI（这两条最稳、最能代表回归），其余三条人工跑（环境噪声大）。

> 未测量的预算 = 没有预算。这是 §8 反模式第 5 条要防的东西。
