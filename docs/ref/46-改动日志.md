# 46 · 改动日志

> **这是什么**：所有 AI 窗口 / 人改这个项目时的**流水账**，一条一改，倒序。
> **为什么要有**：多个窗口并行改同一个仓库时，`git log` 只能看到"某个文件变了"，
> 看不到"为什么变、当时排除了什么、还有什么没做完"。这份文件补的就是这一段。
>
> **什么时候读**：接手任何改动之前，先扫一眼最新几条，确认你要动的地方是不是刚被人动过。
> **什么时候写**：每次改完并提交之后，在**最上面**加一节。没提交的改动也要写，标注「未提交」。

## 一条记录写什么

```md
## YYYY-MM-DD · 一句话标题
- **commit**：`abc1234`（或「未提交」）
- **动机**：为什么改（用户原话 / 观察到的现象 / 上一节留下的待办）
- **改了**：文件 → 做了什么（表格，只列真改的）
- **关键决策**：选了 A 不选 B 的理由，以及踩到的坑
- **验证**：跑了哪些命令，结果如何
- **遗留**：没做的、条件性的、已知但先不修的
```

规矩：

1. **只写"读代码看不出来"的东西**。改了哪几行 git 有，别再抄一遍。
2. **坑必须写**。下一个窗口会踩同一个坑。
3. **遗留必须写**。写"没做"比写"做了"更有价值。
4. 一条记录不超过一屏。超了说明该拆成独立文档，在 `docs/README.md` 里单独编号。

## 2026-11-02 · 网易云接入：适配器 + 扫码登录 + 在线播放（新仓库 `6e41891`）

- **commit**：新仓库 `6e41891`
- **动机**：用户「我用网易云扫码」。M3 第一家真音源。

- **先验后写**（关键做法）：用 node 直连官方接口探了一遍，结果决定了实现——
  | 接口 | 匿名实测 |
  |---|---|
  | `POST /api/cloudsearch/pc` | 200，正常出歌 |
  | `GET /api/song/lyric` | 200，lrc 有内容 |
  | `POST /api/login/qrcode/unikey` | 200，返回 unikey |
  | `GET /api/song/enhance/player/url/v1` | **`code: -110`、`url: null`** |

- **关键决策**：
  1. **不自己实现 CookieJar**。`net.fetch` 走 Chromium 网络栈，扫码成功后的 `Set-Cookie` 自动进 session。旧仓库手写了 CookieJar，这里是**少写一层**。
  2. **拿不到地址必须区分「未登录」与「无版权」**。混成"没版权"会让用户以为歌下架了，真实原因是没登录。现在：未登录 → `auth-required`（请先登录），已登录才 → `track-missing`。
  3. **二维码放主进程**（`qrcode` 依赖）：只在扫码那一下用，进渲染 bundle 等于每次启动都加载它。
  4. **登录态缓存 30s**，但网络出错时**不谎报已登录**（旧仓库踩过，界面会显示假用户名）。

- **坑**：
  1. **`-110` 不是"无版权"**，是"没有可用地址"，最常见原因是未登录。按字面理解会写出错误的用户提示。
  2. **Chromium 不允许手动设置 `Cookie` 请求头**（会被静默忽略）。基础 cookie 只能 `session.cookies.set`。
  3. 旧仓库的 `CookieJar` 类看着"参考价值高"，在 Electron 里是多余的——**照抄会多一层且更容易出错**。

- **新依赖**：`qrcode`（MIT）。按 51 新增的"加依赖三个问题"过了一遍：标准库做不了、只用于扫码一处、不进渲染 bundle。已登记进 51 §1.4 白名单。

- **验证**：`npm run verify` ALL GREEN（54 源文件 / lint 6 条 / 212 测试 / 冒烟 2 个音源 / 3 条性能预算）。真网接口用 node 直连验证，**不进 verify**（避免网络波动导致误红）。

- **遗留**：
  1. **扫码登录与在线播放都没经人工验证** —— 需要用户在应用里点一次。
  2. 在线曲目没有标题：`trackId` 直接是 URL，播放条显示 URL 尾巴（应给 store 加 `trackTitle`，M4）。
  3. 会员音质（flac）没声明；歌单/专辑/电台四项能力声明为 false（契约支持，实现没做）。

## 2026-11-02 · M3 可离线部分完成：歌词四格式 + 在线页（新仓库 `226c92d`）

- **commit**：新仓库 `226c92d`（功能）、`docs` 一条（文档）
- **动机**：用户「按这个顺序继续」—— 先做不依赖凭证的两件，真音源只剩"填适配器"。
- **改了**：

| 位置 | 做了什么 |
|---|---|
| `capability/lyrics/` | `detect`（格式识别）、`parse`（LRC/增强LRC/QRC/YRC/TTML/纯文本 → `LyricDoc`，毫秒）、`reflow`（智能重排） |
| `ui/views/online/` | 音源下拉（**来自注册表**）+ 搜索 + 结果 |
| `ui/index.tsx` | 本地 / 在线 tab |
| `ui/bootstrap.ts` | 注册 demo 源、`sources()`/`searchOnline()`/`resolveOnlineUrl()`，错误统一 `humanize()` |

- **关键决策**：
  1. **TTML 用正则解，不用 XML parser**。解析要能在**主进程**（无 `DOMParser`）和 **node 测试**里跑；TTML 歌词就 `p`/`span` 两种标签，上 XML parser 是给一首歌词装一台编译器。
  2. **时间一律毫秒**，与 clock 同单位：少一次换算就少一次换错。
  3. **逐字行不参与重排** —— 切了逐字时间就对不上。
  4. **音源下拉读注册表不写死**：加第三家源时下拉自动多一项。

- **坑**：
  1. **QRC 会被误判成 LRC**（行首是 `[毫秒,时长]`，没有冒号）。识别顺序必须先看结构标记，不能只看"有没有 [mm:ss]"。
  2. **增强 LRC 的尖括号时间指"接下来那段"的起点**，第一段从行时间开始。测试断言一度写错（17200 vs 16800）——**实现是对的，测试写错了**。
  3. **错误必须结构化带 `code`**：demo 源原本把码写在 message 里，界面显示成"出了点问题"。改成 `Object.assign(new Error(...), { code })` 后显示"当前音源不支持这个操作"。`translateError` 同时加了 message 兜底（第三方源常见这种写法）。
  4. 旧仓库歌词样本是**秒**，新契约是**毫秒**，直接搬不换算会整体差 1000 倍。

- **验证**：`npm run verify` ALL GREEN —— 49 源文件 / lint 6 条 / **212 项测试** / 三阶段冒烟（新增**在线链路**：切 tab → 读注册表 → 搜索 → 点击 → 断言提示是人话且不含错误码）/ 3 条性能预算。

- **遗留**：
  1. **在线播放没接**：demo 不给地址。真音源接入时才开 CSP `media-src https:` 并给 engine 加 `loadRemote()`，**故意不提前放开**。
  2. 两家真音源（网易云 / QQ）仍未接，需真号联调。
  3. EQ / ReplayGain、歌词接进播放页（属 M4）都没做。

| `scripts/` | 抽 `lib/harness.mjs`（冒烟与性能共用）、新增 `perf.mjs` 并接入 verify |

- **性能实测**（都进 verify）：二次启动恢复 5000 首 **24.3ms**（预算 120）、滚动帧间隔 p95 **6.8ms**（预算 20）、搜索 **11.9ms**（预算 100）、真扫描 80 个 wav 解析 79ms（**外推 5000 首 ≈ 5.1s**，预算 30）。

- **关键决策**：
  1. **曲库不进 kernel store**，另起一个只有两个通知（列表变、搜索词变）的 store。5000 条塞进播放 store 会让每次 dispatch 白算一遍。
  2. **身份用规范化路径小写，显示用原始路径**。否则 `C:\A.mp3` 与 `c:\a.mp3` 会变成两首歌。
  3. **增量靠 stat 比对**，不重读标签：5000 首改 3 首只解析 3 首。
  4. **拼音只取首字母**（21KB），不取全拼（103KB）。"打 2 个字符出歌"用不到全拼。
  5. **缺失只标记不删**：自动移除会让用户以为歌被吞了，外接盘没插时更糟。

- **坑**：
  1. **`setTracks` 把通知参数传成 `false`** → 曲库加载完界面永远显示"0 首"。单测里 `getFiltered()` 拿得到数据所以全绿，**只有端到端能发现**。这是第二次踩"纯函数测试测不到装配层"（M1 是 clock 锚点）。
  2. **`readTags` 串行，5000 首外推 37.3s，超 30s 预算**。改 8 路并发后 80 个文件 597ms → 82ms。**预算不是写完才想的，是 perf 脚本逼出来的。**
  3. **lint 规则 6 把字符串里的 `library` 也当业务词**（文件名 `"library.json"` 被判违规）。判定前先剥字符串 —— 规则误伤会让人直接关掉规则。

- **遗留**：
  1. **"点扫描按钮 → 选目录 → 入库"端到端没自动化**（`showOpenDialog` 拦不住）；IPC 链路与编排分别有覆盖，"真点一次"仍要人工。
  2. 5000 首首次扫描是**外推值**，没有真 5000 个音频的机器验过。
  3. 封面缩略图没做（`hasCover` 只标了布尔值）；收藏/歌单/历史（"顺序外"三节）也没做。

## 曾在这个仓库确定过的、容易被推翻的结论

> 这几条不是某个窗口的一次性改动，而是跨会话的判断，后续改代码前先确认还要不要坚持。

1. **不做 `frame: false`**。窗口装饰一律交还系统，自绘只负责标题栏内容（品牌 / 功能区）。
