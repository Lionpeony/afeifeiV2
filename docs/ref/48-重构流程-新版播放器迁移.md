# 48 · 重构流程：把 `app/` 的能力迁到 `next/`

> **这份文档回答一个问题**：现在的 `app/` 和初期的 `next/`，怎么合成一个产品？
> **写于 2026-11-02**。基于当天实测：`app/` 140 个 JS 文件 26,143 行 + 32 个 CSS 11,298 行；`next/` 21 个文件 1,969 行（**5.3%**）。
>
> **怎么读**：§1 决策 → §3 目标架构 → §4 九个阶段（**干活的在这**）→ §5 迁移台账 → §6 质量护栏 → §7 风险 → §8 不做清单 → §9 本周就能动的 7 件事。

---

## 0. 一句话

**`next/` 是新底座，`app/` 是功能资产。用绞杀者模式（Strangler Fig）逐域迁移：每迁完一域，`next/` 独立可用，`app/` 对应能力立即冻结。`app/` 保持可发布直到 `next/` 覆盖度 ≥ 90% 且用户试用无回退。**

---

## 1. 三个前置决策（先拍板，不然流程走不下去）

### 1.1 决策一：**不弃 `app/` 的功能，重写的是底座**

| | 大爆炸重写（弃 app/） | 绞杀式迁移（本文） |
|---|---|---|
| 工作量 | 3–6 个月，全部功能重写 | 逐段搬运，每段可发布 |
| 功能倒退 | 必然（新版本要重新长出 2 个音源、歌词引擎、视觉引擎、下载、EQ） | 无（旧版一直在） |
| 出错代价 | 一次性，全量 | 单域，可回滚 |
| 风险集中度 | 全部压在最后 | 每阶段 1/9 |

`app/` 里这些东西**是资产，不是包袱**：2 个音源适配器（`qq.js` 2042 行 / `netease.js` 902 行）、歌词重排引擎（`lyrics-pro.js` 769 行，支持 LRC/增强LRC/QRC/YRC/TTML + 逐字 + 智能重排）、WebGL2 视觉引擎（`visual-engine.js` 2011 行）、L3 演出模式（three + GSAP）、下载引擎（断点续传）、EQ + ReplayGain、安全层（`mediaGuard` 路径白名单 + `netGuard` 签名票据 + `safeStorage`）。**这些在重写里都要"再写一遍"，不如搬。**

### 1.2 决策二：**迁移期双轨，`app/` 只冻结不删除**

| 规则 | 内容 |
|---|---|
| 功能只进 `next/` | `app/` 迁移期只修 bug，不加新功能 |
| 迁完即冻结 | 某域迁完，`app/` 对应目录标 `FROZEN.md`，此后只修致命 bug |
| 两条线不并行开发同一功能 | 否则会得到两份半成品，这是本方案唯一的致命失败模式 |
| 退役是独立决定 | 覆盖度 ≥ 90% + 用户试用一周无回退 → 归档 `app/` 到 `archive/` 分支，再讨论删除 |

### 1.3 决策三：**契约先行，代码后动**

迁移前先把**接口**定死（`next/electron/contract.ts`），再搬实现。原因：`app/` 的 IPC 是 46 个入站 + 12 个出站 + preload 11 个命名空间约 63 个函数（`docs/09` §5）。如果边搬边定接口，会出现"搬一半发现形状不对 → 返工"。

**契约先行还顺带解决一个老问题**：`app/` 现在是「单一 `src:invoke` 通道 + 方法名字符串白名单」，粒度太粗。`next/` 的契约直接按 `docs/47` 的结论写：`omni` 门面 + 每域独立命名空间 + 入参 schema 校验 + 可信窗口校验。

## 3. 目标架构

```
next/
├─ electron/                       主进程（Node，不 import 任何渲染层东西）
│  ├─ main.cjs                     窗口/协议/菜单/托盘 —— 只做组装
│  ├─ preload.cjs                  唯一 contextBridge
│  ├─ contract.ts                  ★ IPC 契约：类型 + 入参 schema + 台账
│  ├─ settings/                    读写（原子写）+ 迁移器
│  ├─ media/                       appmedia:// id 协议 + mediaGuard + Range
│  ├─ net/                         net.cjs（CookieJar/GBK/gzip/JSONP/retry）+ guard.cjs（票据/SSRF/降级）
│  ├─ library/                     scan / index / watch / ops / cover
│  ├─ onlineMusic/                 ★ 照 docs/47 的结构
│  │  ├─ omni.cjs                  唯一对外门面（UI 只认它）
│  │  ├─ registry.cjs              唯一注册表
│  │  ├─ capabilities.ts           20 项能力对象（不是字符串数组）
│  │  ├─ failure/                  通用层（不认识平台）+ 平台层（翻译）
│  │  ├─ login/                    createQr / openLoginPage 两种形态
│  │  ├─ netease/  qq/             每平台一个目录，14 个薄文件
│  ├─ lyrics/                      LRC/增强LRC/QRC/YRC/TTML 解析 + 智能重排
│  ├─ downloads/  behavior/  mini/ tray/
├─ src/
│  ├─ core/                        store types player queue effects commands host
│  ├─ features/<域>/               每个域一个目录，只导出 index
│  │   library/ online/ radio/ playlists/ favorites/ lyrics/ settings/ theatre/ home/
│  ├─ ui/                          基础控件（对应 app/renderer/kit）
│  ├─ visual/                      engine.ts（WebGL2）+ registry/ + stage/
│  └─ styles/                      tokens.css（唯一 token owner）+ components/
├─ test/                           单测 + 契约测试
└─ scripts/                        dev / smoke / build / verify
```

**依赖方向（单向，不可逆）**：

```
electron/contract.ts  ←  src/core  ←  src/features  ←  src/ui
        （主进程不 import 渲染层；渲染层不 import 主进程实现，只认 contract）
```

**三条硬规矩**：

1. **单一写者**：每个域只有一个模块能写 store。照 `next/src/core/player.ts` 的注释与实现（"唯一允许写 playerStore 的模块"）。
2. **真实路径不出主进程**：渲染层只见 id。`next/electron/main.cjs:42-124` 已经做对，保持。
3. **平台名不进 UI**：`next/src/` 里不准出现 "网易云" / "QQ" 字样，只能按能力开关渲染。照 `docs/47` §3.1 + Folia 的 `platformNameCount.ts` 思路，写成一条 lint。
