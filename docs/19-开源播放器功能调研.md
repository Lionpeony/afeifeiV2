## 一、播放器"该有的"功能（通用底座，11 家都有）

## 二、各家的独门特色（真正拉开差距的东西）

### folia-major —— **Folium 插件生态 + 自建云**
- 插件有**三级信任签名**：官方签名 = `Verified`，早期体验 = `Preview`，第三方无签名 = `Unverified`（**仍然可用**，不阻断）
- 插件声明**权限**（manifest fields / permissions），有完整的 **API registry**（事件 / 上下文 / 服务四类）
- 官方 mod 示例覆盖：歌词动画、调音、进度条、播放器页面图层、透明视频导出 —— **官方先做难题，mod 补生态**
- 设置页直接分 **ai / desktop / graphics / hifi / integration / storage** 六组
- 云端三种自建方案：Cloudflare Workers+D1 / Docker / Node+SQLite

### lx-music-desktop —— **音质与歌词的极致 + 局域网自建**
- **Windows WASAPI Exclusive 独占模式**：绕过系统混音器，bit-perfect 输出
- **Audio Fingerprinting**：AcoustID + MusicBrainz 识别未知曲目，**自动补全标签与高清封面**
- **AI 生成带时间戳的歌词**（逐字卡拉OK级），并可**修正时间轴**
- **一键翻译 + 双语并排显示**
- **无服务器局域网同步**：自动发现同网实例，双向同步**播放列表 / 歌词缓存 / 翻译库**，并提供浏览器 Web 界面上传下载
- 直连 **Navidrome / Jellyfin**，挂载 **WebDAV / SMB**（分块读头，不用下全曲就能看标签）
- 独立 `renderer-lyric` 进程（桌面歌词）与排行榜

### YesPlayMusic —— **把网易云当唯一内容源做透**
- **私人 FM / 每日推荐**（算法流直接进播放器）
- **MV 播放**（有独立的 artistMV、Video、Comment 视图）
- **UnblockNeteaseMusic 音源替换**：灰掉的歌自动换源可播（网页版除外）
- Last.fm Scrobble、Touch Bar 歌词、PWA、每日签到、海外可播
- **明确声明"无任何社交功能"**（反共识定位）

### nuclear —— **插件是一等公民**
- `plugin-sdk` 是独立 package，插件能拿到完整 context
- Sources（多音源）/ Themes（主题）/ Logs（诊断）都是一等视图
- 有独立的 **KeyboardShortcuts** 页与 **PlaylistImport** 页

### MusicFreeDesktop —— **插件 + 多进程 + 主题**
- 独立渲染进程：**desktop-lyric**（桌面歌词）、**minimode**（迷你模式）、**webworkers**（不卡 UI）
- **music-sheet**（乐谱/歌单）、plugin-manager、theme-view
- 整体最克制：功能少但每件都干净

### SPlayer —— **视图最全**
- 18 个视图：Artist / DesktopLyric / Discover / Download / Home / Like / List / Local / **Radio** / Search / Song / Status / **Streaming** / **Cloud** / **Comment** / **DailySongs** / History / **Video**
- 翻译（36 命中）与 i18n 完整

### vynody —— **功能集大成**
- 几乎收齐所有旗标：EQ 86 / 睡眠定时 61 / WebDAV 127 / 频谱 88 / 翻译 67 / **指纹 55**
- 特有页面：**cover_flow**（封面流）、**remote**（远程控制页）

### 其余
- **tauri-rmusic**：Rust + Tauri 重写，OnlineAlbum / OnlinePlaylist 分离
- **museeks**：最简，只有 themes + 插件
- **Mineradio**：多源 + EQ + 指纹 + 桌面歌词

## 四、我们的特色功能（结合已有资产设计，别家的短板就是我们的机会）

### ① 逐字时间轴 = 唯一真相源
别家的歌词是"每家自己算"。我们已经有逐字时间轴与段落聚类，应该让它成为**全站唯一数据源**：六套播放样式、歌词页、报告页全部读同一份 `LyricDoc`。
→ **别家的"多套皮肤"会各自算错行；我们不会。**

### ② 结构 = 可操作的队列（只听副歌）
我们有真实段落聚类。别家把段落只当"显示"，我们可以让它是**动作**：
- 只听副歌 → 生成一条 62 秒的新队列
- 只听桥段 / 只听前奏
- 段落级跳转、段落级音量
→ **这是"我们的数据"才能做的，别人有歌词也做不了。**

### ③ 作品层：世界级播放器还没有的东西
12 家里，搜同一首歌在不同平台得到不同条目（不同专辑图、不同时长、不同版本）。
我们做**作品层**：一首歌一个真相，多个来源并置（网易云 / QQ / 本地 / 试听），自动选最好的那个，并保留"全部来源"。
→ 这是**架构级差异**，不是 UI 差异。

### ④ 解释器：为什么是这首
我们有播放历史和循环数据。首页与播放页都给一句**可解释、可重掷**的理由（"你在 10/28 之后循环过它 14 次"）。
→ 对应 `12 L2`，别家只有"推荐"没有"解释"。

### ⑤ 唱针时间机：曲库可以回到过去
别家的"历史"是**列表**（最近播放）。我们做**时间轴**：拖到 10/28，整个曲库变成那天的样子（当时的歌单、当时的上新、当时在听的那首），并可回滚。
→ 列表 → 时间轴，是**形态级**差异。

### ⑥ 会话票根：听歌可以"回放"
一次收听结束，生成一张可分享、可再次播放的票（时长、最常听、第一次听、最长连播）。
→ 让"听过了"变成一个**对象**。

### ⑦ 六套播放样式 + 各自独立的视觉语言
别家最多 2–3 套皮肤（同色系换布局）。我们有六套**机制完全不同**的样式（翻牌时刻表 / 调谐收音机 / 光谱带 / 叠印海报 / 蓝图工程图 / 活字帖 / 刻纹现场 / 碟），每套连视觉语言都不同（纸墨 / 琥珀 / 荧光绿 / 朱红 / 深蓝 / 暖纸）。
→ 这才是"用户想自由切换"的真正价值：**换的是信息隐喻，不是皮肤**。

### ⑧ 纸张级材质（纸墨 / 相纸 / 票根 / 印章）
这是你原稿 a2/b2 已经在做、且明显强于别家的东西——**界面像一张实物**。别家的 UI 都是"玻璃卡片"，我们是"印刷品"。
→ 建议把这条**升格为全站基线**，不只是播放页。

## 五、明确不做（避免范围爆炸，写下来免得反复讨论）

| 不做 | 理由 |
|---|---|
| 插件市场 + 三级签名 + 权限模型 | folia-major 的 Folium 是整个项目最重的部分，我们没有生态基础 |
| 自建云服务（Workers/Docker/Node） | 需要运维，和"本地播放器"定位冲突 |
| AI 生成歌词 | 成本与合规；我们已有真实逐字数据，不需要生成 |
| bit-perfect 独占模式（WASAPI） | Windows 专属，收益集中在发烧友，优先级极低 |
| MV / 视频播放 | 与"听觉播放器"定位冲突（YesPlayMusic 做了，但那是另一种产品） |
| 社交 / 评论 / 关注 | 明确不做（同 YesPlayMusic 的判断） |
| 局域网同步 / 远程控制 | P2，等核心跑通再说 |

## 六、从调研到开发：三步

1. **P0 补齐**（1–2 周）：播放模式、音量、红心、队列可点、歌词点击跳句 —— 这是"不像播放器"的根因
2. **P1 差异化上墙**（2–3 周）：先做 **②只听副歌** 与 **③作品层**，这两件是数据驱动、别人抄不走的
3. **P2 视觉统一**（并行）：纸墨基线 + 六套播放样式切换（`StageStyle` 枚举 + KV `stage-style`）

## 七、结论：双轨制（细则见 `20-功能基线与任务清单.md`）

调研的最大收获不是功能清单，是两条结论：

**① 通用能力是入场券，不是差异化。** EQ、桌面歌词、翻译、指纹、主题、多源、WebDAV——11 家都有，我们不能弱，但也不能靠它赢。

**② 别人都做卷了的地方，恰恰没人在架构层解决。** 12 家里搜同一首歌返回不同条目、历史只是一张列表、段落只用来显示不用来操作——**"作品层""结构可操作""时间轴式历史"三处是空白**，而这三处都需要我们已有的逐字数据与段落聚类。

> **轨道 A（不许弱）**：通用能力，每项达到同行最高水平，见 `20` 的 §2 对标基线（16 项）。
> **轨道 B（要领先）**：8 项特色，见 `20` 的 §4。
>
> 只做 B 是自嗨；只做 A 是竞品。两条同时成立才叫好产品。
