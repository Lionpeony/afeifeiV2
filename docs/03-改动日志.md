## 2026-11-02 · M1 内核完成

- **commit**：`4450d54`（内核）、`58a8834`（冒烟与修复）
- **动机**：按 `docs/01` §4 M1 施工单，做到"能播一首，且时间是对的"。
- **改了**：

| 层 | 新增 |
|---|---|
| `contracts` | 六态 `PlayerStatus`、`ErrorCode` 十二码、`QueueState` 三分、`Intent` 全集、`ports.ts`（Storage / Media） |
| `kernel` | `queue.ts`（shuffle 投影 / 步进 / 3s 规则）、`clock.ts`（插值 + 漂移吸附）、`player.ts`（六态机纯函数表）、`persist.ts`（节流 1s + 原子写）、`store.ts` 扩展全部 Intent |
| `capability` | `audio/graph.ts`（唯一 AudioContext + 四 stage）、`audio/engine.ts`（唯一读 currentTime 的地方） |
| `main` | `host/`（app:// 提供界面）、`media/tokens.ts` + `media/protocol.ts`（appmedia:// + Range）、`fs/state.ts`、`ipc/` |
| `ui` | `compositor.ts`（唯一 rAF）、`bootstrap.ts`（装配 + store→engine 单向同步）、`index.tsx`（4 按钮 + 进度 + 音量） |
| `scripts` | `smoke.mjs` 两阶段 CDP 冒烟 |

- **关键决策**：
  1. **clock 不碰 DOM**。环 0 不许碰 DOM，所以时钟不直接读 `audio.currentTime`，改由 capability 用 `attach(() => audio.currentTime * 1000)` 注入。于是"谁读 currentTime"有了唯一答案：engine。
  2. **状态机做成纯函数表**而不是散在事件回调里。六个状态 × 七个事件的转移一次写完，能穷举测；未定义的转移一律保持原状态（宁可没反应，也不要把界面打成 error）。
  3. **实时位置不进 store**。store 的 `positionMs` 只记"用户最后一次 seek / 切歌的位置"，进度条每帧从 `clock.t()` 取 —— 否则每帧一次全量通知 + 整棵树重渲染。
  4. **界面用 `app://` 而不是 `file://`**。见坑 1，这不是洁癖，是能否显示的问题。
  5. **3 秒规则留在 kernel**，但由 UI 把 `atPositionMs` 带上来 —— 规则不散到 UI，store 也不必追实时位置。

- **坑**：
  1. **`file://` 下 CSP 的 `'self'` 匹配不到任何 URL**，`<script src>` 被静默拦掉，窗口一片空白且控制台没有明显报错。**M0 那条"窗口显示 afeifei"其实从未被验证过**（当时只看了进程存活和日志）。改用 `app://` 自定义协议后才真正跑起来。推论：**判据必须验到 DOM，不能只看进程活着。**
  2. **`protocol.registerSchemesAsPrivileged` 多次调用会互相覆盖**，不是累加。我原本 `app` 和 `appmedia` 各调一次，后一次把 `app` 的 `standard/secure` 抹掉了 —— 症状是 HTML 能加载、`<script>` 却被拦。必须一次性传数组。
  3. **`file://` 下 ES module 会被 CORS 拦**，renderer 产物必须是 `iife` + 普通 `<script>`。
  4. **`beforeunload` 的 flush 会覆盖测试注入的存档**。想验"重启恢复"必须 `SIGKILL`（模拟断电），不能靠 reload —— 否则测的是"退出时保存"，不是"崩溃后恢复"。
  5. **冒烟第一次失败是"查得太早"**：页面刚加载就查 `h1`，React 还没渲染。所有 DOM 断言都要轮询等待，不能查一次就下结论。
  6. **`main/renderer/` 这个目录名和环 4 撞了**，lint 规则 6 因此误报。两者都改了：目录改名 `main/host/`，规则改成按解析后的真实路径判断而不是字符串匹配。

- **验证**：
  - `npm run verify` **ALL GREEN**：22 个源文件、lint 6 条无违规、**69 项纯函数测试**、build、smoke
  - 冒烟实测：`Alarm01.wav` 解码 5.57s、`currentTime` 推进；无效令牌返回 410；**SIGKILL 后重启，曲目 / 位置 2000±1000ms / 音量 30% / 暂停态 全部恢复**
  - M1 测试下限：queue 29 ≥ 20、clock 14 ≥ 10、累计 69 ≥ 30

- **遗留**：
  1. **"切歌不闪白"仍未验证**：白屏要靠截图对比，冒烟只能证明 DOM 与状态一致（`4d114ed` 补上了连切 20 首与淡入淡出）。
  2. **`player/cue` 的时钟锚点 bug 是冒烟抓到的**（修在 `58a8834`）。说明"恢复后进度条从 0 开始"这类问题只有端到端能发现，纯函数测试测不到装配层。
  3. store 仍是全量快照订阅，5000 条时需 selector 级订阅（M2）。
  4. `ui/compositor.ts` 是最小版，只分发 `now`；M4 才接 `clock.t` 的统一分发与降级。
  5. 切歌的淡入淡出是写死的 8ms/20ms，且只覆盖"换曲"；暂停/恢复的淡出与可配置 crossfade 属 M3 的 fade stage。

## 2026-11-02 · M1 剩余两条判据闭环

- **commit**：`4d114ed`
- **动机**：M1 阶段门要求判据逐条过。切歌与错误态两条当时挂着"需人工"，实际都能自动化。
- **改了**：

| 文件 | 做了什么 |
|---|---|
| `scripts/smoke.mjs` | 扩到**三阶段**：①界面/播放/存档 ②强杀重启验恢复 + **连切 20 首** ③存档指向已删文件 → 重启验错误态 |
| `src/renderer/capability/audio/engine.ts` | 切歌改为**淡出 8ms → 换 src → 淡入 20ms**；`play()` 走 `fadeIn()` |

- **判据结果**：
  - 连切 20 首：经过 **19 个不同曲目**、无一次进入 error、进度条值始终不越界
  - 文件被删：界面落进 **`error · track-missing`**（不是崩溃、不是空白）
  - 20 次切歌用的是 `C:\Windows\Media` 下真实的 20 个 wav，不是同一文件重复

- **关键决策**：
  1. **两条判据复用同一条"硬杀→重启"路径**。因为"文件被删"最真实的场景就是"上次播的歌，下次启动时没了" —— 用存档注入比造一个假 provider 更贴近现实。
  2. **"不爆音"拆成两半**：结构上（切歌只换 src、不重建 AudioContext、不动 gain）+ 声学上（8ms 淡出/20ms 淡入）。前者可断言，后者只能靠"淡入淡出确实存在"这个事实。

- **坑**：
  1. **硬切 `el.src = ...` 一定会有咔哒声**，因为波形不连续。这不是 bug，是"还没做淡入淡出"。补 8ms 淡出后消失 —— 但**8ms 是人耳下限附近，再短就没用了**，M3 做 crossfade 时要重新标定。
  2. 连切 20 首时第 20 次会走到队列末尾（order 模式返回 -1 → `ended`），所以只经过 19 个不同曲目。断言写成 `>= 15` 而不是 `== 20`，就是因为这个 —— **判据要留出对"队列到头"的合理解释**。

- **遗留**：
  1. "切歌不闪白"仍未验证（要截图对比，M4 有截图存档机制后再补）。
  2. 淡入淡出参数写死，且不覆盖暂停；M3 的 fade stage 会接管。

- **关键决策**：
  1. **`node --test` 不带目录参数**。Windows 上 `node --test test/` 会把结尾斜杠当模块名解析，直接 `MODULE_NOT_FOUND`（`docs/01` §2.4 里写的是带参数的版本，已回写修正）。
  2. **测试跑编译产物**（`dist-test/kernel.mjs`），不直接跑 TS。`node --test` 不认识 `.ts`，先 esbuild 转译再测，比引 tsx/ts-node 少一个依赖。
  3. **store 的 reduce 幂等化**。原实现重复 dispatch 同一 intent 也会通知订阅者，被测试 4 抓到。改 store 不改测试 —— 这是真实缺陷，不是测试写错。

- **坑**：
  1. **lint 规则 1 一开始是假绿**。`layerOf()` 用相对路径匹配 `^src/renderer/`，而 `resolveLocal()` 返回绝对路径 → 目标层永远 null → 跨层 import 全部跳过。症状是"造了违规却不报"。修法：`norm()` 统一成 `path.relative(ROOT, path.resolve(...))`。**任何"解析后比较路径"的检查，都要先统一基准。**
  2. **规则 1 把 `main/` 和 `preload/` 也判了**。它们本来就该 import electron，是"环境"和"端口"，不在环里。加 `if (!me) continue`。
  3. **`JSX.Element` 在 React 19 里不可用**（全局 namespace 已移除），`tsc` 报 `TS2503`。去掉返回类型标注即可。
  4. **`npm config set ELECTRON_MIRROR` 在新版 npm 上直接报错**（不是合法 option）。正确做法是写项目级 `.npmrc` 的 `electron_mirror=`。
