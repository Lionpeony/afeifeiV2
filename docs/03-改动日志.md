## 2026-11-03 · 扫码"没反应"真因：check 的 key 没传到本地服务

- **commit**：见本条
- **动机**：用户"扫完码后没有反应"——二维码出来了、也扫了，但弹层永远停在等待。

## 2026-11-03 · M7 真机首修：下载冻结的自唤醒递归 + 自定义下载路径

- **commit**：见本条
- **动机**：用户真机三连：①下载卡住不动；②完成的歌要重启应用才出现在曲库；③要自定义下载路径。
- **根因（①，②是它的果）**：runner 里 `flushProgress → dispatch(progress) → store 通知 → subscribe 回调 pump() → pump 又调 flushProgress`——**同步自唤醒递归**；而 progress reducer 没有"值相同即不变"的短路，每次都换新状态对象、每次都再通知。渲染层被这棵递归树冻死，表现为"卡住不动"；重启后 KV 恢复任务、无递归路径跑完下载——于是"重启才出现"。
- **修法**：
  1. pump 里**删掉 flushProgress 调用**（进度只由 interval 驱动），progress reducer 加值相同短路；
  2. `fetchToFile` 加**停滞看门狗**（20s 无字节 abort → "连接停滞，正在重试" → 走重试续传）+ 进度 IPC 节流 200ms（防刷爆渲染层消息泵）+ 开始/完成日志；
  3. ingest 失败从无声改为 console.warn；
  4. **自定义下载路径**：主进程 `download:setDir`（目录对话框 → KV `download-dir` → 内存覆盖），下载页「更改下载目录」按钮；已有文件不搬，新任务生效。
- **坑**：**dispatch 的同步通知 + 订阅者里再 dispatch = 无界递归**。凡是"订阅 store 的执行器"，回调里要么不再 dispatch，要么先判幂等；本例三层叠加（递归 + reducer 无短路 + 每次都新建对象）才炸成冻屏。I2 的"单写者"挡得住并发写，挡不住这种**自触发循环**。
- **验证**：verify ALL GREEN。待真机：下载不再卡、完成即入曲库、更改目录生效。

  3. **store 的 reduce 幂等化**。原实现重复 dispatch 同一 intent 也会通知订阅者，被测试 4 抓到。改 store 不改测试 —— 这是真实缺陷，不是测试写错。

- **坑**：
  1. **lint 规则 1 一开始是假绿**。`layerOf()` 用相对路径匹配 `^src/renderer/`，而 `resolveLocal()` 返回绝对路径 → 目标层永远 null → 跨层 import 全部跳过。症状是"造了违规却不报"。修法：`norm()` 统一成 `path.relative(ROOT, path.resolve(...))`。**任何"解析后比较路径"的检查，都要先统一基准。**
  2. **规则 1 把 `main/` 和 `preload/` 也判了**。它们本来就该 import electron，是"环境"和"端口"，不在环里。加 `if (!me) continue`。
  3. **`JSX.Element` 在 React 19 里不可用**（全局 namespace 已移除），`tsc` 报 `TS2503`。去掉返回类型标注即可。
  4. **`npm config set ELECTRON_MIRROR` 在新版 npm 上直接报错**（不是合法 option）。正确做法是写项目级 `.npmrc` 的 `electron_mirror=`。
