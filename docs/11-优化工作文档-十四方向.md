## 2. 排序依据（为什么不按 14 个数并列做）

三条硬约束先行：

1. **`00 §17` 反目标与 `08 §7.4` 黑名单 12 条继续有效**：模组系统、15 种可视化、歌词 shader、全量 i18n、DLNA、一次接 7 家、手写 WSOLA、3D 混纹一律不动。
2. **前置条件未满足的（云同步）继续不做**：起算日 2026-11-03，单机稳定 ≥1 个月 + schema 冻结。
3. **先做"省力底座"，再铺功能**：§5 的三件底座做完，后面十项各自少一半工作量。

排序：

```
B0 底座（会话账本 + shell port + 能力/音质契约）   ← 先立
 → B1 演出交互（沉浸态）      ← 用户每天看得见
 → B2 系统集成（托盘/热键/媒体键） ← 缺口最大、感知最强
 → B3 音频管线（音质阶梯/gapless/ReplayGain）
 → B4 歌词（本地内嵌/偏移/翻译） ← 最容易撞上的洞
 → B5 队列歌单（插队/来源身份/M3U）
 → B6 统计与报告页（消费账本）
 → B7 缓存/搜索/主题/多源（按需穿插，各自独立）
```

## 3. 十四方向逐项

**做法**：本方向不新开功能，只做**归位**——新增能力全部满足两条：① 能进命令面板并用键盘完成；② 至少落在一个已有页（不新造页面壳）。唯一新页是「报告」（3.14），因为统计没有合适的既有落点。

**判据**：`docs/08 §7` 每条 🔨 变 ✅ 时，`docs/03` 有 commit 证据（`08 §10.2` 的自我纪律）。

**体量**：贯穿全篇，不单独计。
**不做**：社交、评论、云同步、PWA、DLNA、多端。

### 3.2 演出交互

**现状**：普通播放页已按 `stage-v10/a2` 重排（页头/活字格歌词/右栏队列+票据+相纸卡/台词本）；`resolveEsc` 五级优先序（`ui/input/keyboard.ts` 唯一 keydown）；迷你窗只有一态；沉浸页 `b2` 未做。

**借谁**：LX 的桌面歌词穿透（已借）、YesPlayMusic 的"克制的转场"（只取参数不取框架）、Rmusic 的沉浸最小集、SPlayer 的歌词页沉浸。

**做法**：
1. `StageConfig` 加 `layout: "normal" | "immersive"`（进 `contracts` + `kernel/store` + `sanitizeStageConfig`，坏值回落 normal）。
2. 沉浸态按 `b2` 重排：大标题 + 黑胶（同心圆 SVG、唱臂、已播热区扇形）+ 右栏词轴提词器 + 底部 HUD 细线 seek + 竖排 spine + 水印编号。**只写 transform/opacity/`--a`**（`00 §9.4`）。
3. Esc 在播放页内：`immersive → normal`；`normal → 退出播放页`。**这要扩展 `resolveEsc` 的上下文**——它现在只有 `{fullscreen, modals, panels}` 三类（`ui/input/keyboard.ts:27`），加第四类 `stage: "none" | "normal" | "immersive"`，按 `00 §9.5` 的五级优先序插在"面板"之后、"忽略"之前，并把穷举测试从 18 组合补到覆盖第四类。
4. 双击播放页 → 全屏（`document.fullscreenElement` 已在守卫里）；鼠标 3s 不动 → 加 `.idle`（`cursor:none` + 控件淡出），动一下即恢复。**用 transform/opacity，不用 display**。
5. 迷你窗两态（展开/收起）按 `10-mini` 稿；仍只暴露 3 个 IPC 方法（`00 §7.4` 纪律）。

**判据**：Esc 从沉浸退回普通**不退出播放页**；全屏下 Esc 先退全屏（现有测试不回归）；鼠标 idle 态无布局位移（截图对比）；迷你窗两态切换不新建状态写者。

**体量**：2 天（沉浸排版 1.5 + 交互 0.5）。
**不做**：路由转场库、3D 抽盘、鼠标跟随粒子。

### 3.3 特效

**现状**：四预设 × 3 档 intensity；取色只写 `--stage-tint`（`846d38b`）；频谱只属 cinema；视差 ±8px/阻尼 0.12；crossfade 等功率（`5d934e7`）。**自动降档未做**。

**借谁**：SPlayer（频谱/crossfade/取色三件已借完，不再加）；Twilight Echo（材质配方）。

**做法**：只补三件，都是"把已有的做稳"而不是"加新效果"：
1. **自动降档**（`08 §9` #4）：合成器里统计帧率，连续 2s <50fps → 关 C1（频谱）；仍 <40fps → C0 转静态（去 filter/transform）；>70fps 持续 5s 逐级恢复。状态只存 UI 局部（不进 store，不进持久化）。
2. **频谱参数化**：柱数/高度/基线进场景层 token（`--stage-spec-bars` 等），不改渲染路径。
3. **预设截图判据**：`stage-shots.mjs` 已能逐预设拍图（本轮修好入口），补"控件层四张同位"的自动对比（像素差仅允许在 C0–C3 区域）。

**判据**：降档/恢复全程布局不跳（截图 + `getBoundingClientRect` 断言）；`fx-0` 仍有完整观感（现有原则）；四预设控件区像素一致。
**体量**：2 天。
**不做**：15 种可视化、歌词 shader、节拍粒子、3D 封面（黑名单 + `08 §7.4`）。

### 3.5 音频音质管线

**现状**：唯一图 `双 audio → fadeA/B → preamp → eq[6] → analyser → destination`（`capability/audio/graph.ts`）；crossfade 0/3/6s 双路交替；远端流一律 `appstream://` 代理（治跨源进图静音）；**能力表 qualities 只有 `128k|320k`**——注意 `Quality` 类型本身**已含 `flac`**（`contracts/capability.ts:11`），缺的只是 netease 的 `traits.qualities` 只声明两档，**不用改类型**；preamp 是手动 dB，无 ReplayGain 分析；无输出设备选择；gapless 靠 crossfade 近似。

**借谁**：LX 的音质选择与降级顺序；Mineradio 的缓存原子写；SPlayer 的 crossfade（已借）。

**做法**（按收益排序，前两条必做）：
1. **音质阶梯纯函数**：`qualityPlan(preferred, available)` → `["flac","320k","128k"]` 的可用子序列，取流失败逐级降，**降级事实写 `player.quality` 只读展示**（不显示没拿到的音质）。能力表 `qualities` 从 `Traits` 读取，源声明什么就试什么。
2. **gapless 预装载**：crossfade=0 时也走"待命元素装 src → `canplaythrough` → 到点交换"，把现在的"切歌 8ms 淡出"升级为真正的无缝；`loadedmetadata` 只认主元素（`5d934e7` 的坑）。
3. **ReplayGain（读不分析）**：扫描时 `music-metadata` 的 `common.replaygain_track_gain` 有值就存索引；播放时 preamp = 手动值 + 曲目增益（夹 ±12dB）。**不做 FFT 响度分析**（要 worker + 全曲扫描，收益不抵）。
4. **输出设备**：`setSinkId` + `enumerateDevices`，设备列表进设置页；切设备不重建 `AudioContext`（I3）。
5. 采样率/位深/码率：有元数据才显示，没有显示 `—`（不编）。

**判据**：降级链穷举单测（每级失败/成功组合）；切歌到出声 <150ms 补测法接进 `perf.mjs`（`08 §9` #5）；EQ 曲线与滤波器参数一致（已有测试不退）。
**体量**：4 天。
**不做**：手写 WSOLA、DSD、独占模式（WASAPI exclusive）、DRM、云端响度归一。

### 3.6 元数据曲库管理

**现状**：`schema v1`（id = 规范化路径小写、path 保原样）；快照 + 增量日志 + `stat` 比对（M2）；`readTags` 8 路并发；两档去重建议（只建议不删）；封面按需 160px；三视图（`be28a44`）。**无标签编辑、无字段排序持久化、无目录监控、schema 无码率/采样率字段**。

**借谁**：Museeks 的本地库完整度（排序/多目录/标签信息展示）、Mineradio 的索引增量与缓存原子写、Folia 的"注册表式 schema 迁移"（迁移器集中在 `schema.ts`）。

**做法**：
1. **schema v2**：加只读字段 `codec?/bitrate?/sampleRate?/gainDb?/lyrics?`（后两个为 3.5、3.12 服务）；迁移器 `migrateV1toV2` 幂等，v1 快照照读。
2. **排序规则持久化**：KV `library-sort`（字段 + 方向），页面重开还原；排序是投影（`projection/library.ts`），不改 `tracks` 顺序。
3. **覆盖元数据表**（替代"写标签"）：KV `meta-override`，按键 `trackId` 存用户改过的标题/艺人/专辑/封面；显示层优先覆盖值，**永不写回文件**（写文件的失败模式太重：权限、编码、破坏原标签）。
4. **目录监控**（可选，最后做）：`fs.watch` 目录级 + 5s 防抖 → 增量 `stat` → 只更新变化项；不做常驻全盘扫描。

**判据**：v1→v2 迁移幂等（跑两次结果相同）；覆盖表清空后回到文件元数据；5000 首恢复预算（21.7ms 基线）不劣化 >20%。
**体量**：3 天（**schema v2 那 1 天落在 B3**，因为 B4 的本地歌词要存 `lyrics` 字段；其余 2 天在 B7）。
**不做**：写回文件标签、批量重命名、MusicBrainz 刮削（网络依赖 + 匹配歧义）、指纹识别。

### 3.7 歌单队列体系

**现状**：`QueueState{items,cursor,context,history,mode,shuffleSeed}`；**shuffle 是投影不是变异**（`kernel/queue.ts` `orderOf`）；3s 规则 `prevAction`；**队列已全量持久化**（`kernel/persist.ts:16/36` 的 `Snapshot.queue`，重启恢复 items/cursor/mode/seed）；`playlists` 只存 `trackIds` 不存曲目副本（`domain/playlists/index.ts:14`，M2 的决策）。
**缺的是队列的"编辑与来源"**：无插队（play next / add to queue）、无单条移除/拖拽排序、`context` 只记曲目数组**说不出"来自哪张专辑/哪个歌单"**、无 M3U 导入导出、无智能歌单。

**借谁**：Nuclear 的队列 UX（play next / add to queue 两键分明）、Museeks 的 M3U 与播放列表管理、MusicFree 的歌单抽象。

**做法**：
1. **插队 intent**：`queue/insert`（`at: "next" | "end"`）。插队**不改 `context`**（context 是"这批歌从哪来"，插队是临时意愿）；shuffle 模式下插到"当前顺序位置 +1"，不是 `items` 的 +1。
2. **context 加来源身份**：保留 `context: TrackId[]`（曲目集合，用于"回到专辑播放"），新增 `origin?: { kind: "album" | "playlist" | "search" | "likes" | "recent" | "radio" | "roam"; id?: string; name: string }`。UI 在队列/播放页显示"来自《xxx》"——这是现在**完全说不出**的信息。
3. **队列编辑**：单条移除（cursor 跟随修正，删的正好是当前曲时按"下一首"接续）；拖拽排序**只在非 shuffle 下可拖**，shuffle 下禁用并给一句说明（否则"投影 vs 变异"立刻打架）。
4. **M3U8 导入导出**：纯文本 `#EXTM3U/#EXTINF`，零依赖；导入时路径不存在的条目**列出来让用户决定**，不静默丢。
5. **智能歌单（只读）**：规则 = 标签 + 红心 + 最近窗口，结果每次现算（不落库）；先只做「最近 30 天常听」一条，验证结构。

**判据**：插队后 `context` 与 `origin` 都不变（单测）；shuffle 下插队落在"下一个播放位置"；M3U 往返（导出→导入）曲目序列与时长等值；删除当前曲后播放接续正确；队列重启恢复与持久化前 `next/prev` 行为一致（现有恢复测试加断言）。
**体量**：3 天。
**不做**：跨设备队列、云歌单、协作歌单。

### 3.8 多音源调度

**现状**：`registry` + `MethodCapabilities`（11 位方法型）+ 启动断言（声明 true 必有实现）+ 12 错误码 + `translateError` 唯一出口 + 每源 session 分区（`05cc5fd`）+ QQ 本地拉起服务（MIT 包）。**无跨源 fallback、无结果去重合并、无健康度熔断、无同源并发限制**。

**借谁**：MusicFree 的"能力声明驱动 UI"（已借）、Nuclear 的"插件按职责分层"（已借）、Mineradio 的"每源独立 session"（已借）。**这三家在这一项上已经被抄完了，剩下的是工程细节，没有第四家可借**（E2）。

**做法**：
1. **跨源 fallback**：`resolveWithFallback(key, sources[])`——同一首歌在多家命中时按用户排序依次取流，命中即停；全部失败按"最后一个错误"上抛（不吞）。
2. **结果合并去重**：键 = `normalize(title) + normalize(artist) + round(durationMs / 2000)`；合并后保留"哪几家有"（用于 UI 显示可切换源）。
3. **健康度熔断**：连续 3 次 `network` → 冷却 5 分钟（内存态，重启清零，不污染持久化）；冷却期该源直接跳过并显示"稍后重试"。
4. **同源串行**：同源请求并发 ≤1（队列化），避免本地拉起服务被并发打爆。

**判据**：禁用一家源后搜索/播放仍可用（fake provider 单测）；冷却期上游请求次数为 0（日志计数断言）；合并去重对同名不同版本（时长差 >2s）不误合。
**体量**：3 天。
**不做**：一次接 7 家（黑名单）、自建服务端、协议逆向、自动切换音源时的静默换曲（用户必须知情）。

### 3.9 全局快捷键与系统托盘

**现状**：**两个都没有**。`grep -E "Tray|globalShortcut|setLoginItemSettings|powerSaveBlocker|thumbar"` 在 `src/` 零命中；只有应用内 `keyboard.ts`（Esc 五级 / Ctrl+K / Ctrl+F / Space）；关窗即退出；无媒体键、无任务栏缩略图按钮、无 `MediaSession`。
> `08 §2` 把 Rmusic 那行的"全局快捷键"标成 ✅ 是**错的**——那指的是应用内快捷键。本文件纠正：系统级未做。

**借谁**：Rmusic（热键最小集）、LX（托盘菜单 + 播放控制 + 迷你窗联动）、YesPlayMusic（Mini 模式入口）。

**做法**：
1. **一条 intent 通道**（关键设计）：主进程所有系统事件（托盘菜单、全局热键、缩略图按钮）**只发同一条结构化 intent** 给主窗（`preload` 单向 `send`），**主进程不持有播放状态、不自己读 store**（I2）。渲染层收到后走与按钮完全相同的 `dispatch`——托盘菜单因此永远和界面同源。
2. `main/shell/tray.ts`：图标 + 菜单（播放/暂停、上一首、下一首、显示主窗、迷你窗、打开播放页、退出）；菜单项的"当前状态文案"由渲染层**回推**（`tray:sync` 单向，最多 500ms 节流），主进程只做展示。
3. `main/shell/shortcuts.ts`：默认注册媒体键三兄弟（`MediaPlayPause`/`MediaNextTrack`/`MediaPreviousTrack`）+ 可配置组合（默认 `Ctrl+Alt+Space` 播放暂停、`Ctrl+Alt+Left/Right` 切歌、`Ctrl+Alt+M` 迷你窗）。**注册失败要能降级**（被其它应用占用时记日志、不抛、设置页显示"被占用"）。
4. `main/shell/thumbar.ts`（Windows）：`setThumbarButtons` 三个按钮（上一首/播放暂停/下一首），同一 intent 通道。
5. **`MediaSession`**（渲染层，OS 级媒体面板）：`metadata`（标题/艺人/专辑/封面）+ `setActionHandler`（play/pause/next/prev/seekto）；封面用当前 `coverUrl`（160px 够）。
6. **关窗语义**：设置项 `closeToTray`（**默认关**——"点了叉还在跑"会吓到人），开了才 `hide()`；托盘「退出」走 `app.quit()`，退出前触发 `persist` flush（现有 `beforeunload` 路径）。
7. 设置页新增「系统」一段：托盘开关、关窗行为、热键列表（只读展示当前生效组合 + 冲突提示），**不做热键录制 UI**（M6 的"录键中"守卫留位）。

**判据**：
- 窗口隐藏时媒体键仍生效（系统键 CDP 触发不了 → **主进程日志断言 + 人工清单**双轨，写进 `docs/07`）；
- 托盘菜单任意项执行后，界面状态与菜单文案一致（同一 intent，无双写者）；
- 热键被占用时不崩、设置页给出"被占用"；
- `closeToTray` 关闭时点叉 = 真退出（回归：不出现"进程还在但窗口没了"）。

**体量**：3 天。
**不做**：开机自启（`setLoginItemSettings` 留位，等用户明确要求）、多套热键方案、托盘悬浮歌词、Windows 跳转列表（JumpList）。

### 3.10 搜索索引

**现状**：拼音首字母 21KB 表 + 打分（字段开头命中优先）+ O(n) `includes`；5000 首 11.9ms、预算 100ms（M2）。**没有倒排索引，也不该现在建。**

**借谁**：Museeks 的库内搜索"够用就好"、Folia 的字段权重（已借打分）。

**做法**：只做两件零成本的事，然后**写死触发条件**：
1. 输入规范化：全角→半角、去多余空格、多词 AND（`"周 青花"` 能命中）；
2. 结果稳定排序：同分按曲名 `localeCompare("zh-Hans-CN")`（现在同分顺序依赖数组顺序，翻页会跳）。
3. **触发条件（写进本文，到点再动）**：库 >2 万首 **或** `searchMs` 基线 >50ms 才上倒排索引；届时在 Worker 里建"首字母/艺人/专辑"三张倒排 + `setTracks` 增量更新，不进主线程（`00 §13`）。

**判据**：现有 perf 搜索预算不劣化；`"周 青花"`/全角输入能命中（单测）；同分顺序稳定（两次调用结果相同）。
**体量**：1 天。
**不做**：现在建倒排（YAGNI）、拼音全拼表（103KB，M2 已决）、Elasticsearch/Lunr 之类依赖。

### 3.11 主题持久化配置

**现状**：`ui-theme` KV + `data-theme` 属性（`a317ed9`）；三层 token（结构/场景/材质）；主题包 JSON 导入导出（`.json` 不是 zip，`499dafe` 的偏离）；纸纹不可关；**三窗不广播**（各窗启动值正确，切换不同步）。

**借谁**：Twilight Echo 的"可换材质"（token 数值层）、Vynody 的 token 三层（已借）。

**做法**：
1. **主题包 v1→v1.1**：加 `meta{name,author,version}`（可选）+ 现有 `sanitizeThemeTokens` 校验；导入后设置页显示包名（现在只有"自定义主题 ✕"）。
2. **纸纹开关**：KV `grain`（off/soft/full → 0/0.05/0.1），`--grain-opacity` 由它驱动；夜间仍自动减半 + `soft-light`（`a317ed9` 的坑）。
3. **跨窗同步**：主进程 `theme:changed` 广播（主窗 → 迷你窗/歌词窗），三窗各自 `applyTheme`；广播只带主题名，不带 token 值（值的唯一来源仍是 `tokens.css`）。
4. **跟随系统**：`nativeTheme.shouldUseDarkColors` + `updated` 事件 → 仅在用户选"跟随系统"时生效（三选项：纸色/墨色/跟随）。

**判据**：三窗切换在一帧内一致（截三个窗对比）；坏包导入不崩（sanitize 测试）；纸纹关掉后 `html::after` 不渲染（`opacity 0` 而非 `display:none`，避免重排）。
**体量**：2 天。
**不做**：在线主题市场、CSS 注入式主题（绕过 token 纪律，等于把 186 个 `!important` 请回来）。

### 3.12 歌词渲染子系统

**现状**：LRC/增强 LRC/QRC/YRC/TTML/纯文本 → `LyricDoc`（毫秒）；四个渲染器**行判定只有 `activeLine` 一份**、对拍 diff=0 由结构保证；桌面歌词窗（穿透/锁定/位置 KV）。**本地曲目没有歌词**（只在线可取）；无翻译行显示；无偏移校准；无手动换词。

**借谁**：LX 的桌面歌词（已借）、SPlayer 的逐字与翻译（逐字已借）、YesPlayMusic 的排版克制。

**做法**（① 是当前最容易撞上的洞，先做）：
1. **本地内嵌歌词**：扫描时读 `common.lyrics`（ID3 `USLT` / Vorbis `LYRICS` / MP4 `©lyr`），存索引 `lyrics` 字段（截断 16KB/首，超了记 `truncated`）；播放页优先用内嵌，没有再走在线。`music-metadata` 已能读，**零新依赖**。
2. **翻译行**：`LyricDoc.translations` 字段已留；press/theatrical 下渲染为当前行下方小字（12px，`--stage-fg-dim`），**不参与行判定**（对拍测试必须仍为 0）。
3. **偏移校准**：KV `lyric-offset:<trackId>`（±5000ms，100ms 步进），只改消费端 `t - offset`，**不碰 clock**（I1）；UI 在台词本页头给 −/+ 两个按钮与当前值。
4. **手动换词**：在线曲目按"标题 + 艺人"重搜歌词，结果 KV 缓存 `lyric-pick:<trackId>`；失败明确说"没找到"，不静默回退到上一份。

**判据**：带 USLT 的本地 mp3 能出词（fixture 造一个）；偏移 ±300ms 生效且重启保留；翻译行不影响 `compareRenderers`（测试仍 diff=0）；换词后 `lineIdx` 重置、桌面歌词窗同步清行（`82cf764` 的行为）。
**体量**：4 天。
**不做**：歌词 shader、AI 生成歌词、逐帧动画歌词（黑名单）、卡拉 OK 打分。

### 3.13 性能缓存

**现状**：封面主进程 LRU 500 + 渲染层 LRU 200 + 并发去重（`main/fs/cover.ts:13`）；索引快照 + 追加日志 + **超 200 条自动压缩回快照**（`domain/library/index-store.ts:15` `COMPACT_THRESHOLD`）；perf 三条预算 + 基线劣化 20% 红（含"劣化先重测两轮取中位"防假红）。**真缺的是封面磁盘缓存**（每次启动重新解码）+ 两条未测预算。

**借谁**：Mineradio 的"缓存原子写 + 上限 LRU"（思路已借，未落到封面磁盘）、Museeks 的库加载体验。

**做法**：
1. **封面磁盘缓存**：`cache/covers/<sha1(path + mtime + size)>.webp`（160px，上限 200MB，LRU 按访问时间淘汰）；命中直接返回，未命中解码后**原子写**（`.tmp` → rename）。key 带 mtime/size，文件换图自动失效。
2. **封面尺寸分级**：列表 40px / 播放页 160px / 唱片墙 320px 三档，按用途各缓存一份，别用 320 的图去填 40 的坑。
3. **预算扩展**：内存 <300MB、切歌到出声 <150ms（`08 §9` #5 同一条），两条都进 `perf.mjs` 或 `docs/07` 人工清单。
4. **不做预取扩张**：队列"下一首"已 `preload="auto"`，再往前预取会抢带宽（在线曲目尤其）。

**判据**：二次启动封面首屏 <100ms（脚本计时）；磁盘缓存超限自动淘汰（单测：写 210MB 假条目）；key 随 mtime 变化失效（换图测试）；内存与出声两条预算有数字口径（可人工跑）。
**体量**：2.5 天。
**不做**：SQLite/better-sqlite3（native ABI）、音频流缓存（M7 已定不做边下边播）、多级缓存框架、日志压缩（已有 `COMPACT_THRESHOLD`）。

### 3.14 听歌统计

**现状**：**完全没有**。`history` 只有 `{trackId, at}`，连续同一首去重、上限 300（`domain/history/index.ts:37`）——算不出"今天听了多久""这首歌听了几次""完成率"。

**借谁**：Museeks / Nuclear 的"播放计数"思路（本地库该有的账）；SPlayer 的"听歌排行"是平台接口给的，我们不依赖平台，**因此必须自建**（这是唯一不能借、只能自己长的一项）。

**做法**：
1. **会话账本（跨方向底座）**：`domain/listening/log.ts` 纯函数
   `finalizeSession({trackId, sourceId, startedAt, playedMs, durationMs, completed})`
   写入条件：`playedMs ≥ 30s` **或** `playedMs ≥ 50% × durationMs`；同一曲连续只记一次（沿用 `history` 的规则，避免单曲循环刷屏）。
2. **存储**：KV 按月分片 `listening-YYYYMM`（单条 ≤120 字节：`{t, s, ms, d, c}`）；聚合快照 `listening-agg`（日时长、艺人 top50、专辑 top50、完成率），每次写入后 5s 防抖重算。
3. **统计投影**：`projection/stats.ts` 纯函数 `rangeTotals(from,to)` / `topArtists(range,n)` / `heatmap(365d)` / `completionRate(range)`。
4. **UI「报告」页**：三段——本周总时长（大数字 + 环比）、365 天热力图（单色阶梯，不用彩色）、艺人 top10 列表；空态诚实写"从今天开始记，明天就有数"。导航放「我的」分组（`pages.ts` 加一行）。
5. **隐私**：全部本机，随备份导出 JSON，**无任何外发**；设置页给"清空听歌记录"。

**判据**：连续播同一首 3 次只记 1 条；跨月落两片；清空后热力图归零；单条 ≤120B（对 1000 条序列化后断言）；坏分片只丢当月（其余月份照常聚合）。
**体量**：4 天。
**不做**：last.fm scrobble（外发，与 `00 §10.2` 的凭据/隐私精神不符）、社交排行、年度报告视频、云同步统计。

### 5.1 账本落地：唯一写者是谁，与 history 什么关系

这是 B0 必须先定死的两件事，否则实现时一定长出第二个写者。

**① 唯一写者不在 reducer 里。**
`queue.history` 现在由 `kernel/store.ts:85`（`queue/next`）与 `:105`（`player/play`）直接算——那是**纯数据**，可以留在 kernel。但账本要读时长、判阈值、落 KV，三条都超出 kernel 的权限（kernel 不许 import domain，也不碰端口）。
所以账本的唯一写者是 **`ui/bootstrap.ts` 里那个唯一的 player 状态订阅**（与现有 `saveHistory`/`persist.schedule` 同址）：在 `playing → paused/ended`、切歌前、窗口退出前三个时机各结算一次，调 `domain/listening` 的纯函数算出一条 session，再 `appendSession(port, entry)`。
`domain/listening` **不持有全局可变数组**（跟 `history` 的 module-level `entries` 不同）：账本是 append-only 日志，读的时候从 KV 分片投影，避免"内存里一份、盘上一份"的第二真相。

**② 账本与 history 不合并。**
两者语义恰好相反：`history` 是"每首只留最后一次"（去重，`history/index.ts:40`），账本是"每一次合格播放都记"（重复计数）。合并会让"最近播放"被刷屏，或让统计丢次数。
分工写死：`history` 继续做「最近播放」页的数据源；账本只服务「报告」页。UI 文案也要分开——recent 页说"最近播放"，报告页说"听歌记录"，不要都说"历史"。

**③ 阈值口径**（避免两处判定不一致）：`playedMs ≥ 30_000` **或** `playedMs ≥ 0.5 × durationMs`；`durationMs` 未知（在线曲目拿不到时长）时**只按 30s 判**，并在记录里标 `d: null`。
