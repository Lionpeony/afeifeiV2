# 02 · 取用台账

> 从旧仓库或第三方取了什么、从哪取、**为什么取**。第三列是唯一有信息量的。

## 已取用

| 取了什么 | 从哪 | 为什么取 |
|---|---|---|
| `scripts/lint.mjs` 的规则 1 骨架 | 旧仓库 `tools/check-layers.mjs` | 文件遍历 + import 解析 + 层判定这套结构已经验证过；只改了 `LAYERS` 表与层名，逻辑重写反而引入新 bug |
| 拼音首字母表（20992 字符，21KB） | 旧仓库 `app/renderer/pinyin-data.js` 的 `i` 字段 | 汉字→首字母没有能算出来的办法，只能查表。**只取了首字母，没取完整拼音**（`f` 字段 103KB）——"打 2 个字符出歌"只需要首字母，数据也有预算。将来要全拼时从同一处取 `f` |
| `NeteaseCloudMusicApi`（npm，MIT，4.32.0） | 第三方依赖 | 网易云 weapi/eapi 加密通道自己写成本高且易错；Folia 用的是同一套做法。只在主进程 `main/net/neteaseClient.ts` 内嵌，不进渲染 bundle |
| ~~`qq-music-api`~~（npm，**无 license**，1.1.2） | 第三方依赖 | **已于 2026-11-03 移除**。无 license 未取用；已被下面的 MIT 包取代 |
| `@yakult-green-tea/qq-music-api`（npm，**MIT**，3.3.5） | 第三方依赖 | QQ 扫码登录（MQTT/HTTP 双通道）+ 登录态会话 + 登录态播放地址，整包作为本地服务由主进程拉起（Folia 生产同款）。手写 ptlogin 协议被 TLS 指纹风控拒（2026-11-03 实测），"先验后写"在协议层不可行——换"用别人验证过的实现" |
