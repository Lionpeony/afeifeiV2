## 3. 推荐内核（Ring 1，纯函数）

`domain/recommend/index.ts`：

- `dailyPicks({ tracks, liked, recent, seed, count })` —— 红心优先 → 最近播放 → 曲库补充，配额「艺人 ≤3、专辑 ≤2」，跳过在线直链
- `dailySeed()` / `nextRefreshMs()` —— 日期串 FNV 哈希做种子，每天 06:00 换新；同一天跨进程同一份
- `recentAdds` / `recentPlayed` / `radioOf` / `reasonOf` / `shuffledBy`

**为什么在 Ring 1**：推荐是业务判断，不是系统调用；放 UI 里就无法测、无法复现，也违反五环依赖方向。测试：`test/recommend.test.mjs`（6 条：同种子稳定、红心优先、配额、06:00 边界、跳过直链、电台门槛）。

## 4. 坑（下一个窗口会重踩的）

1. `.body` 必须写 `grid-column: 1 / -1`。不写就落进 96px 导航列，`.main` 被挤成 0 宽 —— 现象是「主区整片空白 + 导航不高亮」，看着像数据没加载。
2. `h1` 的 `textContent` 必须正好是 `afeifei`。SMOKE 断言在这里；中文副名要拆到 `h1` 外面，不能塞 `<span>`。
3. UI 里不许用 `setInterval` 驱动界面（lint 会拦）。倒计时挂 `onTick`，并且**文本没变就不写 DOM**，否则每帧一次 `textContent` 赋值。
4. `.btn.primary:disabled` 要单独给灰态，否则禁用的主按钮仍是朱砂红，看着像能点。
5. 走带按钮会被 `.transport` 的 `flex: 1` 拉伸 → `.tb` 必须 `flex: none`。
6. 音量是 0–1 状态量纲；早先滑杆用 0–100 再换算，两处都能写错，已统一。

## 7. 不要重新发明

- **不造假数据**：没有推荐接口就不做榜单，没有电台流就不做主播，没有红心时间戳就不画「收讫日」。
- **不造第二个时钟**：任何随播放前进的东西只能读合成器的 `t`（`onTick`）。
- **不新增领域模型**去还原某张稿子的区块；先问「这份数据现在存不存在」。
