# 05 · 发布检查单（M8）

> 发版前逐项打勾。全绿才打 tag、才发便携包。缺一项就停，不许"下次补"。

## 1. 代码与验证

- [ ] `npm run verify` ALL GREEN（typecheck / lint / build:test / test / build / smoke / perf）
- [ ] `node scripts/todo-count.mjs` TODO 处数不高于上次发版
- [ ] `docs/03-改动日志.md` 最新条目与本版变更一致，无"缺标题"结构问题

## 2. 版本与 tag

- [ ] `package.json` `version` 已按 semver 提升（tag 形态只允许 `主.次.补丁`，不带 prerelease——更新检查的 `isNewer` 只认这个形态）
- [ ] `git tag m<X>` / `v<版本号>` 已打，`git status` 干净

## 3. 打包与试装

- [ ] `npm run dist`（electron-builder）成功，产物在 `release/`
- [ ] exe 属性里有版本号与图标（M8 判据；Windows 开发者模式签名配置见 M8 第 3 项）
- [ ] 便携包在**另一台没装过开发依赖的机器**上试装：启动、扫码登录、在线播放、下载、EQ/预设重启恢复各过一遍
- [ ] 旧版本升级安装：数据（曲库 / 收藏 / 歌单 / KV）原样保留

## 4. 更新链路

- [ ] `docs/04` M8 第 1 项的 `REPO` 常量指向真实仓库，GitHub Releases 上有比当前版本新的 tag → 启动 30s 内出提示、点提示能打开发布页
- [ ] 无新版本时启动零打扰（不出现任何更新提示）

## 5. 崩溃兜底

- [ ] 人为制造渲染进程崩溃（任务管理器杀渲染进程）→ `logs/crash-*.log` 生成
- [ ] 再次启动出现"上次异常退出"提示，且只提示一次

## 6. 数据安全

- [ ] 备份导出 → 清空 dataDir → 备份导入 → 重启：曲库 / 收藏 / 歌单 / KV 全部回来
- [ ] 备份目录**不含** cookie / 登录凭据（抽查备份目录内容）
- [ ] 选一个不是备份的目录做"恢复"→ 被拒绝且有提示

## 7. 文档

- [ ] `docs/README.md` 编号表与本版新增/改名的文档一致
- [ ] `docs/00-设计基线.md` 与实现无已知冲突（有冲突先改 00）

---

**流程**：1 → 2 顺序执行；3–6 可并行；任何一项失败，修完**从第 1 项重跑**——verify 是门，不是橡皮章。
