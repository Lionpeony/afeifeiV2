### 8.2 八关（按 `docs/22` §四 顺序，一关不绿就停）

**关 1 · 坏文件三连**（P0-14 / P0-15 / P0-16）
1. 队列排：好曲 → 不存在的路径 → 403 直链 → 扩展名合法但内容是文本的文件 → 好曲。
2. 从头播。
3. 期望：每首 **5s 内掠到下一首**；队列对应行显示「播不了 · 点一下重试」；**连掠 3 首后停机并给原因**，不无限跳；状态栏有记录。
4. 设置页「播放失败时」改**暂停** → 重放坏项 → 停在错误态**不跳**；改回**跳过** → 又自动跳（P0-15 重启后仍保持）。
5. 点带标记那行重试；把文件放回去再点 → 真播起来 **500ms 后标记自己消失**（P0-16）。

**关 2 · 队列五操作**（P0-10 / 11 / 12）
底栏「队列」开抽屉 → 应**自动滚到当前曲** → 点第 20 首（立即切，抽屉不关）→ 第 3 首拖到第 1 位（拖到列表顶边应自动滚动；有插入线；当前播放**不中断**）→ 行内 × 删当前曲（自动接下一首）→ 「清空」点一次**不空**、再点确认才空 → 空态文案。
再加一条：切到**随机**模式，拖拽应禁用（拖 items 改不动播放序）。

**关 3 · 拖进度松开**（P0-03）
按住进度条 3 秒不松 → **声音完全不动**，时间显示的是"要跳到哪儿"；松手才跳。键盘 ←/→ 仍是即时跳 5s。

**关 4 · 切第二个声卡**（P0-09）
设置 → 输出设备 → 选第二个 → **立刻生效**（声音从第二设备出）。拔掉/禁用该设备 → 回退 `default` 且**有提示**，不静默无声。
> 只有一块声卡时用 VB-Cable 之类虚拟声卡代替，别跳过。

**关 5 · 慢半拍的词调准**（P0-18 / P0-21）
放一首词明显慢半拍的（或把 lrc 时间戳整体 +800ms）→ 播放页「视图」→「校准」`+0.5s` 两次 → 词对上 → 切走再切回 **仍准** → 重启 **仍准**。
桌面歌词窗（底栏「词」）与迷你窗**同步跟着准**；两者与主窗的偏差要 **≤100ms**（P0-21 明确没做实测，就靠这关补）。

**关 6 · 拔网线**（P0-25）
播本地曲 → 拔网线/禁用网卡 → **1s 内**顶部常驻横幅；在线/榜单入口与搜索置灰 → 本地曲**照常播** → 插回 → **1s 内**横幅消失。
> 已知不覆盖：Wi-Fi 连着但出口断（DNS 黑洞）不触发 `offline`。

**关 7 · 迷你窗往返**（P0-27）
底栏「迷你」→ 小窗里有封面、当前歌词行+译文、进度可拖、hover 出控制条 → 双击封面**回主窗** → 把小窗拖到屏幕右下角 → 重启应用 → 再开迷你窗，**位置回来**。
> 强杀进程会丢最后一次位置（只在拖动结束/关闭时写盘）。

**关 8 · 不带鼠标走一遍**（P0-22 / P0-23）
键位表逐条：`Space` / `←→` / `Shift+←→` / `↑↓` / `M` / `L` / `0–9`（播放页）/ `Esc` / `Ctrl+K` / `Ctrl+F`。
焦点在搜索框时**不抢键**（空格出空格）。窗口失焦后按 `Ctrl+Alt+←/→` → 跳 5s；**长按只算一次**（250ms 冷却）。切歌已退到 `Ctrl+Alt+Shift+←/→`。
> 这台机器 `Ctrl+Alt+W` 被别的程序占着（日志「未注册」），不算回归；换机器重验。

### 8.3 已知遗留——出现这些**不要当 bug 记**

- 在线曲目没有真实时长，相纸/中心标时长是 `--:--`
- 离线时的置灰只在 CSS 层（`pointer-events`），Tab 仍能走到并触发搜索
- 迷你窗没有封面模糊底
- 睡眠定时到点没有系统通知，只有按钮上「等这首完」
- 单曲循环 + crossfade 不做自动淡入；repeat-one 靠 `player/ended` 兜底
- 长按方向键 = 连续 seek（没做节流，实测跟手）

### 8.4 PERF 门禁的当前状态（2026-11-04 已修，不再是红）

此前 `verify` 的 PERF 步骤连续判红、被记成「环境波动」三次。**那次是误判**，实测数据：

| | 老代码 `10d431c`（录基线那版） | HEAD |
|---|---|---|
| restore 7 轮中位 | 31.7ms（22.3–36.6） | 42.7ms（29.2–47.0） |
| 同版本另一组 7 轮 | — | 32.2ms |
| 基线文件原值 | 21.7ms（2026-11-02） | — |

- **基线 21.7 用老代码也复现不出来**（31.7，+46%）——「机器漂移」真实存在。
- **同一版本两次 7 轮中位就差 10.5ms**，而新老差异 11ms → 噪声 ≥ 差异，**测不出回归**。拿 22.8（单次）比 47.5（三次中位）得出的「真回归」是错的，样本不对等。
- 恢复耗时拆解：`IPC 7.3 + 建拼音键 9.8 + 通知 0.2 = 17.3ms`，其余约 15ms 在第二次 IPC（`readLog`）+ parse + migrate + replay。没有新增逻辑。

根因是**判据精度**：20% 在 20–50ms 的指标上只等于 4–10ms，比噪声还小。

现行判据（`gate:` 提交，原值→新值）：

| 项 | 原 | 现 |
|---|---|---|
| restore 绝对预算 | 120ms | **80ms**（实测 30–50ms，120 留 3 倍余量等于没护栏） |
| 相对基线判红 | 超 20% 即红 | 超 20% **且**绝对差 >15ms 才红（`NOISE_MS`） |
| 基线 | 21.7 / 4.9 / 7.1（2026-11-02） | **43.7 / 7.8 / 9.3**（2026-11-04 重录，三次中位） |

> 采样时见过 `max` 帧间隔 52s：窗口失焦/遮挡时 `requestAnimationFrame` 会被 Chromium 节流到 1fps 甚至暂停。测滚动必须保证窗口可见、别开别的全屏程序——p95 不受影响，`max` 会骗人。
