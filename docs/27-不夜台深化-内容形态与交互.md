## A · 真实素材

### A.1 现状与证据

| 问题 | 证据 | 后果 |
|---|---|---|
| 音频是静音 WAV | `scripts/live-shots.mjs:28` `wavFor` 只写 44 字节头，数据区全 0 | 频谱柱、信号表、声纹全是平的；截图「看起来像坏了」 |
| 封面是三种配色的同心圆 | `scripts/live-shots.mjs:88` `coverOf` | 直播间的唱片/封套没有真实质感；轮播无法证明「不同封面 = 不同视觉」 |
| 只有一套 fixture | 三张专辑 × 六首，标题固定 | 无法验证长标题、无封面、单曲专辑等真实边界 |

### A.2 改法

**A.2.1 有声 fixture（`scripts/live-shots.mjs`）**

把 `wavFor` 从「写零」改为「写真实波形」：

- 8kHz → **22050Hz** 单声道 16bit（体积可控，频谱有高频内容）。
- 每首用 `trackId` 派生一个种子，生成：
  - 3–5 个正弦分音（基频 110–440Hz，按种子定）；
  - 一个节拍包络（每 0.5s 一个衰减脉冲，模拟底鼓）；
  - 低幅白噪声（-42dB，防止频谱过于干净）；
  - 4 秒淡入淡出，避免截图时爆音。
- 时长仍跟随曲目元数据。
- 纯函数 `synthWav(seconds, seed)`，放在脚本内，可被 `node -e` 单独验证。

**判据**：`node scripts/live-shots.mjs` 后，频谱截图中 `analyser` 的 `getByteFrequencyData` 有 > 0 的柱；信号表非平线。

**A.2.2 程序化封面（`scripts/live-shots.mjs`）**

`coverOf` 升级为「设计过的占位」：

- 保留三张专辑的色板，但按专辑名 hash 生成几何构图（圆环 / 斜线 / 网格，三选一）；
- 加入 4–6 张「边界封面」：超长标题、纯黑、纯白、无封面（`hasCover:false`）；
- 生成方式仍是 SVG data-uri，不引入图片文件、不涉及版权。

**判据**：轮播截图中相邻封面明显不同；无封面曲目的占位盘与有封面曲目可区分。

**A.2.3 真实库入口（可选，不阻塞）**

给脚本加 `--library <目录>`：
- 有参数时走真实扫描 → 真实标题/封面/时长；
- 无参数时保持现有 fixture。
- `perf.mjs:139` 已有真扫描先例（`C:\Windows\Media`）。

**不做的**：不把真实音频提交进仓库；不在 CI 依赖真实曲库。

## C · 内容形态

### C.1 现状与证据

| 问题 | 证据 | 后果 |
|---|---|---|
| 12 房间同一副骨架 | 各 `views/*/index.tsx` 均为 `PageHead + 工具条 + .lib-list` | 换皮只能换皮，页面之间只有数据不同 |
| 编排模型缺失 | 只有 `domain/station/schedule.ts` 服务首页；房间没有「播什么、按什么顺序」的概念 | 房间无法成为「节目」，只能是「列表」 |

### C.2 改法：先抽投影，再做样板

**C.2.1 `RoomProgram` 投影（新文件）**

`src/renderer/projection/room-program.ts`，纯函数、可单测：

```ts
export type RoomKind = "tape" | "shelf" | "board" | "report" | "form";

export interface RoomProgram {
  kind: RoomKind;
  /** 编目元信息：房间名、计数、时段说明 */
  meta: { title: string; count: number; note?: string };
  /** tape：按时间/名次排开的段；shelf：分组后的书架；board：状态列 */
  segments: ProgramSegment[];
}

export interface ProgramSegment {
  key: string;
  label: string;
  items: ProgramItem[];
  /** 时间型段落的起止（ms），供走带/归档带用 */
  fromMs?: number;
  toMs?: number;
}

export interface ProgramItem {
  id: string;
  title: string;
  sub: string;
  durationMs?: number;
  cover?: boolean;
  state?: "queued" | "active" | "done" | "error";
}
```

每个房间只负责「把域数据映射成 RoomProgram」，与渲染解耦。

**C.2.2 四种编排语法**

| 语法 | 房间 | 形态 | 与列表的区别 |
|---|---|---|---|
| `shelf` | 本地、歌单、在线 | 封面墙 + 字母尺 + 馆藏计数；行是「展开后的索引」 | 首屏是空间不是表格 |
| `tape` | 最近、喜欢、榜单 | 横向归档带，格子宽度随时间/名次变化 | 顺序本身是信息 |
| `board` | 下载 | 三列看板：排队 / 传输中 / 已归档 | 状态迁移可见 |
| `report` | 统计 | 时段热力 + 排行，不做单一柱状 | 数据形态不止一种 |
| `form` | 设置 | 保留表单 | 工具页就该像工具 |

**C.2.3 样板间（先做三个）**

1. **本地 `shelf`**：`views/library/index.tsx`
   - 首屏：专辑封面墙（4 列，按字母分组）+ 顶部字母尺 + 馆藏计数；
   - 点击专辑 → 下钻到曲目索引（保留现有行表与虚拟列表）；
   - 搜索聚焦时回到行视图（搜索要的是效率，不是浏览）。
2. **喜欢 / 最近 `tape`**：`views/liked/index.tsx`、`views/recent/index.tsx`
   - 横向归档带：每一格 = 一首，越近越宽；带下方保留行表作为精确视图；
   - 喜欢页保留账号区块（两栏各自完整，不做合并）。
3. **下载 `board`**：`views/downloads/index.tsx`
   - 三列状态板；完成项 2 秒后从中间淡出（`fx-0` 下立即移除）；
   - 失败项留在原列并标红，可重试。

**判据（每页都要有）**：
- 冒烟断言首屏存在新结构（`.shelf-wall` / `.tape-rail` / `.board-col`），且旧 `.lib-list` 不是唯一主体；
- 1024×768 / 1280×800 / 1440×900 三档无横向溢出；
- 点击、播放、红心、下钻行为与改前一致（用现有 smoke 断言兜底）；
- 空态、加载态、错误态各有对应形态。

**C.2.4 铺开（样板立住后）**

| 批次 | 房间 | 语法 | 状态 |
|---|---|---|---|
| 2 | 歌单、在线、榜单 | `shelf` / 结果带 / 榜单带 | 2026-11-05 已落地 |
| 3 | 漫游、电台 | 已有转盘 / 频段墙形态 | 不改（避免同质化） |
| 4 | 统计 | 时段热力带 | 2026-11-05 已落地 |
| 设置 | 不改 | `form` | — |

**不做的**：不给每个房间硬塞节目带；不同房间必须用不同语法，避免同质化换位。

## E. 验收（整条战线）

1. **素材**：有声音频让频谱 / 信号表 / 唱片有内容；封面在轮播中可区分。
2. **交互**：町景与沉浸页已移除，不再验收。
3. **内容**：至少三页不再是「表格 + 皮肤」；首屏结构与其余房间可区分；功能与改前一致。
4. **工程**：`verify` 全绿；单测覆盖 room-program；无新增依赖。
5. **设计自评**：按 `15` 的 100 分尺重评，目标 ≥ 95；未达必须写「未达 95（xx 分）：草稿，仅用于确认方向」。

## F. 风险与边界

- **fixture 变重**：22050Hz × 三分钟 ≈ 8MB/首，脚本现场生成不落盘，不要提交。
- **编排过度**：`RoomProgram` 只抽一层，不建实体表、不做跨房间编排引擎。
