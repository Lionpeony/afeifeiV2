## 01 · 机制总览

```
usePref("palette","default")  →  <html data-palette="…">
                                    │
```

## 03 · 暗色覆盖规则

暗色包块**必须**用多一档的选择器，且放在亮色块之后：

```css
:root[data-palette="gbc"]{ … }                          /* 亮色 */
:root[data-theme="dark"][data-palette="gbc"]{ … }       /* 暗色：权重 (0,3,0) > (0,2,0) */
```

不做这个的话，`data-theme="dark"` 基座块（同权重写在前面）会被包亮色块覆盖，熄灯失效。

## 11 · 事故复盘：整窗布局塌成一条竖列（2026-11-19）

现象：打开播放器，侧栏/顶栏/页面/底栏全部竖着堆成一列，顶栏掉到底部。截图 image-42。

根因：**对比度回炉批量替换时用了 PowerShell Set-Content -Encoding UTF8，给 8 个 css（base/account/compat/lyrics/player/shell/studio/v4）写进了 UTF-8 BOM**。build.mjs 把多个 css 拼进单一 dist/renderer/app.css，**文件中部的 U+FEFF 不是合法 CSS 字符**，解析器把它和后面第一个规则（shell.css 的 .app{display:grid}）一起吞掉 → .app 退化 block 流 → 整窗塌列。BOM 在文件开头会被忽略，所以单独打开文件看不出问题；
pm run verify 的 lint 也不查 BOM。

修复：全仓剥 BOM（src/docs/scripts），重建后 CDP 实测 .app 恢复 display:grid、列 200px/1fr 正确落位。

预防：①批量改文件一律用编辑工具/WriteAllBytes 无 BOM 写入，禁 Set-Content -Encoding UTF8（PS5.1 默认带 BOM）；②verify.mjs 可加「css 首三字节 ≠ EF BB BF」检查（待办）。

诊断工具沉淀：scripts/_diag-open.mjs——复制真实 userData 起真 app，CDP 截首屏 + 打 DOM/computed style，本次就是靠它定位的（注意：opencode shell 带 ELECTRON_RUN_AS_NODE=1，跑前要删掉，否则 electron.exe 变纯 node 必崩；node16 无 fetch/WebSocket，用 electron 自带 node v20 跑）。

## 33 · 扫码登录「刷新二维码」失效修复（2026-11-21）
现象：二维码过期（网易云 code 800）后出现「刷新二维码」链接，点下去界面停在「正在获取二维码…」，旧码仍在、不再轮询，也没有新会话——只能关掉浮层重开。

- **顺带加固**：音源接口无超时会永久吊住（僵尸态的另一个入口），新增 `withTimeout`——`start` 20s、`poll` 10s，超时按失败处理并置 `stopped`，保证「刷新」永远有出路；`scan__qrfoot` 改为直接显示 `qrNote`（超时/过期各自说自己的话，不再一律「码失效了」）。

### 33.1 · 真正让二维码出不来的是 ENOENT（2026-11-21 补）
- **现象（截图）**：控制台 `Error invoking remote method 'netease:call': ENOENT ... \AppData\Local\Temp\anonymous_token`，二维码始终是「正在获取二维码…」。
- **根因**：上游 `NeteaseCloudMusicApi@4.32` 的 `util/request.js` 在**模块加载期**同步 `fs.readFileSync(os.tmpdir()/anonymous_token)`，没有 existsSync 保护。文件不在 → require 直接抛 ENOENT → 所有走 `callNcm` 的接口（扫码 key、榜单、搜索、播放地址）一起不可用。系统清临时目录、换机器、首次安装都会命中。
- **复现**：删掉 `%TEMP%\anonymous_token` → `require('util/request.js')` 抛 ENOENT；写入空文件后 require 通过，`login_qr_key` 实测 `status 200 / code 200` 并拿到 unikey。
- **修法**：`src/main/net/neteaseClient.ts` 模块加载时先 `ensureAnonymousToken()`——文件不存在就写一个**空占位**（`MUSIC_A` 只是未登录兜底 cookie，空值实测可正常走 weapi），已存在则绝不覆盖（真 token / 其他客户端生成的值保留）。
- 验证：tsc 0、lint PASS、build ok；`dist/main.js` 里 `ensureAnonymousToken()` 的调用位置在首个 `NeteaseCloudMusicApi/util/request.js` 引用之前（bundled 顺序 438505 < 439691）。

## 34 · 迷子·雨夜播放页雨丝「断线」修复（2026-11-21）
- **现象**：用户截图圈出播放页中段，雨丝线一段一段断开（红框处最明显），观感像渲染坏了。
- **定位**：取真机截图后按行采样，暗线间距实测 74px（CP 1.2 下 89px），与 `.np::after` 第 4 层 `repeating-linear-gradient(97deg,…34px 35.5px…)` 的周期完全对上；注入 `display:none` 对比可排除其它层，关掉 `maigoRain` 动画后断线仍在 → 不是动画造成。
- **根因**：Chromium 对**斜角重复渐变**按块栅格化，发丝线（1.5px）在块缝处被截断，角度越接近垂直越明显。97° 正好是最差区间。
- **修法**（`player.css` mygo 亮/暗两段）：雨丝改成**轴向** `repeating-linear-gradient(90deg,…)` + 在 `.np::after` 上整层 `transform:rotate(-7deg)`，倾斜交给 transform，栅格化始终轴对齐，线就连续了。周期取 **84px**，与 `maigoRain` 的横向位移 -84px 对齐 → 动画每轮刚好错一格，换周期无跳变。`inset` 从 0 放大到 -12%，补上旋转后露出的四角。
- 同型缺陷一并修：`eggs.css` `.packfx__rain`（78° 重复渐变）→ 改 90° + `rotate(-12deg)`，周期 68→88 对齐 `rainFall` 的 -88px。
- 验证：build ok、lint PASS（43 源文件 / 11 规则）、node --test 63/2（基线环境项）；真机重拍 `assets/diag/实看-播放页-mygo.png`，行采样周期 85px、线通篇不断。
- 关联未做：队列白卡/粉贴条/封面占位粉紫仍是全局色，属「换包材质收尾」，等用户确认后再动。

## 35 · 播放页三处材质收尾：队列卡/贴纸/占位封面随包（2026-11-21）
