> 与 `00` 冲突时**以 `00` 为准**；本文只管"做什么产品、凭什么不一样"，工程缺口仍看 `11`。

## 2. 一句话定位（先定这个，再谈功能）

> **阿飞飞不是"又一个播放器"，是一个把「听歌这件事」当成**一场有节目单的演出**的播放器。**
> 别的播放器给你"列表 + 进度条"，我们给你**节目单、台词本、票根、唱针、以及每一首歌为什么被选中**。

这句话决定了后面所有取舍：凡是**不能强化"演出感"和"可解释性"**的功能，一律排在后面（哪怕主流播放器都有）。

### 2.1 UI 与效果：放进产品方向，但不是当"第 7 个亮点"

**结论先说**：UI 设计和视觉效果**必须进产品方向**（否则"看不见优点"这件事永远不会被解决），但它们的身份是**产品语言（language）与载体（carrier）**，不是并列的第 7 个功能亮点。

理由三条：

1. **视觉是现在唯一已经成立的差异**。打开就能看出不是 SPlayer、不是 YesPlayMusic——但这个差异**没有被写成规则**，所以只活在截图里，讲不出来、也守不住（改三次就会走形）。
2. **视觉单独不构成壁垒**。换一套 CSS 就能抄；它必须**承载某个机制**才值钱——票根承载"会话账本"、活字格承载"剧本结构"、时间轴刻度承载"时间机"。
3. **视觉会跟功能抢工期**。上一版砍了 6 项工程省 6 天，如果视觉再无限加，砍的就白砍了。所以要分类：哪些是语言（不许删）、哪些是装饰（可降级）。

#### 产品语言七条硬规则（能验收，不是形容词）

| # | 规则 | 怎么验 |
|---|---|---|
| 1 | **朱砂只标"正在发生"**：正在播放、当前歌词、进度头、主操作。其余一律墨色 | grep `var(--accent)` 的消费点，每处必须能答"它在发生什么"；答不出的改墨 |
| 2 | **零圆角，只有三个例外**：胶囊 999 / 黑胶盘面 50% / `--stage-cover-radius` 场景位 | lint 已有"圆角收直角"纪律，补一条例外白名单 |
| 3 | **发丝线永远 1px**：分区 28% 墨、行分隔 12% 墨，永不加粗 | 截图放大看；CSS 里 `border-width` 只许 1px 或 0 |
| 4 | **阴影只给浮层**（面板/弹窗/票根），正文区零阴影 | grep `box-shadow`，正文类名里出现即违规 |
| 5 | **每页唯一一处大字**：40px 及以上只允许一处（标题或统计数字） | 截图；`font-size ≥ 40px` 的选择器每页 ≤1 |
| 6 | **等宽字体只用于数字、编号、英文小标**；印刷感靠字距不靠字号 | 评审时逐处看：中文正文用等宽 = 违规 |
| 7 | **动效只写 transform / opacity**，时长 180–400ms，`fx-0` 必须好看 | lint 规则 4 + 现有 `fx-0` 截图 |

> 这七条的作用不是"更好看"，而是**让别人抄不走时能说清抄的不是配色，是规矩**。`docs/08 §4` 管画布与预设参数、`docs/09` 管排版还原，**本文只回答"为什么这套语言属于产品方向"**，细则不回写。

#### 亮点 × 视觉载体（没有这个视觉，亮点就变成普通功能）

| 亮点 | 视觉载体 | 抽掉载体后会变成 |
|---|---|---|
| L2 播放解释器 | 票根边注式的小字（mono + 朱砂短线） | 一个带 tooltip 的列表 |
| L3 剧本结构 | 活字格 + 台词本的三列铅字 | 一个彩色进度条 |
| L1 唱针时间机 | 时间轴上的印刷刻度与"当日增删"小字 | 一个带日期的下拉框 |
| L5 手动交叉台 | 双线仪表（A 降 B 升的等功率曲线） | 两个滑块 |
| L6 会话票根 | 纸面票根（墨条、编号、撕口） | 一张分享截图 |
| L4 作品层 | 右侧并置的源标（`网易云 · QQ · 本地`，mono 小字） | 一个"可用源"下拉 |

#### 效果清单：哪些是语言，哪些只是装饰

| 类别 | 内容 | 处置 |
|---|---|---|
| **语言（保留）** | 纸纹、发丝线、活字格、台词本、细线 seek + 朱砂头、票根、唱针/黑胶 | 不许删，删了产品语言就断 |
| **装饰（可降级）** | 频谱柱、封面视差、取色光晕、旋转封面、cinematic 模糊壁纸 | 掉帧时**先砍这些**（自动降档顺序：频谱 → 视差 → 色晕），`fx-0` 下全部关掉 |
| **明确不加** | 粒子、shader 歌词、3D 封面、彩色热力图 | `08 §7.4` 黑名单 |

这条分类直接服务 `11 §3.3` 的自动降档：**降档只准降装饰，语言层一个像素都不许动**（否则一卡就"变回别的播放器"）。

### 2.2 第一眼：三秒定生死

> 用户原话：**"我想要的是，第一眼就惊艳的播放器。"**
> 这句话把权重从"机制独有"推到"第一印象"。必须先承认一件事：

**纸墨语言给人"高级"，不给人"惊艳"。** 惊艳来自三个物理量：**大图、强对比、动势**。现在的首屏是"一张纸 + 细线 + 小字 + 大留白"——耐看，但第一眼不会让人"哇"。更糟的是：**最惊艳的东西（活字格、黑胶、票根）全藏在 console 点一下之后的播放页里**，第一眼根本看不到。

#### 现在的第一眼，逐帧是什么

| 时刻 | 实际发生 | 问题 |
|---|---|---|
| 0ms | 窗口出现，`#f3f1ea` 纸底 | 没有品牌落版，像"还没加载完" |
| ~900ms | 曲库恢复（21.7ms）+ 首屏渲染 | 封面异步请求，先出**灰块** |
| ~1200ms | 首页 hero 出来：288px 封面 + 文案 | 封面是 **160px 缩略图放大的**（`main/fs/cover.ts:14` `THUMB_SIZE=160`），在 288px 里就是**糊的** |
| 永远 | 播放页要**点 console 的 `.np`** 才进 | 产品最漂亮的一屏不在首屏动线上 |
| 无 | 中文标题走系统黑体（衬线自托管在 §10 被砍） | 唯一能"一眼印刷感"的字形没了 |

**结论**：现在的第一眼 = 一张好看的纸 + 一张糊图。**不惊艳，是"整洁"。**

#### 三秒脚本（启动到可用，每一帧都要设计）

| 时刻 | 该发生什么 | 实现要点 |
|---|---|---|
| 0 | 纯纸色 + 一枚朱砂句号（品牌落版，**绝不闪白、绝不 spinner**） | 首帧只画一个 12px 红点，0 请求 |
| 120ms | `afeifei.` 落版（rise 14px + blur 5→0，420ms） | 与 v11 稿的 `rise` 同一条曲线 |
| 240ms | **印刷空版**：细线 + 占位块出现（不是灰骨架） | 用 1px 发丝线画版式，不用 `skeleton` 动画 |
| 600ms | **封面糊→清**：`blur(12px)→0` + `scale(1.04)→1`，420ms | 最便宜的一招，效果最大 |
| 900ms | 首屏内容 stagger 落版（每行 40ms，最多 6 行） | 只对首屏做，别对全部列表做 |
| 1500ms | **取色渐进**：封面主色以 18% 从中心晕开（已有 `--stage-tint`） | 复用 OKLab 取色，不新增计算 |
| 3000ms | 静止、可交互 | 之后不再有动画 |

#### 五个 wow 点（按性价比排序）

| # | 效果 | 成本 | 为什么惊艳 |
|---|---|---|---|
| 1 | **封面糊→清** + **取色渐进** | 0.5 天 | 眼睛对"由虚到实"和"颜色漫上来"最敏感；两招都不需要新依赖 |
| 2 | **点封面 → 沉浸演出**（封面放大成壁纸、歌词浮起、控制条下沉，FLIP 过渡 520ms） | 2 天 | 这是"第一眼之后第二眼"的杀招：**用户点一下，界面整个换台** |
| 3 | **切歌黑场 120ms**（纸色遮罩一闪 + 新标题落版，不是渐隐） | 1 天 | 把"换歌"做成"换幕"，演出感来自**断点**而不是平滑 |
| 4 | **大字排版**：中文标题自托管一个衬线字重（子集化 ≈ 1.5–3MB），或退一步"超大字号 + 紧字距" | 1–2 天 | 印刷感 90% 来自字形；现在被系统黑体吃掉了 |
| 5 | **票根落下**（播完一首，票根从下方"撕"上来，纸边有撕口） | 1 天 | 闭环的收尾动作，最容易被截图传播 |

#### 六项"今天就该改"（半天内出效果）

1. **启动落地页**：不是首页，而是"上次离开的地方"——若上次在播，**直接进播放页**（沉浸态）。
2. **封面尺寸分级**：`THUMB_SIZE` 160 → 列表 40 / 播放页 360 / 首屏 640（正好落 `11 §3.13` 的第 2 条，从"优化项"升级为"必须项"）。
3. **删掉所有 spinner 与灰骨架**，换印刷空版（细线占位）。
4. **首屏加"糊→清"与"取色渐进"**（0.5 天，最高性价比）。
5. **入场编排统一到 9 页**：每页只在**首屏**做 stagger，列表滚动不做。
6. **中文标题调一档**：字重 600、字距 −0.02em、行高 1.05（先不换字体，等第 4 个 wow 决定）。

#### 需要推翻的三个旧决定

| 旧决定 | 出处 | 为什么推翻 |
|---|---|---|
| 封面只做 160px 缩略图 | `11 §3.13`、`main/fs/cover.ts:14` | 160 放大了就是糊的，**糊图毁掉一切排版** |
| **中文衬线自托管 = 不做** | 本文 §10（我自己砍的） | 当时的理由是"要重排 9 页"；但"第一眼惊艳"的核心就是字形，**该砍的是别的**（见 §6.1 已砍 6 项） |
| 启动默认落首页 | `ui/index.tsx` | 产品最漂亮的一屏不在动线上，等于**把招牌藏在后厨** |

#### 验收：3 秒盲测（不用"好看"这种词）

给 5 个没见过项目的人看**启动后 3 秒的截图**，问两个问题：

1. "这是听歌的软件吗？" —— 要 5/5 答对；
2. "想不想点一下？" —— 要 ≥4/5 答"想"。

**答不到就不算惊艳，改的是首屏，不是配色。**

### 2.3 视觉方向裁决：不要纸墨底，改成「暗房 · 底片光」

> 用户放权："为了突出惊艳，可以不要纸墨语言，用你觉得更好的也行。"
> 我的判断：**换底，不换骨。**

#### 先承认：纸墨与"惊艳"在物理层面相反

| 惊艳的机制 | 纸墨给的是什么 | 冲突 |
|---|---|---|
| **高对比**（暗底 + 亮点，屏幕有透光感） | 纸 #f3f1ea + 墨 #17150f = **软对比** | 亮底在大屏上显"平" |
| **纵深**（模糊背景 + 前景清晰 + 视差） | 平面印刷，无景深 | 没有空间 |
| **光**（封面取色当环境光） | 18% 淡淡的 `--stage-tint` | 几乎看不见 |
| **大**（图/字占屏 >50%） | 33–40px 标题 + 214px 相纸卡 | 尺寸克制 |

**纸墨的巅峰是"耐看"，而第一眼要的是"响"。** 而且"纸墨 + 印刷"这个方向在独立播放器里已经有人走（YesPlayMusic 的留白、Museeks 的极简），它不是空白区。

#### 但纸墨真正的资产不是"纸"，是**印刷纪律**

细线 1px、等宽字体只做数字、朱砂只标"正在发生"、零圆角、大留白、每页唯一大字——**这套纪律搬到暗底上，张力立刻翻倍**。所以：

> **换底不换骨：布局、组件、排版、动效纪律一个都不动，只换"底色与光"。**

#### 目标方向：「暗房 · 底片光」

| 层 | 值 | 说明 |
|---|---|---|
| 底 | `#0a0b0d`（比纯黑略暖） | 纯黑会显"塑料"，略暖才有胶片味 |
| 前景 | `#f3f1ea`（原来的纸色） | **把纸色从"底"变成"字"**——这是最省力的一招 |
| 次文字 | `rgba(243,241,234,0.55)` | 暗底上次文字要压到 55%，否则发灰 |
| 强调 | `#e0492f`（朱砂提亮一档） | 暗底上原来的 #d8341c 会发乌（夜间 token 已有先例） |
| 光 | **封面主色 40% 大面积晕染 + 20% 反光** | 现在只有 18%，要敢加；两三个色相就够，别做成彩虹 |
| 线 | `rgba(243,241,234,0.22)` / `0.10` | 比纸底的墨线更细更暗，才有"刻线"感 |
| 材质 | 只在浮层用**极轻的暗色玻璃**（1px 亮边 + 内阴影） | 不做大面积 `backdrop-filter`（性能） |

**效果差异一句话**：同一套排版，纸底像"唱片内页"，暗底像"剧场开演前的黑场"——后者才符合我们"一场演出"的定位。

#### 只做三件事，第一眼就换掉

1. **换 tokens**（`tokens.css` 结构层 + 场景层，约 20 个值）→ 9 页自动变暗，**零布局改动**；
2. **把 `--stage-tint` 从 18% 提到 40%**，并允许 2–3 个色相（主色 + 次色 + 高光），改成"环境光"而不是"淡染"；
3. **首屏加糊→清与光扩散**（§2.2 的第 1 个 wow）。

**成本 1.5–2 天**（改值 + 逐页对图 + 重拍 `docs/assets`），不是重做。

#### 保留 / 作废 / 反转

| 项 | 处置 |
|---|---|
| 9 页布局、rail、页头三件套、console、活字格、台词本 | **全保留**（一行不动） |
| 印刷纪律七条（`§2.1`） | **全保留**，只是"墨/纸"互换 |
| `docs/09` 排版还原规格 | 保留（它管尺寸与线，不管底色） |
| `docs/assets/*.png` 全部截图 | **作废，重拍**（纸底截图不能再当证据） |
| 默认主题 | **反转为暗房默认**，亮纸作为"白天模式"保留（现成的 `[data-theme]` 通道，改一下默认值） |
| 纸纹 | 暗底下 `multiply` 会全黑，改用 `soft-light`（`a317ed9` 已有正确配方，直接用） |

#### 为什么不是另外两个方向

| 备选 | 为什么不做 |
|---|---|
| **液态玻璃 / visionOS 风** | 大面积 `backdrop-filter` 掉帧，且 v2 明确去毛玻璃（旧仓 186 个 `!important` 就长在这上面）；一旦降档就崩成灰块 |
| **赛博霓虹 / 高饱和渐变** | 半年就过时，且与"票根/节目单"的叙事冲突；廉价感最难救 |

**我拍这个板，理由三条**：① 改动最小（只换值，不动 9 页）；② 与产品叙事一致（剧场黑场）；③ 性能最好（无大面积模糊）。

> 用户随后追加"可以全部重新设计，所有页，所有功能排版"——**施工图升到 [`13-全站重设计蓝图.md`](13-全站重设计蓝图.md)**（设计系统值表、逐页骨架、R0–R7 批次）。本文 §2.3 的裁决仍是方向依据，13 是它的落地图纸。

#### 验收：A/B 盲测

同一页面拍两张——纸底 vs 暗房——给 5 个人看，只问一句："哪张让你更想点一下？" 要 **≥4/5 选暗房**。选不出来，就说明光加得不够，不是方向错。

## 3. 六个候选亮点（两个真独有 + 三个半独有 + 一个传播件）

判断标准三条：① 依赖本仓已建成、别家没有的**结构资产**；② 一句话能说清；③ 3–4 天能出可验收雏形。

### 3.0 先老实分级：六个里真正"抄不走"的只有三个

上一版把六件都叫"只有我们能做"，这不诚实。按**别人要抄得先建什么**重排：

| 亮点 | 分级 | 别人抄走要先建什么 | 一句话（不含术语，说给朋友听） | 30 秒演示 |
|---|---|---|---|---|
| **L1 唱针时间机** | **半独有** | 索引改成"快照 + 增量日志"——**Mineradio 已经有**，所以它抄得走 | "我的播放器能回到三天前的曲库" | 拉时间轴 → 点 10/28 → 曲库变成那天的样子 → 回滚 |
| **L2 播放解释器** | **独有** | 推荐必须变成能复现的纯函数 + 有决策上下文；他们的推荐在**服务端**，想说也说不出来 | "它每放一首歌，都能告诉你为什么放这首" | 点队列里的 `？` → 看到"同专辑 / 红心 / 30 天没播" → 点「换一个理由」换歌 |
| **L3 剧本结构** | **半独有** | 要有 QRC/YRC 逐字时间轴——LX/SPlayer 有；我们的差异在**把它当结构用**（段落图 + 只听副歌） | "它把一首歌当成剧本，告诉你哪段是副歌" | 播一首带逐字歌词的歌 → 点「结构」→ 出现 5 个色块 → 点「只听副歌」 |
| **L4 作品层** | **独有** | 要有能力声明表 + 错误码 + 跨源取流，并把"作品"当成一等实体 | "搜一首歌只出一条，点开能看到哪几个平台有" | 搜《老人と海》→ 一条结果 → 右侧 `网易云·QQ·本地` → 点播自动选可用源 |
| **L5 手动交叉台** | **半独有** | 要双 audio + 等功率曲线——SPlayer 有；差异在**把参数变成操作** | "能像 DJ 一样手动把两首歌推着换过去" | 拖推子 → 实时听到 A 渐弱 B 渐强 → 头顶两条曲线反向 |
| **L6 会话票根** | **产品化差异** | 只要做分享卡片就行（Spotify 年度报告同思路）；独有只在视觉语言 | "听完一首歌，能生成一张像票根的卡片" | 点「存档」→ 出一张票 → 导出 PNG → 扫码/点链接能再播同一首 |

**结论**：真正抄不走的是 **L2（解释器）和 L4（作品层）**——它们依赖的是"决策可复现"和"作品只有一个真相"，这是 `00` 的 I2/I4 长出来的，不是功能长得出来的。L1/L3/L5 是**结构优势下的快赢**（别人抄要走一遍改造），L6 是**传播件**（不构成壁垒，但能让优点被看见）。

### 3.1 六个亮点其实是一条线，不是六个散点

这是上一版最大的问题：六个功能并列，用户记不住。它们应该组成**一场演出的一生**：

```
        ┌─ L2 解释器：为什么是这首 ─┐
选曲 ───┤                            ├─→ 听（L3 剧本结构 / L5 交叉台）
        └─ L4 作品层：这首到底是哪首 ┘         │
                                                ↓
                          回看（L1 时间机：曲库怎么变成今天这样）
                                                │
                                                ↓
                          留下（L6 票根：这一次听歌的凭证）
```

**一句话主线**：**"它知道放什么（解释）、知道放的是哪一版（作品）、知道怎么放（剧本/交叉）、记得住过去（时间机）、留得下凭证（票根）。"**

按这条线讲，优点不再是六个名词，而是**一个闭环**。任何一个单独做出来都只是"新功能"，连起来才是"这个播放器为什么存在"。

### L1 唱针时间机 · 曲库时间旅行 ★最亮

**用户看到什么**：曲库里一个「时光」按钮，拉一条时间轴，能看到"10 月 28 日：+312 首 / -4 首 / 改了 2 个专辑名"；点任意一天，整个曲库**回到那一刻的样子**（只读）；可以「把这一版存为快照」或「回滚到这里」。

**为什么我们能先做**（半独有：Mineradio 有同样的索引结构，但没把它给用户看）：曲库本来就是**快照 + 增量日志**（`domain/library/index-store.ts`，`COMPACT_THRESHOLD=200`），每一条 upsert/remove 都有记录。多数播放器直接覆盖（没有历史），少数上 SQLite（有历史但不敢给用户看）。我们只要把日志**留档而不只是压缩**，再把 `replay` 包一层时间参数——纯函数已经在手。

**判据**：给定一份日志，`replayAt(log, ts)` 的结果与"当时真实曲库"一致（用现有测试数据构造）；回滚后索引可被下一次扫描正常接续；日志保留上限 30 天/2 万条，超了按最旧丢。
**体量**：3 天（日志留档 1 + `replayAt` 纯函数 1 + UI 1）。
**风险**：日志体积。回退：只保留"每日首个状态 + 当日增量"，体积降一个量级。
**不做**：文件级回滚（磁盘上的 mp3 不动，只回滚索引）。

---

### L2 播放解释器 · 为什么是这首

**用户看到什么**：队列每一项右侧一个 `？`。点开是一行解释：
`因为你刚听完《老人と海》同专辑；红心；30 天没播过`
再点「换一个理由」→ 从同专辑里换一首（理由随之变化）。

**为什么只有我们能做**：推荐内核是 Ring 1 纯函数（`domain/recommend`，`dailyPicks/reasonOf` 已有雏形），决策可复现（日期种子 + LCG）。别家的推荐是服务端黑盒，**想说也说不出来**。我们的每一首歌的来路都是可计算的。

**判据**：`explain(trackId, ctx)` 返回非空理由且与 `dailyPicks` 的实际选择一致（同种子可复现）；无理由时诚实返回 `"曲库补充"` 而不是编；理由文案全部来自 `reasonOf` 的枚举，不散落。
**体量**：2 天（纯函数 1 + UI 1）。
**风险**：理由太机械。回退：理由只保留 4 类（红心/最近/同专辑/久未播），不做伪随机措辞。

---

### L3 剧本结构 · 把歌词变成剧本

**用户看到什么**：播放页的「台词本」升级成**结构图**：整首歌被切成 `前奏 / 主歌 A / 副歌 / 主歌 B / 副歌 / 桥段 / 尾奏`，每段一个色块 + 起止时间；点任意段直跳；「只听副歌」一键生成 60 秒的"精华队列"。

**为什么我们能先做**（半独有：LX/SPlayer 也有逐字轴，差异在"把它当结构用"）：QRC/YRC 的**逐字时间轴**已经解析进 `LyricDoc.words`（`capability/lyrics/parse.ts`），段落边界可以从"逐字密度 + 行间隔 + 重复行"聚类算出来，全部纯函数、可测。别家的歌词只用来滚动，没有人把它当**结构数据**用。

**判据**：对 20 首带 QRC 的歌跑 `segments(doc)`，段落数在 4–10 之间、副歌（重复率最高的段）识别正确（人工抽检 5 首）；无逐字数据时降级为"按行间隔切"并标注 `low-confidence`；「只听副歌」生成的队列不改原队列（插队语义，见 `11 §3.7`）。
**体量**：4 天（聚类 2 + UI 1 + 精华队列 1）。
**风险**：聚类不准。回退：只做"按时间等分 5 段"的兜底，并明说"这是估算"。

---

### L4 作品层 · 一首歌只有一个身份

**用户看到什么**：搜索结果里《老人と海》出现一次，右侧小字 `网易云 · QQ · 本地`；点播放时按"音质最好且可用"取流；下载时只下一次；队列里不会出现三个同名条目。

**为什么只有我们能做**：我们有**能力声明表 + 12 个错误码 + 跨源 fallback**（`11 §3.8`），可以定义"作品"这一层：`作品 = normalize(标题) + normalize(艺人) + 时长±2s`。别家按源分列（QQ 一栏、网易云一栏），用户看到的是**三份数据**；我们能把它们收成**一个真相**——这正是 `00` 的 I2 哲学在数据层的延伸。

**判据**：同一首歌在两家源的合并键相同、不同版本（时长差 >2s）不误合；合并后仍能点开"有哪些源"；离线时本地那一条永远可用。
**体量**：4 天（归并纯函数 1.5 + 源标记 UI 1 + 取流 fallback 1.5）。
**风险**：误合（同名不同曲）。回退：宁可不合并——**只有时长差 ≤2s 且标题完全一致才合**。

---

### L5 手动交叉台 · 双路 A/B

**用户看到什么**：一个双通道推子，左 A 右 B，拖动时**实时听**两首歌交叉；上方画着两条等功率能量曲线（A 降、B 升）；松手停在任意比例，或点「一键完成过渡」。

**为什么我们能先做**（半独有：SPlayer 有双路与曲线，差异在"把参数变成操作"）：图里本来就有两条 `GainNode`（`graph.ts` 的 `fadeA/fadeB`），crossfade 也是等功率曲线（`5d934e7`）——现在只差**把曲线交给用户的手**。别家的 crossfade 是参数（3 秒/6 秒），我们是**乐器**。

**判据**：推子位置与两条曲线数值一一对应（同一份 `crossfadeCurves()` 纯函数）；推到底自动 `finalize` 交换主备；`fx-0` 档位下推子仍可用但无动画。
**体量**：3 天（曲线复用 0.5 + 推子 UI 1 + 交换语义 1.5）。
**风险**：拖到一半暂停的边界。回退：暂停即冻结两路增益（不再走曲线）。

---

### L6 会话票根 · 一次播放 = 一张票

**用户看到什么**：一次播放结束（或手动点「存档」），生成一张**纸面票根**：曲名、艺人、播放时长、起止时刻、封面取色的色块、编号 `NO. 030`、底部一行 `afeifei://play?source=…&id=…`。可导出 PNG。

**我们凭什么做得好**（产品化差异，不是壁垒）：视觉资产（纸墨/朱砂/发丝线/票根语言）是本仓独有的；`afeifei://` scheme 已经能唤起播放；封面取色（OKLab）已有；导出 PNG 用 canvas 不需要新依赖。别家做"分享"是截图，我们做的是**可回放的票**。

**判据**：票据上的时长/时刻来自会话账本（`11 §5.1`）真实数据，拿不到就留 `—`；导出的 PNG 尺寸固定 1080×1350；票根里的 scheme 在本机唤起后能播同一首。
**体量**：2.5 天。
**风险**：中文字体在 canvas 里的差异。回退：用系统字体族，不嵌字体（票根是短文本）。

### 三个备选（先不做，给触发条件）

| 备选 | 说明 | 什么时候做 |
|---|---|---|
| **断点续听** | 每首歌记住听到的第几秒（不只是"上次会话"），KV 存 5000 条压缩位置表 | 若用户抱怨"每次都得从头"，1 天就能加（其实**并入 L1 批次顺手做**更省） |

| **命令宏** | 录制"切页→搜索→播放→调音量"序列，绑热键/托盘 | 命令面板命令数 >15 条再谈（现在只有播放/搜索两类，录不出东西） |

## 5. 流程走查：真 bug 与不合理（都有证据）

`11` 只写"缺什么功能"，没写"现有功能哪里别扭"。这一节补上，按"用户会不会立刻骂"分级。

### P0（立刻能撞上）

| # | 问题 | 证据 | 后果 | 修法 |
|---|---|---|---|---|
| 1 | **在线播放不进「最近播放」** | `views/recent/index.tsx:49-53`：`byId.get(entry.trackId)` 查不到就 `lost += 1`，只显示"n 条不在曲库" | 听了一晚上在线歌，最近播放是空的 | history 改存 `{trackId, title, sourceId?, at}`（带最小展示信息）；本地仍按 id 关联曲库 |
| 2 | **持久化里存着会过期的直链** | `kernel/persist.ts:13` 存的是 `trackId`；在线播放时 `player.trackId` 就是 CDN 直链，而 `remote` 明确不持久化（`contracts/index.ts:43`）。队列里其实**没有**在线曲目——`player/play` 只改 player，`queue.items` 里查不到这个 URL（`store.ts:103`） | 重启后恢复出一首点了就报错、且没有歌词身份的歌 | persist 存 `{sourceId, songId}` 身份而非 URL，启动时重新 resolve，失败回落"未在播放"（不报错、不弹窗）。**注意**：`player.trackId` 在 engine / history / likes 多处被当字符串用，加身份要一层映射，**1.5 天的原始估算偏乐观，实际按 2.5 天算** |
| 3 | **两套键：队列存 `path`，曲库 id 是规范化小写** | `ui/index.tsx:163` `onPlay` 用 `r.path` 建队列；`schema.ts` `trackIdOf` 是小写 | 大小写/斜杠不同就"找不到这首歌"，我已在播放页打补丁（同时建两个键），**底层没修** | 队列统一存 `track.id`；`path` 只在交给 media 端口时用 |
| 4 | **shuffle 下"第 N 首"是错的** | 播放页 `st-src` 与票据用 `queue.cursor + 1`，而 shuffle 的播放顺序由 `orderOf` 现算 | 随机播放时编号跳来跳去、与实际不符 | 显示 `positionOf(order, cursor) + 1`；或干脆显示"随机中"不显示序号 |

## 6. 新的施工顺序（亮点优先，工程穿插）

```
L0.5 第一眼：**换底（暗房·底片光）** + 启动落播放页
     + 封面尺寸分级 + 糊→清 + 取色 40% + 衬线字重   3.5 天  ← 第一周就要"哇"
L0   流程修复（P0 四条）                          2.5 天  ← 让现有功能不别扭
L1   手感包：拖放导入 + 导入文件 + 正在播放高亮
     + 右键菜单 + 断点续听                        3 天    ← 第二周能感到"顺手了"
L2   播放解释器                                   2 天    ← 第一件"只有我们有"，第 3 周
L3   唱针时间机                                   3 天    ← 半独有，但故事最好讲
L4   剧本结构                                     4 天    ← 视觉最有辨识度
L5   作品层                                       4 天    ← 真独有，也最重
L6   手动交叉台                                   3 天    ← 听觉上的独有
L7   会话票根                                     2.5 天  ← 传播性最强
L8   主流长尾（速度/睡眠/静音/通知/多选/预设/输出设备） 5 天
L9   工程欠账（`11` 砍完剩 27.5 天：托盘/音质/歌词/统计…） 穿插着做
```

**总计 60 天**（第一眼 3.5 + 修复 2.5 + 亮点 26.5 + 工程 27.5）。

**三周可见成果 = L0.5 + L0 + L1 + L2**：第一眼"哇"、不别扭、顺手，并且第一次能对别人说"它每放一首歌，都能告诉你为什么"。

**一条纪律**：L2–L7 每一件都必须**先能跑判据再加 UI**（纯函数在 Ring 1，UI 只做消费者）——否则六个亮点会变成六个半成品。

### 6.1 砍掉什么（加亮点的前提是减工程量）

上一版最大的漏洞：只加不减，总工时从 28 天涨到 33.5 + 26 = 59.5 天，"亮点"变成"加班"。下面六项**降级或永久砍**，省约 6 天，且不影响主线：

| 原项（`11`） | 处置 | 省 | 理由 |
|---|---|---|---|
| 听歌统计的 **365 天热力图** | 降级为「本周 / 本月」两个数字 + 艺人 top5 | −2 天 | 热力图好看但没人天天看；先证明"有人在看统计"再加 |
| **主题包 v1.1 元信息**（name/author/version） | 砍 | −0.5 天 | 现在只有自己用，没有分享场景 |
| **目录监控**（`fs.watch`） | **永久砍** | −1 天 | Windows 上 `fs.watch` 递归不稳、触发风暴；扫描按钮已能覆盖 |
| **搜索倒排索引** | **永不主动做** | — | 触发条件已写死（2 万首 / 50ms），不到点不碰 |
| **多源健康度熔断**（连续 3 次 + 冷却 5 分钟） | 降级为「失败一次即跳过该源，不冷却」 | −1 天 | 两家源而已，熔断是三家以上才划算的复杂度 |
| **输出设备选择**（`setSinkId`） | 移到 L8 长尾 | −1 天 | 少数人用；主线不需要它 |

**净效果**：工程侧 33.5 → **27.5 天**，亮点侧 26 天，流程修复 2.5 天（P0-2 修正后），总计约 **56 天**，但**前 5 周就能演示三件**（见 6.2）。

### 6.2 演示节奏（每两周必须能拿出来看）

产品文档和工程文档的区别只有一个：**有没有"什么时候能给用户看"**。

| 周 | 交付 | 演示时说的那一句 |
|---|---|---|
| **第 1–2 周** | **L0.5 第一眼（换暗房底）** + L0 流程修复 | **"打开第一秒：黑场里封面从虚到实，颜色自己漫上来。"** + "在线听的歌也会进最近播放。" |
| 第 3 周 | L1 手感包（拖放/导入/高亮/右键/断点续听） | "把 mp3 拖进来就能听，曲库里一眼看到在播哪首。" |
| **第 3 周** | **L2 播放解释器** | **"它每放一首，都能告诉你为什么。"** ← 第一次"只有我们有" |

**规矩**：每次演示只讲**一句话 + 30 秒操作**（就是 §3.0 那张表里的两列）。讲不完，说明这件还没做完。

### 为什么最终是 95，比上一版低 1 分

上一版 96 是**虚高的**：它把六件都叫"只有我们能做"（其中三件 Mineradio/LX/SPlayer 已经有底座），也没回答"总工时涨到 59.5 天怎么办"。
本轮把权重整个挪向"第一眼"（10 → 25，从机制/主流/流程各挪 5 分），并新增 §2.2 的三秒脚本与盲测法。**在同一把尺子下：初版 91 → 本轮 95。**

一句话解释用户的困惑：**"看得到不一样，说不清好在哪"——因为第一眼只有 9/25，做出来的不够响；机制只有 2/15，没做出来的当然说不清。**

拆开之后有一句话能解释用户的困惑：**28 分的辨识度里，观感占 8、机制占 20（纸面）。也就是说"看得到不一样，说不清好在哪"——因为不一样的那部分本来就没做出来。**

宁可要一份 95 分的真话，不要一份 96 分的自我表扬。

### 仍扣的 5 分（如实写）

1. **六个亮点都是纸面**：没有一行代码；L3 的段落聚类、L4 的归并键都还没在真实数据上验过。
2. **"主流普遍性"是归纳**（E2），不是逐家统计。
3. **流程走查不完整**：只走了播放/队列/曲库/设置四条主路径，下载、登录、迷你窗的窄路径没逐一走。

5. **L2 的"独有"有一个前提没验证**：如果将来接了"平台推荐接口"，理由就变成平台给的，独有性会打折——所以 L2 的价值绑在"我们自己算"这条路上。

## 8. 边界

1. 产品定位以本文 §2 为准；**架构与不变式仍以 `00` 为准**，任何亮点不许为了"看起来炫"破坏 I1–I5（例：L5 的推子写的是 `GainNode` 的 `gain`，不是新开 `AudioContext`）。
2. **UI 的三层归属不许混**：本文 §2.1 回答"这套视觉为什么属于产品方向"（语言与规则）；画布/预设参数归 `08 §4`；旧仓排版还原规格归 `09`。要改细则改 08/09，**不许在本文里写像素值**。
3. `11` 从"优化总纲"降级为**工程缺口清单**（托盘/音质/歌词/统计/缓存等），与本文不冲突：本文管"做什么产品"，`11` 管"工程还欠什么"。
4. 每完成一件亮点，回写本文的 ✅ 与 `docs/03`；**状态列不许凭印象改**。
5. 六个亮点全部是"纯函数先行、UI 只做消费者"，这是它们能被验收的唯一原因——不许先画 UI 再补逻辑。
