# 18 · 播放页功能清单

> 2026-11-03。从 `design/four-more.html`、`design/c1-blueprint.html`、`design/v2/a2.html`、`design/v2/b2.html` 的实际代码里逐项数出来。
> **六套是同一份功能的不同视觉实现**——功能集相同，主角机制不同。落地时这一份清单是验收表。

---

## 一、基础层（六套共用，全部要有）

### 1.1 曲目身份
| 字段 | 说明 | 六套呈现位置 |
|---|---|---|
| 曲名 | 主标题 | A 翻牌逐字 / B 大字 / D 巨字 / C1 标题栏 / a2 田字格区外 |
| 艺人 | 必带 | 副信息行 |
| 专辑 | 可选 | 副信息行（B 特别版式） |
| 时长 | 总时长 | 底部大钟 / 频率旁 |
| 码率·采样率 | FLAC 1411 / 44.1kHz | 技术行 |
| 来源 | 网易云 / QQ / 本地 | 作品层标记（**待做，见 §4**） |

### 1.2 播放控制
- 播放 / 暂停（一个状态一个表现：暂停时盘停转、呼吸停）
- 上一首 / 下一首
- 进度拖动（点击 + 拖拽，实时 seek）
- 音量 / 静音
- 播放模式（顺序 / 单曲 / 随机）—— **待做**
- 收藏 / 喜欢（红心）—— **待做**

### 1.3 时间三件
- 当前时间 `01:44`（等宽数字）
- 总时长 `05:21`
- **剩余时间** `03:36`（六套里 B/A/D 已有，C/C1/a2/b2 待统一）

### 1.4 歌词
- 当前句（第二视觉，字号 ≥ 24px）
- 下一句（次级，14–16px）
- 上一句（**C1/a2 有，B/D 待补**）
- 逐字或逐行跟随（**依赖逐字时间轴**）
- 点击歌词跳句（**待做**）

### 1.5 段落（结构）
- 当前段落名（副歌 / 主歌 A …）
- 段落时间区间 `01:18–02:20`
- 段落可视化（各套形态不同，见 §2）
- 点击段落跳转（**待做**）
- 下一段预告 `NEXT VERSE B 02:20`（C1 已有）

### 1.6 队列
- 接下来 N 首（3 首）
- 可点播放（**待做**）
- 队列总数 / 空队列状态（**待做**）
- 当前正在播的那首在队列中的高亮

### 1.7 五种状态（缺一个就扣 2 分）
| 状态 | 该显示什么 |
|---|---|
| 正在播放 | 正常 + chrome 高亮 |
| 暂停 | 转的东西全停 |
| 加载中 | 扫描线 / 骨架 |
| 无歌词 | 「纯音乐 · 这首歌没有歌词」 |
| 无封面 | 刻纹底 / 素色底降级 |

### 1.8 键盘与鼠标
| 键 | 动作 |
|---|---|
| 空格 | 播放 / 暂停 |
| ← / → | 上一首 / 下一首 |
| ↑ / ↓ | 音量 |
| Esc | 从沉浸态退回普通播放页 |
| 点击进度条 / 段落条 / 刻度尺 | 跳转 |

### 1.9 三种窗口
- normal（主窗口）
- immersive（沉浸态，隐藏导航与页头）
- compact（窄窗 / 小窗，**降级规则**）

## 二、六套的主角机制（各套独有，这是"风格"的来源）

| 套 | 主角 | 承载的功能 |
|---|---|---|
| **A 翻牌时刻表** | 曲名逐字翻牌 + 经停站列表 + **当前站三行大字** | 歌=车次、段落=经停站、当前站=现在停在哪 |
| **B 调谐收音机** | 频率刻度带 + 指针 + 频段条 + 旋钮 | 曲目=电台、频率=进度、频段=段落、旋钮=手动调谐 |
| **C 光谱带** | 已播点亮的光谱 + 指针 + 段落条 | 已播=被照亮的部分、波长刻度=第三层 |
| **D 叠印海报** | 封面出血 + 220px 巨字 + **双版套印** | 巨字跨过图心、套印偏=印刷没对准 |
| **C1 蓝图** | 俯视工程图 + **切割头** + 尺寸标注 | 进度=切割位置、段落=刻度尺、标题栏=图纸惯例 |
| **a2 活字帖** | 田字格逐字 + 台词本 3×12 + 票根 + 相纸 | 活字=逐字、台词本=可点跳句、票根=场次 |
| **b2 刻纹现场** | 黑盘 + 唱臂 + 封套 + 描边水印 + HUD | 刻纹=播放的本质、封套=实物 |

## 三、产品级独有机制（别家没有，是这六个播放器真正的差异）

| 编号 | 机制 | 落点 | 状态 |
|---|---|---|---|
| **L1** | **结构**：段落聚类（真实逐字数据算出来的） | 所有套的段落可视化 | 已有 |
| **L2** | **解释器**：为什么是这首（可重掷理由） | 首页 / 播放页副信息 | 已有（首页） |
| **L3** | **只听副歌**：把结构变成队列生成器 | 段落条右键 / 长按 | **待做** |
| **L4** | **作品层**：一首歌只有一个真相 + 多源并置 | 在线页 + 播放页来源标记 | 已有（在线页） |
| **L5** | **唱针时间机**：回到某一天的曲库 | 最近页 | 已有 |
| **L6** | **会话票根**：听完出一张可回放的票 | 报告页 | 已有 |

## 五、按"落地优先"排的功能补齐顺序

| 批次 | 功能 | 落点 | 为什么先做 |
|---|---|---|---|
| **P0** | 音量 + 播放模式 + 红心 | 所有套 | 三件是"播放器"的最低配置，缺了不像播放器 |
| **P0** | 队列可点 + 歌词点击跳句 | 所有套 | 用户 100% 会点的两个地方 |
| **P1** | 来源标记（作品层 L4） | 所有套 | 这是我们的差异化，不能只有在线页有 |
| **P1** | 剩余时间 + 上一句 + 下一段预告 统一 | C / D / C1 / a2 / b2 | 补齐后六套的信息层数一致（都 ≥8 层） |
| **P1** | 空队列 / 无歌词 / 无封面 三态统一 | 六套 | 这三态是"最后一条歌"和"纯音乐"的日常场景 |
| **P2** | 紧凑窗口降级规则 | 六套 | 三窗产品必须有 |
| **P2** | 只听副歌（L3） | 段落条交互 | 这是结构数据的杀手级用法 |
| **P3** | 逐字跟随 + 歌词高亮 | 全部 | 需要逐字时间轴数据，前置依赖在 `11` |

## 六、这套清单怎么用

1. **设计验收**：新出一套播放页，对着 §1 打勾，缺一项扣 2 分
2. **开发验收**：§4 矩阵逐格转成任务，P0/P1 先行
3. **文案来源**：所有状态文案（无歌词 / 空队列 / 加载中）从 §1.7 直接抄，不要另编
4. **换样式不影响功能**：任何一套的 §1 缺失项，都是**功能缺失**，不是"风格差异"
