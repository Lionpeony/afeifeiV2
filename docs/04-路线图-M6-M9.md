## M6 · 收编欠账（体量：1 周）

**目标**：三段里程碑的"遗留"清零，M3 的最后一块真缺口（QQ 播放地址）补上。

**顺序**

1. **QQ 登录 + 播放地址**（3 天，M6 的主体）

   - `main/net/qqClient.ts` 扩 `login` / `loginPoll`；cookie 走 Electron session（同网易云，零 CookieJar）
   - vkey 接口在登录态下复测（M3 实测匿名全 403/40000，登录态未测过）
   - **打通后**：`canGetUrl: true`、`traits.qualities` 复核、在线 scheme 的 `source=qq` 分支接上（`03` M5 遗留）
2. **M4 表现欠账**（1 天）：电影感封面视差（±8px，阻尼 0.12，`transform` only）、纸面剧场噪点（SVG feTurbulence data-uri，替代径向渐变近似）、四套预设截图入 `docs/assets/`
3. **沙箱硬化**（1 天）：`host.cache` 落 KV（`cache/<sha1(key)>.json`，TTL 沿用）、内存上限评估（utilityProcess 崩溃频率观测，够用则记"不设硬限"的理由进 00）
4. **lint 第 7 条固化**（半天）：z-index 全集校验 + `!important` 计数（跳过注释）——按 `gate:` 协议单独提交，写清原 6 条 → 7 条
5. **数据备份**（半天）：`data/` 目录一键导出/导入（zip 不引入依赖，用目录复制），覆盖曲库/歌单/收藏/KV

## M7 · 下载与离线（体量：1.5–2 周）

**目标**：在线曲目可下载、可离线播放。00 §17 #11 的解锁条件已满足（播放体验已由 M1–M5 证明）。

**设计约束（先立规矩）**

- **下载是业务**（`domain/download/`）：队列、并发、重试、状态机全在渲染层；`main/fs/` 只提供 `fetchToFile(url, path, rangeStart)`——系统调用与业务继续分离（00 §2.1）
- **I2**：下载状态进 `AppState.download`（单写者 dispatch），UI 只读投影 + 发 intent
- **磁盘有预算**（I5）：下载目录上限沿用 §6.3 的 LRU 思路，默认 2GB，超限按"最旧先删"且正在下载的除外
- **断点续传**：Range 头 + `.part` 文件 + 完成后 rename 原子落盘
- **不入库的文件不播**：下载完成 → 触发单文件扫描（复用 M2 的 `indexFile`）→ 身份进曲库，播放走 appmedia（**本地播放链路零新代码**）

**顺序**

1. `main/fs/fetchToFile.ts`：Range 续传 + 进度回调 + 原子写（1 天）
2. `domain/download/`：队列纯函数（并发 ≤2、重试 3 次退避、取消）+ 测试（1 天）
3. store：`download` 域 + intents（`download/add`、`download/pause`、`download/cancel`）（半天）
4. `projection/download.ts`：进度/速度/剩余视图模型（半天）
5. UI：在线行内下载按钮（能力驱动：`canGetUrl` 为 true 才渲染）+ 下载管理页（1 天）
6. 磁盘配额：写入前检查上限，超限按序淘汰（1 天）
7. 下载完成 → `indexFile` 入库 → 曲库可见（半天）
8. 冒烟：下载 → 断点 → 完成 → 入库 → 播放全链路（1 天）

**今天不写**：P2P、加密缓存、 lyric 离线包、按歌手批量下载。

**判据**

- [ ] 500MB 文件中断 3 次，续传后校验大小与 mtime
- [ ] 并发 2 队列：第三个任务排队，p95 滚动帧率不受影响（perf 回归）
- [ ] 超配额：下载被拒且文案人话，不是静默失败
- [ ] 下载的歌曲杀进程重启后仍在曲库、可播
- [ ] 单测 ≥ 15 项（队列纯函数为主）

**常见走偏**

| 走偏 | 修 |
|---|---|
| 下载进度每毫秒进 store | 进度走投影节流，store 只记状态机转移 |
| 直接把 CDN url 写 `<audio>` 播 | 下载与播放同源：完成后走曲库，不做"边下边播" |
| 淘汰策略现场发挥 | 上限与顺序写死进 00 §6.3 的表格（要改先改 00） |

## M8 · 分发与数据安全（体量：1 周）

**目标**：能安全地装、能安全地升级、坏了能救回来。

**顺序**

1. **更新检查（非静默，00 §17 #9 只禁静默安装）**（2 天）
   - `main/update/`：启动后拉版本 JSON（GitHub Releases API），比对 semver，UI 出"有新版本"提示 → 用户确认 → 打开下载页。**不引 electron-updater**（白名单纪律 + 我们的场景一个提示就够）
2. **崩溃兜底**（1 天）：渲染进程 `render-process-gone` / 主进程未捕获异常 → 落 `logs/crash-*.log`（含版本、最后 50 条日志、栈），下次启动提示"上次异常退出"
3. **打包签名**（1 天）：开 Windows 开发者模式 → 去掉 `signAndEditExecutable: false` → exe 带图标与版本信息（M0 遗留）
4. **perf 基线对比**（1 天）：`perf.mjs --baseline` 存 JSON，verify 时对比劣化 >20% 即红（I5 的"预算进 CI"补完）
5. **`docs/05-发布检查单.md`**（半天）：发版前人工清单（tag、verify、便携包试装、数据迁移路径）

**判据**

- [ ] 有新版本时启动 30s 内出提示，无新版本零打扰
- [ ] 杀掉渲染进程 → 下次启动能看到崩溃记录与日志文件
- [ ] exe 属性里有版本号与图标
- [ ] perf 基线：人为劣化搜索（O(n²)）→ verify 红

**常见走偏**：更新提示做成弹窗打断播放 → 用状态栏一条；基线对比把机器波动当劣化 → 三次取中位。

**顺序**

1. **桌面歌词窗**（3 天，00 §7.4 的最后一块）：独立置顶透明窗 + **独立 preload 只 3 方法**（迷你窗同款模式）+ 两种鼠标态（interactive / click-through，中键锁定）+ 位置字号持久化

**判据**

- [ ] 桌面歌词与播放页同一时间轴（对拍复用 M4 的 `compareRenderers`），穿透态不打断操作
- [ ] EQ 曲线与实际滤波器参数一致（改滑杆曲线即时变）
- [ ] 歌单页加第三家音源时 UI 零改动（能力契约复验）
