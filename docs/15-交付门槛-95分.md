# 15 · 交付门槛：95 分

> **由来**：2026-11-03，用户在看到"6 套播放样式里 5 套没过 95 就直接摆出来"之后立的规矩——
> **"之后设计开发必须自评过 95 分才能输出。"**
> **效力**：与 `00` 的不变式同级，**不是建议**。`.codebuddy/rules/95-gate.mdc` 是它的执行版本（`alwaysApply: true`）。

---

## 1. 为什么要立这条

不是洁癖，是因为**"先给你看看"的成本全落在用户身上**：

| 我们以为 | 实际发生 |
|---|---|
| "先出个方向，用户选一个" | 用户要在**5 个半成品**里挑，比没有更累 |
| "能跑就行，细节后面补" | 细节永远补不上，因为下一轮又在赶新东西 |
| "我评了 92，挺高了" | 92 分的作品看起来"差一点"，但差的正是决定性那一点 |

**一个 96 分的作品 > 六个 90 分的作品。** 这条规则就是把这句话变成硬约束。

## 2. 两条评分尺（设计 / 开发）

### 2.1 设计（100）

| 维度 | 权重 | 扣分口径 |
|---|---|---|
> **2026-11-03 换尺**：用户给了专业评审标准，**下面是唯一有效的设计尺**。此前用的"辨识度/惊艳/完成度/品类/可实施/一致"六维尺**作废**（它把"我觉得惊艳"当维度，专业度不够）。

| 一级维度 | 分值 | 核心考察 |
|---|---|---|
| **创意与概念** | 25 | 原创性、思想深度、概念与目标契合度 |
| **视觉表现** | 25 | 色彩、版式、构图、视觉层次（至少 3 级信息层级） |
| **功能与传达** | 20 | 信息效率、认知成本、是否达成设计目标 |
| **执行与工艺** | 20 | 像素级精度、技术规范、素材质量、可交付性 |
| **一致性与适配性** | 10 | 风格统一、品牌匹配、多场景适配、可扩展 |

**四档口径**（每维都要落到档，再取分）：

| 档 | 创意 | 视觉 | 功能 | 执行 | 一致 |
|---|---|---|---|---|---|
| 优秀 | 21–25 | 21–25 | 17–20 | 17–20 | 9–10 |
| 良好 | 16–20 | 16–20 | 13–16 | 13–16 | 7–8 |
| 一般 | 11–15 | 11–15 | 9–12 | 9–12 | 5–6 |
| 较差 | 0–10 | 0–10 | 0–8 | 0–8 | 0–4 |

**等级线**：90–100 **A+ 卓越**（行业顶尖、可作标杆）｜80–89 A 优秀｜70–79 B 良好｜60–69 C 合格｜50–59 D 待改进｜0–49 F 不合格。

**95 分落在 A+ 区间**——意味着"创意与执行俱佳的标杆作品"，不是"能看"。这就是这条闸门的真实标高。

**两条使用纪律**（来自标准原文）：
1. **分项打分再求和**，不许凭整体印象直接给总分；
2. **客观优先**——能用"层级是否清晰、有没有错位、信息能否 3 秒读到"这类可量化判据，就不许用"我觉得好看"。

| **功能正确** | 25 | 判据逐条过；边界（空/满/超长/断网/并发）有覆盖 |

> 落地：`LiveHome.tsx`（`spawnFly` / 转场 effect / 待播带 rect 快照 / 重播脉冲 / 歌名滚动交接）+ `on-air.ts`（`orderProgram` 播出顺序投影）+ `cover-stage.css`（`.cs-fly` / `.cs-stage.cs-flying` / `.cs-stage.cs-landed` / `.cs-home.cs-flying.cs-back` / `.cs-lead-roll` / `@property --cs-tint`）。

|---|---|---|
| T1 两份副本 | 删掉旧封面那次 `spawnFly` | `n: 2` |

| **T9 列表不骗人**（核心） | `upcoming` 改回 `program[(leadIndex+k)%total]`（不用 `orderProgram`） | 随机模式下：点前列表第 1 格 == 点后 hero，实测「末班车」=「末班车」 |

| T11 列表晚于封面起步 | 把 `LIST_DELAY_MS` 改成 0 | `lag: 50`（`startTime + delay` 之差，判 30–80） |
| T12 歌名滚动交接 | 删 `land()` 里的两处 `animate` / 不给 `.cs-lead-ghost` 设 900ms 回收 | 落位后 1.3s 内逐帧扫到 `rolling: true`（新字有推入动画）→ 收尾 `ghost: 0` |
| **T13 离场层不许回弹**（用户截图实锤） | 把离场层动画从 `fill: forwards` 改回 `backwards`（只兜 delay，结束交还样式） | `{bad: null, sawGhost: true, rolling: true}`；改回 backwards 后 660–900ms 会抓到 `{op: 1, t: "none"}` = 旧字压在新字上 |

**四条纪律**：
1. **中间态不做几何断言**：`capturePage` 有 300–800ms 延迟，380ms 的飞行抓不到中段；`pause()` + `currentTime` 定格会让 `capturePage` 卡死（实测 7 分半不返回）。要拍中间态就临时把 `FLY_MS` 放大到 2000 + `SWAP_SHOTS=1`，拍完改回——别在脚本里做 seek。
2. **副本的叠放靠 DOM 顺序，不靠 z-index**：两份同为 `z-index: 50`（全局层序白名单里只有 40/50/60），后插入的在上。T3 守的就是这个。
3. **换歌是异步的**：`onPlayRemote` 走 IPC，`click()` 的同步帧里查不到副本，判据必须轮询到 `.cs-fly` 出现再采样（`requestAnimationFrame` 轮询，5s 超时）。
4. **倒退的尺寸关系与顺播相反**：顺播是新封面从卡位长出来（一窄一宽，比例 ~3.8），倒退是新封面从大图尺寸推入（两份都是大图宽，比例 ~1）。T6 用**比值**而不是绝对值，就是为了区分走的是哪条分支——只断言"有两份副本"时两条分支都能绿。
5. **`fill: backwards` 的动画在 finish 后会被浏览器移除**：滚动交接 240ms 就跑完，1.8 秒后读 `getAnimations()` 必然是 0 条。要验"动过"必须在动画窗口内采样，或者改判它的副作用（`cs-landed`、`.cs-lead-ghost` 是否回收）。
   **更要命的是"交还样式"**：`backwards` 在动画结束后把元素还给样式表 —— 离场层因此弹回原位、不透明，压在新标题上（T13 就是这么来的，用单点采样根本抓不到，必须整段逐帧扫）。离场类动画要用 `forwards` 并在 `finished` 里立刻摘节点。
6. **`animation.startTime` 要等一次动画 tick 才有值，而 tick 排在 rAF 之后**：在 rAF 回调里读永远是 `null`（会误报成"测不到"，而不是"没做到"）。T11 延 60ms 采样，此时副本仍在飞行（380ms），两组 `startTime` 都已落定。

**两条纪律**：
1. **尺寸改动有连带**：主键从 40px 改到 44px（只为好看）就把底栏顶高 4px，播放页 1160×740 立刻多出 11px 纵向滚动 —— 跨页面的判据会替用户先发现。改任何固定尺寸前先想清楚谁依赖它。
2. **溢出判据只判"用户真能滚到"的**：`.sl-sleeve` 里正在转的黑胶会把自身 `scrollHeight` 撑大 11px，但它是 `overflow: visible` 的装饰盒，既不出滚动条也裁不到内容。判据若把它算红，同一份代码会**随播放态抖动**（播放态红、暂停态绿，实测）。所以只判文档级 + `overflow` 非 visible/hidden 的盒子，装饰盒只记日志。

7. **`cs-flying` 挂在 `.cs-home`、`cs-landed` 挂在 `.cs-stage`**：读错元素会假红（T9 段就踩过一次，报"命中转场但没落位"）。

**未验 / 已知瑕疵（如实记）**：
- 自动播完切歌未跑到曲末实测（同一条 lead 变化路径，逻辑上命中）。
- **随机模式切档那一刻**（点随机按钮）order 重排、整排换内容，目前是硬切，没有过渡。
- **画质**：大图 593×469，而 fixture 封面源只有 400×400，飞行最后一段是 1.48 倍放大，会逐渐变糊。这不是曲线问题，是像素问题（真实音源尺寸未全量核查）。
- 歌名滚动在"旧两行 / 新一行"时，旧字超出 mask 的部分会被裁掉。220ms 内几乎不可见，但不精确。
- **跳多首的倒退**（一次退 2 首以上）只做封面交接、不做整排位移：步长不止一格，硬套一个 `step` 会把中间几张推错位。这条没做也没测。
- **切上一首时最右那格是原地消失**：React 直接删节点，没有退场，300ms 内位置 4 会短暂"半空"，等前一张滑进来才填满。修它要保留幽灵节点或改布局（会碰光场 anchor），成本远超收益——它发生在屏幕最右端，注意力在左侧交接。

### 3.5 判据台账：首页信息去重与中轴（D1–D5，2026-11-12 第四轮）

> 这一轮改的是**文案分工与轴线**，不是新功能：判据因此分两类 ——
> 「该在的位置必须还在」（正向）与「不该再出现的东西不许回来」（反向）。
> 只写正向的话，冗余文案加回来照样绿，这轮就等于没验。

| 判据 | 这条在守什么 | 当前绿灯值 |
|---|---|---|
| **D1 状态词只有一个出口** | 说明句不许再出现「正在播放」——它是眉标的专属词 | 眉标含「正在播放」，说明句匹配 `/还剩\s*\d+\s*首/` 且不含状态词 |
| **D2 脚注只描述波形与总量** | 脚注不许复述播放态，也不许写回「循环列表」（循环开关在底栏） | 脚注含「共」+ 数字、不含「正在播放」、不含 `STEREO`/`L·R` |
| **D3 右栏不再转述播放态** | 小标题是「播放队列」不是「正在播放」；meta 不写「来自当前队列」 | `feed == 播放队列`、`meta` 非空且不含「来自当前队列」 |
| **D4 说明句与播放态解耦** | 暂停时说明句不该改口（它说的是队列还剩多少，与播/停无关） | 暂停后仍匹配 `/还剩\s*\d+\s*首/`，且不含「正在播放」 |
| **D5 编号口径可解析** | 眉标改「第 N 首」后，解析口径必须同步（旧代码用 `split("/")`） | `/\d+/` 取数后 +1 == 角标数字；口径不同步会拿到 `NaN`，`isFinite` 判红 |
| **中轴（几何）** | 主键与进度条必须同一条竖直轴 | 1440 窗：主键圆心 **690.5** / 轨道中心 **690.5**（改前 606 vs 714，差 90） |

**两条纪律**：
1. **改文案必须同时改判据，但方向要反过来**：原来判"文案里必须有『来自』"，现在判"文案里不许有『正在播放』"。前者会奖励复述，后者才守住去重——判据写的方向，决定了下一个改它的人会往哪走。
2. **几何判据量中心，不量边**：主键偏左 90px 时，量"主键左边距"只能得到"比上次小了 90"，量两者中心才能断言"同一条轴"。同理，两端时间戳要定宽（44px）—— 不定宽时 `3:10 → 12:04` 会让轨道跳一格，那是排版在抖，不是进度在走。

**已知瑕疵（如实记）**：右栏卡片底到频谱之间仍有约 145px 空白（4 张卡只占右栏上部 38%）；封面 `object-fit: cover` 仍是居中裁，构图偏边的封面会被切掉一侧。两条都属"内容密度 / 逐图判断"，本轮没动。

## 4. 假自评黑名单

| 假自评 | 识别方法 |
|---|---|
| 把"能跑"当"完成" | 问一句：空态长什么样？错误态呢？窄窗呢？ |
| 把"布局变体"当"多个设计" | 把两版并排，如果信息结构一样只是骨架不同 → 算一个 |
| 无扣分项 | 96 分以上的作品也该有 4 分可扣；写不出 = 没评 |
| 分数无理由上涨 | 对比上一版的扣分项，逐条核对是否真的修掉 |
| 拿旧截图当新证据 | 查文件修改时间与截图内的时间码 |
| 只做 happy path | 数一数实现了几个状态：正常 / 空 / 错 / 加载 / 降级 |

## 4.1 评分前置条件：**必须先真实渲染，再打分**（2026-11-03 血的教训）

我给六套样式打过 96/97，用户贴出真机截图后实测只有 58–84。根因三条，全部写进流程：

1. **合成器滞后**：DOM 切换了、画面还停在上一条 → `scripts/mockup-shots.mjs` 必须**回读 `.view.on`** 并**等两帧 + 260ms** 再截。不校验就截 = 假证据（我因此把「影院」截成了「剧本」）。
2. **CSS 渐变不能当封面**：图为主的设计（影院/海报/碟）在占位渐变下必然崩。必须拿**真实照片**验（本机 `C:\Windows\Web\Wallpaper\Windows\img0.jpg` 即可）。
3. **对比度不能靠"设计软件里的感觉"**：`hair .09` / `mute .28` / 未播 `.18` 在 1334×747 真屏上等于隐形，所有"细节设计"都白做。统一提到 `.16 / .46 / .30` 再评。

**所以：任何设计稿的自评，必须附 `docs/assets/mockups/*.png` 的真实截图路径；没有截图 = 不许评分 = 不许输出。**

## 5. 例外

只有一种：用户**明确要求**"先看草稿/先定方向"。此时输出**第一行**必须写：

例外不许变成常态。**同一话题连续两次用例外，就是没把这条规则当回事。**

## 7. 反面案例（别重犯）

**2026-11-03**：一次输出 6 套播放样式，自评 96 / 92 / 90 / 93 / 94 / 91。
