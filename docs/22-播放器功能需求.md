## 一、三条判定原则

1. **「做完」= 入口 + 四态 + 键盘可达 + 可红判据**。
   任何功能缺「空态 / 错误态 / 加载态 / 断网态」之一，按未完成计（`15` 扣分口径）。
2. **对标是同行最高水平，不是平均**。
   每项都指名「抄谁」；指不出对标对象的，不许进 P0。
3. **能抄不写，抄的时候只改三处**：
   ① 框架层（Vue/composition → React/我们 store）；② 数据源（接 `contracts/` 与 kernel intent）；③ 文案。
   **不改算法、不改判据**——改了就没有「同行验证过」这层保障。

**已定的显示规则（A 方案，2026-11-04 用户拍板）**：账号归账号、本地归本地，**两栏并列，不做 id 合并**。
理由：账号红心是 songId、本地红心是 trackId，两套 id 空间；按「歌名+歌手」猜映射会把同名不同版本（现场版/翻唱）误判成同一首。
哪天要做合并，先解决匹配准确率，再动 `domain/likes`。

**统一设计**（照 folia 的分法，但只取一层）：账号数据挂在 `SourceProvider.account` 上，UI 一律读「有没有 account / 登录没登录」决定出入口。**未登录时账号接口抛 `auth-required`，不返回空列表**——空列表会显示成「今天没有推荐」，用户不知道自己只是没登录。

**出口判据**：登录一个真实账号 → 首页推荐与网易云 App 同一天同一批；「喜欢的音乐」里账号红心数与 App 一致；「最近播放」显示账号的听歌排行；漫游连抽 5 首都不是本地曲库的。
