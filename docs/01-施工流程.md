## 1. 开工前必须定下的 7 件事

先拍板，不然第一天就会在岔路口停下。每件都给了默认值，**不同意就现在改，改完再动第一行代码**。

### 1.1 新仓库放哪

| 项 | 默认 | 理由 |
|---|---|---|
| 路径 | `f:/AI/afeifei-v2` | **不要中文、不要空格**。旧路径 `f:/AI/自己的播放器` 含中文，electron-builder / node-gyp / 部分 CLI 在非 ASCII 路径上有历史事故，新仓库没必要继承这个风险 |

| 旧仓库 | 只读。禁止在本次开发中修改它 | 一旦两边都能改，就出现第二个真相——这正是 50 §1.2 要消灭的东西 |

### 1.2 许可证与署名

- `LICENSE` = **AGPL-3.0-only**（与旧仓库一致，已发布过就不换了）。
- 从旧仓库拷来的文件：文件头保留原作者声明。
- 从十家开源项目取做法：记进 `THIRD-PARTY-NOTICES.md`（格式见 50 §1.1 末）。

### 1.3 语言与构建

| 决定 | 选 | 不选的理由 |
|---|---|---|
| 语言 | **TypeScript**（`strict: true`） | 50 §12 全目录是 `.ts`；环之间的契约必须是类型，靠注释约束不住 |
| 构建 | **esbuild** 手写 `scripts/build.mjs` | 旧仓库已验证这套能跑通（旧 `tools/build-ui.mjs`）；Vite 会引入 dev server、HMR、插件生态三层东西，本项目**只有一个窗口、不需要 HMR 之外的任何东西** |
| 类型检查 | `tsc --noEmit`（只在 verify 里跑） | 构建不用 tsc，两者职责分开：tsc 管类型，esbuild 管产物 |
| 测试 | **`node --test`（内置，零依赖）** | 50 §13 明确要求；且"纯函数层要能在没装 Electron 的机器上跑" |
| UI | React 19（只在 Ring 4） | 50 §2 定死了；但**只有 `ui/` 能 import react**，由 lint 强制 |

**构建产物结构**（`dist/` 全部由 esbuild 生成，不入库）：

```
dist/
  main.js          ← main/ 打包（node 平台，external: electron）
  preload.js       ← preload/ 打包（cjs，contextBridge 唯一桥）
  renderer/
    index.html     ← 从 src/renderer/index.html 原样拷贝
    app.js         ← ui/ 打包（browser 平台）
    app.css        ← ui/**/*.css 合成一份
```

### 1.7 运行环境与数据落点（最容易"以后再说"，然后 M1 撞上）

| 项 | 定死 | 为什么现在定 |
|---|---|---|
| Node | **≥ 20.11 LTS**（实测 22.22 亦可） | `node --test` 需要 ≥ 18.13；Electron 33 内置 Node 20。低于这个版本，本文所有测试命令形式都不生效 |
| 系统 | Windows 10/11 x64 | 打包目标是 `--win portable --x64`，不做跨平台分支 |
| Electron 下载 | 项目根写 `.npmrc` 两行：`electron_mirror=` 与 `electron_builder_binaries_mirror=`（都指向 npmmirror）。**不要用 `npm config set ELECTRON_MIRROR`**——新版 npm 会直接报 `not a valid npm option` | 不设镜像，`npm i electron` 可能卡十几分钟甚至超时失败。这是这条流程里第一个会浪费半天的地方 |
| 数据目录 | **便携版必须跟随 exe**：`process.env.PORTABLE_EXECUTABLE_DIR` 存在时用 `<该目录>/data`，否则用 `app.getPath("userData")` | electron-builder 的便携版默认把数据写进 `%APPDATA%`。用户把 exe 拷到 U 盘，队列、歌单、登录全丢——这是便携版最常被投诉的点，而它只在 M1 第 8 步（队列持久化）才第一次暴露 |
| 日志 | `<数据目录>/logs/app.log`，单文件 5MB、保留 3 份，落点由 `main/log/` 一个模块负责 | 50 §10 定了日志三条，但"写到哪、谁轮转"没人认领。M1 出问题时只能靠 DevTools，而那时进程已经崩了 |
| 单实例 | `app.requestSingleInstanceLock()` **放 M0**，不放 M5 | M5 的 `afeifei://` 依赖它。等到 M5 才发现双开在抢同一份队列文件和日志，前面所有持久化都得返工 |
| 打包 | 账户没有符号链接特权时，`electron-builder` 解压 winCodeSign 会失败（`Cannot create symbolic link`）。配置写 `"win": { "signAndEditExecutable": false }` 可绕过（代价：exe 无自定义图标与版本信息）；要图标就开 Windows 开发者模式或以管理员运行 | 它发生在**第一次**打包，报错是乱码 + 中文"+ 重试 3 次"，极易误判成网络问题，然后去折腾镜像 |

路径判定就三行，M0 写死在 `main/paths.ts`：

```ts
export const dataDir = () => process.env.PORTABLE_EXECUTABLE_DIR
  ? path.join(process.env.PORTABLE_EXECUTABLE_DIR, "data")
  : app.getPath("userData");
```

**之后所有持久化只认 `dataDir()`，不许在别处再算一次路径**——第二个真相都是从"我顺手拼一下"开始的。

## 2. M0 · 建仓（D0–D2，唯一一段边搭边定规矩）

M0 的判据在 50 §16（五条）。本节把它拆成可执行的动作，**顺序不能换**：闸门先于代码，否则后面每一段都会有人绕过它。

### 2.0 命令约定（先读这七行，否则第一条命令就报错）

本文的目标环境是 **Windows + PowerShell**，有两件事和网上抄来的教程不一样：

| 写在哪 | `&&` 能用吗 | 说明 |
|---|---|---|
| `package.json` 的 `scripts` | **能** | npm 在 Windows 走 `cmd.exe`，`&&` 正常 |
| 你手敲的 PowerShell 5.1 | **不能** | 会报「'&&' 不是此版本中的有效语句分隔符」。用 PowerShell 7（`pwsh`），或者逐行敲 |
| `grep` / `wc` | **不能用** | Windows 原生没有这两个命令。本文的检查一律写成 `node scripts/*.mjs` |

所以本文不出现 shell 管道。多写几个 `.mjs` 换来的好处是：**这些检查同时就是常驻 lint 规则**，能一直守着，而不是只在你手动跑的那一次有效。

### 2.1 建目录（10 分钟）

在 `f:/AI` 下开 PowerShell：

```powershell
node -e "const fs=require('fs');['src/main/log','src/main/fs','src/main/net','src/main/media','src/main/ipc','src/preload','src/contracts','src/renderer/kernel','src/renderer/domain','src/renderer/capability','src/renderer/projection','src/renderer/ui','src/renderer/workers','scripts','test','docs'].forEach(d=>fs.mkdirSync(d,{recursive:true}))"
git init
```

**空目录先建全，哪怕里面只有 `index.ts`。** 目录是约束的物理形态：没有 `projection/` 这个目录，selector 就会漂到组件里去。

### 2.2 装依赖（15 分钟，先设镜像）

```powershell
npm config set ELECTRON_MIRROR https://npmmirror.com/mirrors/electron/
npm init -y
npm i -D electron@^33 electron-builder@^25 typescript@^5 esbuild@^0.28 @types/node @types/react @types/react-dom
npm i react@^19 react-dom@^19 music-metadata@^7
node -v
```

最后一行确认 ≥ 20.11。M0 **不装 three**（M4 才用）。

`tsconfig.json` 有三项必须写对，不写 React 19 的 JSX 直接解析失败：

```jsonc
{ "compilerOptions": {
  "jsx": "react-jsx",          // 不是 "react"，否则每个文件都要手写 import React
  "moduleResolution": "bundler", // 配合 esbuild，不要求 .js 后缀
  "strict": true, "noEmit": true
} }
```

`scripts/build.mjs` 里对应写 `jsx: "automatic"`。**tsc 只做类型检查（`--noEmit`），产物全部由 esbuild 出**——两者职责不重叠。

### 2.3 九个骨架文件（应用代码 ≤ 40 行；两个脚本不设上限，但 lint 的每条规则 ≤ 30 行）

| 文件 | 只做到这些 | 为什么现在就要 |
|---|---|---|
| `src/main/paths.ts` | `dataDir()` 三行（§1.7）。**全仓库唯一算数据路径的地方** | 别处再算一次就是第二个真相 |
| `src/main/log/index.ts` | 写 `<dataDir>/logs/app.log`，5MB 轮转 3 份，导出 `log/warn/error` | M1 出问题时有地方看；凭据一律不进日志 |
| `src/main/index.ts` | 单实例锁 → `whenReady` → 建窗口（`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`）→ 设 CSP → 载 `dist/renderer/index.html`。**不含任何 fs / net / 业务** | 50 §2 主进程不许有业务。**M0 就压住，以后加不进去** |
| `src/preload/index.ts` | 一个 `contextBridge.exposeInMainWorld("api", { ping })` | 唯一桥。先证明"桥是具名的"，后面每个方法都要在这排队，桥自然会窄 |
| `src/contracts/index.ts` | 只放类型：`PlayerState`、`Intent`、`TrackId` | 环之间的契约必须第一天存在，否则 ui 会先 `any` 起来 |
| `src/renderer/kernel/store.ts` | 60 行单写者：`getState / dispatch / subscribe`（`Set<() => void>`，无库） | I2 的物理载体。第一个写者在这登记，第二个加不进来 |
| `src/renderer/ui/index.tsx` | 挂 `<div>afeifei</div>`，订阅 store 打印状态 | 证明 React 只吃投影，不碰 kernel 写方法 |
| `scripts/build.mjs` | esbuild 三次打包（main / preload / renderer）+ 拷 html/css | 手写 60 行，比引 Vite 便宜 |
| `scripts/verify.mjs` | 依次 `spawn` 下面的闸门，任一非 0 退出即整体红 | **一条命令**是这个项目的纪律载体 |

三件 M0 必须写对、后面很难改的事：

- **界面必须用自定义协议（`app://`）提供，不要 `file://`**。原因不是洁癖：`file://` 页面的 origin 是 opaque，CSP 里的 `'self'` 匹配不到任何 URL，于是 `<script src="app.js">` 被**静默拦掉** —— 进程活着、日志正常、窗口一片空白，控制台还看不出原因。顺带两个连带结论：renderer 产物必须是 **iife + 普通 `<script>`**（`file://` 下 ES module 会被 CORS 拦）；`registerSchemesAsPrivileged` **只能一次性传数组**，分两次调用会互相覆盖（后一次抹掉前一次的 `standard/secure` 特权，症状同样是"HTML 加载了、脚本不执行"）。
- **`sandbox: true` 时 preload 不能 `require` 任何业务模块**，只能用 `electron` 的 `contextBridge` / `ipcRenderer`。这正是我们要的——preload 只做桥。等到 M1 想"顺手在 preload 里读个文件"时会撞墙，那不是限制，是提醒。
- **CSP 必须在 M0 就设**，后加会撞一堆内联脚本。最小可用值：
  `default-src 'self'; script-src 'self'; style-src 'self'; media-src appmedia:; img-src 'self' data: blob:; connect-src 'self' appmedia:`
  （React 通过 DOM API 设的内联 style 不受 `style-src` 限制，所以不需要 `'unsafe-inline'`；`connect-src` 不写 `appmedia:` 的话，`fetch("appmedia://…")` 会被拦。）

### 2.4 五道闸门（D1，**必须比第一个功能先绿**）

```js
// scripts/verify.mjs（骨架）
import { spawnSync } from "node:child_process";
const steps = [
  ["typecheck", ["npx", "tsc", "--noEmit"]],
  ["lint",      ["node", "scripts/lint.mjs"]],
  ["test",      ["node", "--test"]],    // Windows 不能写 "test/"：结尾斜杠会被当模块名，报 MODULE_NOT_FOUND
  ["build",     ["node", "scripts/build.mjs"]],
  ["smoke",     ["node", "scripts/smoke.mjs"]],   // M1 起才有
];
for (const [name, [cmd, ...args]] of steps) {
  const r = spawnSync(cmd, args, { stdio: "inherit", shell: false });
  if (r.status !== 0) { console.error(`✗ ${name} 失败`); process.exit(1); }
}
```

**参数用数组传、`shell: false`**，不要拼成一整条字符串——`C:\Users\张三\...` 这种路径拼字符串必炸（空格与中文各炸一次）。

`scripts/lint.mjs` 六条规则，每条对应 50 的一条不变式：

| # | 规则 | 查什么 | 对应 |
|---|---|---|---|
| 1 | **环依赖** | `renderer/` 下按 `kernel→domain→capability→projection→ui` 单向，反向 import 即红；`ui/` 之外出现 `from "react"` 即红；环 0–4 出现 `ipcRenderer` 即红 | 50 §2、I2 |
| 2 | **音频图唯一** | `new AudioContext` 出现 **>1 次**即红；出现 1 次但不在 `capability/audio/graph.ts` 也红。M0 是 0 次，这条允许（写成"必须等于 1"会让 M0 直接红） | I3 |
| 3 | **时间唯一** | `ui/`、`projection/` 出现 `audio.currentTime` 或 `setInterval(` 即红。`Date.now()` **不进这条规则**——它常是合理的墙上时间，用错与否只能人看（判断方法见 §3①） | I1 |
| 4 | **rAF 唯一** | `requestAnimationFrame` **只准出现在 `ui/compositor.ts`**，其它文件出现即红 | 50 §9.1 |
| 5 | **hex 白名单** | `.css` / `.tsx` / 内联 style 里出现 `#rgb` 或 `#rrggbb` 即红；**白名单**：`ui/tokens.css`、`ui/theme/presets/**`、`test/**` | 50 §9.3 |
| 6 | **主进程无业务** | `src/main/**` 禁止 import `src/renderer/**`；禁止出现 `library` / `playlist` / `dedupe` / `history` 这类**业务标识符**（函数名/变量名；注释不算）；单文件 ≤ 400 行 | 50 §2.1 |

两条注意：

- **规则 3/4/5 按"文件"判，不按"次数"判。** 计数在递归和循环里必然对不上（`requestAnimationFrame` 递归调用一次就出现两行），这类判据很容易写成"永远红"或"永远绿"。
- 规则 1 直接改旧仓库 `tools/check-layers.mjs` 的 `LAYERS` 表：结构一模一样，只把层名换成 `kernel/domain/capability/projection/ui`，并给 `ui` 开 `react` 例外。这是 §1.5 里"取纯函数"的第一个例子。

### 2.5 一条命令

```json
{ "scripts": {
    "start": "node scripts/build.mjs && electron dist/main.js",
    "verify": "node scripts/verify.mjs",
    "dist": "node scripts/build.mjs && electron-builder --win portable --x64"

```

（这里的 `&&` 是给 npm 看的，Windows 下正常。）

## 3. 施工循环：M1 之后每个任务都走这六步

```
① 这条不变式今天怎么被检查？
        ↓
② 纯函数 + 测试（先红）
        ↓
③ 实现（跑到绿）
        ↓
④ npm run verify 全绿
        ↓
⑤ 假数据手点一遍（真机，不看测试报告）
        ↓
⑥ git commit + docs/03 加一条
```

### ① 先想"怎么被检查"，再想"怎么写"

每个任务开工前写一行：**这个改动如果被做错，哪条检查会红？**

- 答不出来 → 这个任务还没想清楚，或者它不值得做（回到 50 §17）。
- 答案是"我会记得" → 不算答案。改成 lint 规则或一条测试。
- 看到 `Date.now()` 时多问一句：**这是播放时间还是墙上时间？** 播放时间（进度、歌词、动画相位）必须来自 `clock.t`；墙上时间（日志、缓存过期、上次登录）才可以用 `Date.now()`。这条机器判不了（§2.4 规则 3 特意没管它），只能人判。

### ② 纯函数先写，测试先红

顺序固定：**类型 → 纯函数 → 测试 → 实现**。

队列、投影、歌词解析、错误翻译、迁移器——全是纯函数，都能在没装 Electron 的机器上跑。这条不是为了覆盖率，是为了**逼你把业务从 UI 里拔出来**（50 §13 的"关键"）。

### ③ 实现

只有两类代码允许出现在"实现"这一步：

- 环内的纯逻辑（kernel / domain / capability / projection）
- 环 4 的渲染（ui）

如果实现时发现要动 `main/`，先问：**这是系统调用，还是业务判断？** 业务判断 → 放回 `domain/`，`main/` 只提供 `readDir / readTags / fetch / writeFile` 这类能力。

### ④ verify

不许跳过、不许把规则注释掉。**闸门红了只有两种处置**：修代码；或按下面的协议改规则。

**阈值/规则变更协议**（全文只此一处，§5 和 §8 都指回这里）：

改 lint 规则、放宽性能阈值、把某条判据改成"人工确认"，**都是合法的**——阈值本来就会随着事实变化而错。但必须同时满足三条，缺一条就是"绕过闸门"：

1. 单独一次提交，提交信息以 `gate:` 开头（例：`gate: 内存预算 350MB → 420MB`）。
2. 同一次提交里 `docs/03` 写清：**原值 → 新值、为什么原值是错的、什么情况下要改回去**。
3. 不许在同一次提交里夹带功能代码。

判断标准很简单：**三个月后别人看到这个改动，能看懂当时为什么放宽。** 看不懂就是绕过。

### ⑤ 假数据手点

测试绿了不代表能用。每段功能都要有一个 `--dev` 开关能注入假数据：

| 段 | 注入什么 | 手点 |
|---|---|---|
| M1 | 3 个本地音频（**mp3 / flac / m4a 各一个**；`C:\Windows\Media\*.wav` 里挑一个再转格式，别等"以后找歌"） | 播 / 暂停 / 切歌 / 拖进度 / 重启恢复 |
| M2 | 5000 条假曲目 | 滚动、搜索、点播 |
| M3 | 假音源（返回固定 JSON），不打真网 | 搜索、播在线、断网错误文案 |
| M4 | 假 FFT 数据 | 四套预设切换、intensity=0 |
| M5 | 假用户源包 | 导入、越权被拒 |

**假数据必须走正式接口**（假 provider 实现真契约），不是 `if (dev) return 假数据`。后者会在 M3 变成第二个真相。

### ⑥ 提交 + 日志

- 一次提交 = 一件事（≤ 400 行 diff，与 50 §12 的文件上限同源）。
- `docs/03-改动日志.md` **最上面**加一条：动机 / 改了哪些文件 / 关键决策 / 坑 / 遗留。
- 不替用户 `push`。

顺序里的编号就是施工顺序，**不许并行**——每一步的输出是下一步的输入。

### M1 · 内核（体量：1.5–2 周）

**目标**：能播一首本地歌，且**时间是对的**。除此之外什么都不做，没有界面设计、没有曲库、没有在线。

**顺序**

1. `contracts/state.ts`：`PlayerState`（六态）、`QueueState`（items/cursor/context/history）、`Intent` 联合类型。**先定类型，不写实现**（半天）
2. `kernel/store.ts`：单写者。`dispatch(intent)` 是唯一入口，`subscribe` 只读。每个域一个 reducer 文件，**一个域只准有一个写者**（半天）
3. `kernel/clock.ts`：`t = anchor + (now - anchorWall)`，每 250ms 用 `audio.currentTime` 重锚；漂移 > 50ms 时吸附并记 `console.warn`。**全仓库唯一读 `audio.currentTime` 的文件**（一天）
4. `kernel/queue.ts`：三分 + shuffle 投影纯函数（`orderOf(items, seed, mode): number[]`，不改 items）（一天）
5. `kernel/player.ts`：六态机 + "上一首 3s 规则"（一天）
6. `capability/audio/graph.ts`：**唯一** `new AudioContext()` + 四 stage（fade / preamp / eq / analyser），Stage 接口 `connect(next)`（一天）
7. `main/media/`：`appmedia://` 协议（id → 文件，支持 Range）+ `main/fs/readFile`。**id 令牌 + TTL，不许把裸路径给渲染层**（一天）
8. 持久化：队列 + 位置 + 音量写盘，节流 1s（50 §4.3）（半天）
9. 测试补齐：queue ≥ 20 项、clock ≥ 10 项（一天）

**今天不写**：曲库扫描、封面、歌词、舞台、设置页、任何在线请求。

**判据**（50 §16 M1 全部 + 以下可验证项）

- [ ] 播一首 → 进度条、`clock.t`、`audio.currentTime` 三者差 < 20ms（打点一次即知）
- [ ] 断网 / 文件被删 → 进入 `error` 态，界面收到 `track-missing`，不崩
- [ ] 强杀进程再启动：队列、位置（≤1s 误差）、音量都在；数据落在 `dataDir()` 指的那个目录里（§1.7）
- [ ] 切歌 20 次：不爆音、不闪白、进度条不跳
- [ ] lint 规则 2、3、4 绿（`new AudioContext` 恰好 1 处；`ui/` 与 `projection/` 里没有 `currentTime`；`rAF` 只在合成器）——这三条已进 verify，不需要单独跑命令

**提交点**：每一步一提交，共 9 个（提交信息格式见 §6.1）。第 3 步（clock）和第 6 步（graph）的提交必须带上对应测试。

**常见走偏**

| 走偏 | 症状 | 修 |
|---|---|---|
| 用 `setInterval` 驱动进度条 | 与音频越走越偏，暂停后还在走 | UI 只订阅 `clock.t`；lint 已禁 `setInterval` |
| 把 `audio` 元素塞进 store | 状态树里有 DOM 节点，序列化失败 | store 只存可序列化的数，`audio` 归 `capability/audio` |
| "先随手写个播放按钮试试" | 三个月后这个按钮长出了自己的状态 | M1 的界面**只有 4 个按钮 + 1 条进度**，多一个都不加 |

**从旧仓库取**：无。M1 全部新写——旧仓库的播放逻辑和 6,000 行 DOM 纠缠在一起，抽出来的成本高于重写。

**目标**：5000 首不卡。索引是**快照 + 增量日志**，不是全量重写。

**顺序**

4. `domain/library/dedupe.ts`：去重建议（同 inode / 同 size+时长 / 同 acoustic id 三档），**返回建议不自动删**（一天）
5. `main/fs/thumb.ts` + `domain/library/cache.ts`：封面缩略图（160px）+ LRU 上限（一天）

9. 测试：索引增量 ≥ 15 项、去重 ≥ 5 项（一天）
10. 接 `scripts/perf.mjs` 进 verify（半天）

**判据**

- [ ] 5000 首首次扫描 → 可搜索 < 30s（后台进行，界面可交互）
- [ ] 二次启动到可搜索 **< 120ms**（这就是"增量日志"的全部意义）
- [ ] 5000 行滚动 p95 < 20ms（`perf.mjs` 采）
- [ ] 拼音首字母 2 个字符出目标歌（50 §18 第 2 条）

**常见走偏**

| 走偏 | 症状 | 修 |
|---|---|---|
| 全量重写 JSON | 5000 首每次启动 800ms | 增量日志；快照只在压缩时写 |
| 主进程里判去重 | 业务进了宿主，无法单测 | 去重逻辑全在 `domain/`，`main/` 只给 `size/ino/duration` |

| 5000 条全塞 store 再筛选 | 每次输入都 O(n) 全量重排 | 首字母索引 + `projection` 里二分 |

### M3 · 能力（体量：2–3 周，全流程最重）

**目标**：两家音源跑通，且**加第三家不改 UI**。歌词四格式能解析。

**顺序**

1. `contracts/capability.ts`：能力声明表类型（20 项布尔/三态，见 `docs/47` 的清单）（半天）
2. `capability/registry.ts`：注册 + **启动断言**（声明了 `canSearch` 就必须有 `search` 方法，否则启动即崩）（一天）
3. `capability/errors.ts`：十二个错误码 + `translate(platformError) → ErrorCode`（一天）
4. **第一家音源**（网易云）：搜索 / 详情 / 播放地址 / 登录，全走 `capability/sources/netease/`（五天）
5. 契约测试：声明表 ↔ 方法一一对应，**不是手写 20 条断言**。做法是让"自动"真的成立：
   - `registry.ts` 里维护一张 `CAPABILITY_METHODS` 映射（`canSearch → "search"`、`canLogin → "login"`、`canGetUrl → "getUrl"` …，20 行）；
   - 导出 `assertCapabilities(p)`：遍历映射，声明为 `true` 但对应方法不是函数 → 抛错并**指名 provider 与缺的方法名**；
   - 测试里只有一行：`for (const p of listProviders()) assertCapabilities(p)`。
   
   这样加第三家源**自动被检查**，不需要有人记得补测试——这才叫自动（一天）
6. **第二家音源**（QQ）：**只许新增目录 + 注册一行**。若需要改 `contracts/` 或 `ui/`，说明第 1/5 步做错了，**回头改契约不改 UI**（五天）
7. `capability/lyrics/`：LRC / Enhanced LRC / QRC / YRC / TTML 解析 → 统一 `LyricDoc`（两天）
8. `main/lyrics/`：解析放到主进程（大文件不阻塞渲染）（半天）
9. EQ + ReplayGain 作为 `capability/audio` 的两个 stage（一天）
10. 测试：错误翻译 ≥ 20 项、歌词解析 ≥ 30 项（一天）

**今天不写**：舞台视觉、主题包、歌词渲染器（解析 ≠ 渲染，渲染在 M4）。

**判据**

- [ ] 加第二家音源：`git diff --stat` 里**只有新增文件 + `registry.ts` 一行**；`ui/`、`projection/` **零改动**；`contracts/` 若有改动，必须是一次单独提交并写清"原契约为什么不够"（见提交点）
- [ ] 故意删掉一家的实现文件 → 启动断言报错，报错信息指名道姓（不是 `undefined is not a function`）
- [ ] 断网搜在线 → 界面文案是"网络有点慢"，**不出现错误码或上游原文**（50 §18 第 8 条）
- [ ] 同一首歌的两个格式（LRC 与 QRC）解析出的时间轴，前 10 行误差 < 50ms
- [ ] 真号全链路：登录 → 搜索 → 播放 → 报错 → 重试
- [ ] **没有可用真号时**：用假 provider（回放录制好的 JSON）先跑通全链路，真号验收挪到过门前最后一次。**不许因此跳过契约测试**——契约测试不联网，它是这段唯一必须绿的

**提交点**：10 步各一个提交，但**第 1 步与第 5 步必须同一次提交**（契约类型 + 校验函数配套落地；只有类型没有校验，等于契约没立）。第 6 步（第二家源）若产生了 `contracts/` 的改动，把那条改动**单独提交**并写明"为什么原来的契约不够"——那是这段最有价值的产出，混在功能提交里就看不见了。

**常见走偏**

| 走偏 | 症状 | 修 |
|---|---|---|
| 能力用"试"不用"声明" | 点了收藏才报"该源不支持" | 声明表先写，UI 按表渲染；契约测试会红 |
| 把上游错误原文透给 UI | 用户看到 `-46003` | `translate()` 是唯一出口，UI 只认十二个码 |
| 为了 QQ 改 `ui/` | 第二家源把第一家搞坏了 | 改契约，不改 UI。这是 M3 唯一的硬规矩 |
| 歌词解析写在渲染层 | 5MB 的 QRC 卡住首帧 | 解析在主进程（第 8 步），渲染层只收 `LyricDoc` |

**从旧仓库取**（这是取货最多的一段）：`docs/47` 的七平台能力清单与失败分类、`app/main/sources/` 里的接口路径与签名算法、旧 `test-lyrics-pro.js` 的四格式样本（**样本比实现值钱**）。

**提交点**：9 步各一个提交。第 1 步（合成器）与第 6 步（对拍脚本）必须带测试；第 4 步（四套预设）与第 8 步（intensity=0）的提交里**附截图路径**——"肉眼明显不同"这条判据，三个月后只能靠截图复核。

**常见走偏**

### M5 · 生态（体量：1.5 周）

**目标**：可扩展、可分享。

**顺序**

1. `main/sandbox/`：用户源宿主（独立 worker/vm，超时 + 越权拒绝 + 崩溃不扩散）（三天）

## 5. 阶段门（Gate）：五条全绿才进下一段

| # | 条件 | 不绿怎么办 |
|---|---|---|
| 1 | `npm run verify` 全绿，**含该段新接入的 smoke / perf** | 修。要放宽阈值 → 走 §3④ 的**阈值变更协议**（单独 `gate:` 提交 + 写清原值/新值/改回条件） |
| 2 | 该段测试下限达到（M1: 30 / M2: 50 / M3: 100 / M4: 120） | 补测试。**下限是累计数**（50 §13） |
| 3 | 该段性能预算达标，且**有测法** | 先写测法；没有测法的"达标"不认。**M1 是例外**：perf 脚本 M2 才接，M1 只测 50 §14 第 3 条（本地出声 < 150ms，打点手测） |
| 4 | 该段"判据"逐条手点过（真机，不看测试报告） | 没过就是没过，不许写"基本通过" |
| 5 | `docs/03` 里该段的"遗留"已清空，或明确降级为"不做"并写理由 | 遗留不许悄悄带进下一段 |

**红灯处置顺序**：定位根因 → 改代码 → 若根因是设计缺陷，**停下来改 50 号文档**（新仓库那份），再改代码。**不许"先让它绿"**。

**跨段检查**（每过一门跑一次，5 分钟）：`node scripts/todo-count.mjs`，数 `TODO / FIXME / HACK` 的处数，数字只许降。（写成脚本而不是管道，是因为 PowerShell 里没有 `grep` 和 `wc`——见 §2.0。）

## 6. 制度

### 6.1 提交粒度

- 一提交一件事，diff ≤ 400 行（与文件上限同源）。
- 提交信息格式：`<环>: <做了什么>`，例：`kernel: add clock drift guard`。**M0 阶段还没有环**，脚本/配置/文档用 `chore:` / `build:` / `docs:`；放宽闸门一律 `gate:`（见 §3④）。
- 每一步（§4 里的编号）至少一个提交。**第 3、6 步这类"关键约束"的提交必须带测试**。

### 6.2 改动日志

新仓库 `docs/03-改动日志.md` 从第一天就有。格式抄旧 `docs/46` 的表头：

```md
## YYYY-MM-DD · 一句话标题
- **commit**：
- **动机**：为什么改
- **改了**：文件 → 做了什么
- **关键决策**：选了 A 不选 B 的理由
- **坑**：下一个窗口会重踩的
- **遗留**：没做的
```

「坑」和「遗留」必写。**没做的比做了的更值钱**——它是下一次决策的输入。

### 6.3 分支与备份

- `main` 一直可发布。功能分支 `m<段>-<短名>`，合并前必须 verify 绿。
- 每段过门后打 tag：`m0` `m1` … `m5`。**tag 是回滚点**，比任何快照脚本可靠。
- 不 push（用户不说就不 push）。

### 6.4 每段开工前的一件事

把 50 号对应章节**重读一遍**（M1 读 `50 §3 / §4 / §5`，M2 读 `50 §6`，M3 读 `50 §7`，M4 读 `50 §9`）。不是仪式——设计文档里那些"当时觉得多余"的句子，在实现到一半时会变成唯一的救命索。

## 7. 从旧仓库取东西的三条通道

| 通道 | 什么 | 怎么做 | 登记 |
|---|---|---|---|
| **拷数据** | 拼音表、token 数值、接口字段映射、歌词样本 | 直接复制，去掉旧代码外壳 | `docs/02` 一行 |
| **拷纯函数** | 歌词解析、去重判定、路径归一化、`check-layers.mjs` | 复制 + 复制它当时的测试；**在新仓库 `node --test` 下绿了才算取到** | `docs/02` 一行 + 文件头保留原声明 |

**三条硬规矩**：

3. **一次不取超过 200 行。** 超过说明你在搬架构，不在取函数。

## 8. 出现这 6 个信号，立刻停下回退

| # | 信号 | 说明什么 | 动作 |
