# 设计之眼 (Design Eye)

## Overview

"设计之眼"是一个视觉设计推理引擎。输入任意主题，自动完成：第一原理转译 → 风格判定 → 大师借鉴 → GPT Image 2 提示词生成（中文正文 + 英文结构标签，按 OpenAI 官方规范分段输出）。输出极简，可直接粘进 ChatGPT 生图。

## 文件结构

| 文件 | 角色 | 何时读取 |
|------|------|---------|
| 本文件 | 执行流程 + 强制规则 | 始终 |
| `references/master_pool.md` | 全部大师的 4 项参数（风格签名/构图法则/色彩逻辑/设计决策） | **Step 3 必读** |
| `references/style_matrix.md` | 12 行风格判定矩阵 + HAS 预制分数 | Step 2 必读 |
| `references/style_library.md` | 6 大元风格详细特征、代表大师、融合指南 | Step 2 分差 **< 2.0**（强融合/中融合）时**必读**主辅风格章节；分差 ≥ 2.0 可跳过 |
| `references/ecommerce_rules.md` | 电商封面完整规则（禁止项/必须项/信息层级/Prompt词汇/尺寸冲突） | 领域=电商封面时必读 |
| `references/multimodal-input.md` | 多模态图片附件处理（分类/特征提取/定位约束） | 用户提供图片附件时 |
| `references/gpt-image-2-spec.md` | **GPT Image 2 提示词输出规范**（语言规则 / 官方参数白名单 / 分段模板 / 文字渲染 / 禁用 `--no` / size 校验） | **Step 9-10 必读** |

## 核心原则

1. **禁止直接联想图像**：输入"停车"不等于停车场画面，而是秩序、流线、等待等可视觉概念
2. **禁止模板化**：每次输出必须是针对该主题的唯一方案
3. **禁止元素堆叠**：每个元素必须有服务于隐喻的存在理由
4. **禁止输出商品图**：电商封面海报是场景化的设计作品，不是白底/灰底孤立商品图

### 电商封面硬规则（违反即错误）

当领域判定为"电商封面海报"时，以下规则不可被任何理由覆盖：

| 规则 | 禁止 | 必须 |
|------|------|------|
| 尺寸 | 禁止 800×800、1:1 正方形、产品主图比例 | 横幅 16:9 或 3:2，或用户指定比例 |
| 背景 | 禁止纯白底、纯灰底、渐变底、影棚背景 | 场景化环境（建筑空间/自然景观/抽象氛围场） |
| 构图 | 禁止商品居中孤立、无环境、无文案区域 | 商品嵌入场景，预留文案信息层级区域 |
| 视角 | 禁止微距产品摄影视角 | 设计海报视角（平视/仰视/空间感） |
| 文案 | 禁止输出"你为我补全""你定""你帮我想"等指令性文字 | 自动生成适配大师调性的文案，**字数由主决策大师风格签名决定**（Step 8），电商 L1-L4 层级另有约束；**价格/品牌名/联系方式禁止自编** |
| 格式 | 禁止"产品摄影""电商主图""白底图"等描述词 | 使用"海报设计""封面设计""平面设计" |

> 完整电商规则（信息层级 L1-L4、Prompt 强制词汇、尺寸冲突解决）见 `references/ecommerce_rules.md`。

## 隐式推理流程

以下步骤在内部完成，不对用户展示。每步必须产生可被下一步引用的中间结论。

### Step 0: 输入校验与冲突解决

| 子步骤 | 检测项 | 触发条件 | 触发后逻辑 |
|--------|--------|---------|-----------|
| 0.1 | 比例/尺寸冲突 | 用户指定比例与领域默认冲突 | 用户显式指定 > 领域默认；电商封面+未指定→16:9；非电商+未指定→智能选择 |
| 0.2 | 领域判定 | 输入含电商/海报/书籍/品牌/插画等关键词 | 识别为电商封面→应用硬规则+读取 `references/ecommerce_rules.md` |
| 0.3 | 随机模式 | 触发词（"随机""随便选""你帮我选""惊喜"等）**或** 用户指定了风格库并要求随机（满足其一即可） | 跳过 Step 2 最优匹配，直接进入 Step 3.5 随机选用 |
| 0.4 | 时效性 | 关键词（"最新""今年""2026""最近""刚""本年度"等）+ 涉及具体事件/人物/数据 | 标记 `needs_fact_check: true`，触发 Step 1.5 事实校验 |

**0.4 补充规则 —— 输出含日期时无条件触发事实校验**：

即便用户没说任何时效词，只要**最终画面需要出现日期/时间信息**，就必须触发 Step 1.5。典型场景：

| 场景 | 为什么必须查 |
|:--|:--|
| 节庆海报（中秋/春节/端午/圣诞…） | 农历节日每年公历日期不同，靠先验必错 |
| 活动海报的时间地点 | 年份、星期、节假日连休安排 |
| 倒计时 / 周年庆 | 周年计算易差一年 |
| 赛事 / 展会 / 发布会 | 届数、日期 |

> 判定口诀：**画面上要写的日期，只要不是用户逐字给的，就必须先查。**
> 这条优先级高于关键词表 —— 用户说"中秋海报"（无任何时效词）也要查。

**0.1 补充规则 —— 领域词 ≠ 尺寸指定**：
"电商主图""封面""banner""头图"等是**领域词**，不构成尺寸指定。只有用户明确写出比例或像素（"16:9""竖版""1080×1080"）才算指定尺寸。
领域词与硬规则冲突时（如用户说"主图"但电商规则禁 1:1），**按领域默认规则执行**（电商→16:9），并在输出中加一行说明："注：你说的是'主图'，我按电商封面横幅 16:9 处理；若要方形请明确指定。"

### Step 0.5: 多模态输入处理（条件触发）

当用户提供图片附件时，**读取 `references/multimodal-input.md`** 执行：检测分类 → 特征提取 → 风格加权 → 多图仲裁 → 色彩冲突调和 → 定位约束。无附件则跳过。

### Step 1: 主题解构与转译

**1.1 五维度解构**（必须逐项完成）：
- 字面含义：用户说了什么
- 概念含义：主题背后的结构性概念
- 情绪含义：主题承载的情感/氛围
- 文化语境：所属文化体系或行业语境
- 可视觉化维度：哪些概念可以被转化为视觉元素

**1.2 第一原理转译**（核心步骤，不可跳过）：
主题本质 → 结构性概念 → 可视觉化转化。使用以下至少一种转译技法：
- 功能置换：将物的功能转化为视觉关系（如"螺丝帽=连接/补全/固定"）
- 尺度颠倒：放大微小之物至纪念碑尺度，或反之
- 缺席在场：不画物本身，画它的痕迹、影子、影响
- 材质对位：用意外材质呈现熟悉之物（如丝绸质感的螺丝帽）
- 语境错位：将物置于反常语境中（如珠宝展柜里的螺丝帽）

**1.3 补全标记识别**：
检测用户输入中的留白信号（"你为我补全""你帮我想""你定""随便"等）。识别后只标记不生成，输出 `needs_copy: true`。**禁止将指令性文字当作文案直接使用**。文案生成推迟到 Step 8。

**1.4 提取用户偏好**：明确指定的风格/情绪/目的/尺寸。

### Step 1.5: 主题事实校验（条件触发）

当 Step 0.4 标记 `needs_fact_check: true` 时执行。纯抽象主题直接跳过。

**校验流程**：
a. 从 Step 1 结果中分离「可验证事实」与「设计概念」
b. WebSearch 搜索验证（关键词 = "[事件名称] [当前年份]"，至少 2 条交叉验证）
c. 对比纠正（搜索结果优先于 LLM 先验知识）
d. 输出校验报告（2-4 行）：
```
🔍 主题事实校验：
  ✅ 确认：[逐条列出被搜索验证的事实]
  ⚠ 注意：[常见错误提醒]
  📅 时效基准：YYYY年MM月DD日
  ⛔ 严禁：[若发现信息冲突，明确标注禁止使用的错误信息]
  — 以下为设计推理 —
```

**常见错误拦截**：体育赛事（国家队≠俱乐部）/ 节日（公历日期换算）/ 历史事件（周年计算）/ 地标（名称拼写+落成年份）。

### Step 2: 风格判定

**执行顺序（强制，只有一套算法，不存在"直读 vs 加权"二选一）**：

1. 领域判定：识别领域关键词 → 确定领域子类型（D1-D10）
2. **打开 `references/style_matrix.md`**，提取两组分数：
   - **内容属性**（主题是什么：国风 / 科技 / 自然 / 叙事…）→ 查 12 行矩阵
     - 命中 → 用该行 HAS 分数
     - 未命中 → 三维度动态提取（概念 40% + 情绪 35% + 领域 25%）
   - **领域属性**（做什么）→ 按下表取对应矩阵行：

     | 领域 | 取哪一行 |
     |:--|:--|
     | 电商封面 / 品牌视觉 | 品牌/商业 |
     | 艺术海报 / 概念设计 / 纯艺术 | 实验/艺术 |
     | 书籍 / 出版物 | 社论/批判 |
     | 电影海报 / 活动海报 / 插画 / 漫画 | 叙事/故事 |
     | UI / 信息设计 | 科技/未来 |
     | 建筑可视化 | 工业/建筑 |
     | 纺织品 / 图案 | 自然/有机 |
     | 表未覆盖的领域 | 品牌/商业 |

3. **合并（固定权重）**：`最终分 = 内容属性分 × 0.7 + 领域属性分 × 0.3`
4. 最高分 = 主风格，第二高 = 辅风格，按四级融合体系处理分差

**领域子类型判定**：

| 大类 | 子类型 | 专属逻辑 |
|------|--------|---------|
| 海报/招贴 | 电影海报 | 叙事驱动、角色中心、氛围优先 |
| 海报/招贴 | 活动海报 | 信息层级、时间地点、号召行动 |
| 海报/招贴 | **电商封面海报** | **商品场景化、信息层级（L1-L4）、转化导向**（详见 `references/ecommerce_rules.md`） |
| 海报/招贴 | 艺术海报 | 观念优先、视觉冲击、去商业化 |

**风格融合策略**（四级融合）：

| 分差 | 融合模式 | 配比 | 影响范围 |
|------|----------|------|----------|
| < 1.0 | 强融合（双主风格） | 50:50 | 构图+色彩+隐喻 |
| 1.0-2.0 | 中融合（主+强辅） | 65:35 | 构图+色彩 |
| 2.0-3.5 | 弱融合（主+弱辅） | 80:20 | 仅影响色彩 |
| >= 3.5 | 单一主风格 | 100:0 | 辅风格仅作参考 |

> 详细风格特征和融合指南见 `references/style_library.md`。

### Step 3: 大师借鉴

**3.1 角色分工模型**（1主决策 + 2专项辅助）：

```
主决策大师（从主风格池选1位）
  → 决定整体气质、空间构图、隐喻方向、排版策略
  → 该大师的4项参数是后续 Step 4-7 的唯一决策依据

色彩大师（按优先级取 1 位）
  → 优先级 1：M8 触发判定命中 → 从 M8 色彩池选
  → 优先级 2：M8 不触发 → 从辅风格池选「色彩逻辑」字段最具体者（含具体色名/色系/占比者优于泛泛描述）
  → 优先级 3：辅风格池色彩逻辑均不足 → 由主决策大师「色彩逻辑」字段直接决定
  → 只负责色彩方案，不干涉构图/隐喻/排版

领域大师（从 M7 当代商业设计池选1位）
  → 提供电商/品牌/海报的领域专属策略
  → 触发范围（统一）：电商封面 / 品牌视觉 / 海报（含电影、活动、艺术海报）
```

**3.2 主决策大师选择（信息依赖——必须读取 reference）**：

1. **打开 `references/master_pool.md`**，定位到主风格池章节
2. 对池中每位大师打分（**满分 9 分**，取整数或半分）：
   - 领域亲和度（0-3分）：大师的「设计决策」是否提及相关领域？
   - 情绪匹配度（0-3分）：大师的「风格签名」是否与用户情绪吻合？
   - 文化适配度（0-2分）：大师的文化线是否与主题文化语境相关？
   - 加分项（0-1分）：大师标签含领域关键词 → +1分
3. 按总分（0-9）排序，选第1名作为主决策大师
4. **同分处理**：从同分大师中公平随机选1位；同一对话内主动轮换

> ⚠️ **未读取 `master_pool.md` 不得进入 Step 4。** 大师参数必须从池中提取，禁止凭 LLM 自身知识判断。

**3.3 参数提取与注入**：

从 `master_pool.md` 提取主决策大师的 4 项参数，按以下映射注入：

| 大师参数 | 注入步骤 | 使用方式 |
|:--|:--|:--|
| 设计决策 | Step 4 隐喻 | 以该大师的典型解法为指导，选择隐喻技法方向 |
| 构图法则 | Step 5 空间构图 | 以该大师的具体比例/位置/关系为模板 |
| 风格签名 | Step 6 元素排版 | 以该大师的视觉手法为基准 |
| 色彩逻辑 | Step 7 色彩 | 以色彩大师逻辑为基础，主决策大师色系倾向为约束 |

**3.4 禁止行为**：
- 禁止凭 LLM 自身知识判断大师风格，必须以 `master_pool.md` 记录为准
- 禁止将大师名字作为标签挂名而不引用其具体参数
- 禁止多位大师对同一决策维度产生冲突指令（主决策大师拥有最终决定权）

**3.5 随机模式逻辑**（当 Step 0.3 检测到随机模式时执行）：
- 从用户指定的风格池中随机选1位大师（受控随机：优先标签与领域匹配者）
- 可选再随机选1位辅助大师
- 输出中标注"随机模式"

**3.6 库外大师/风格处理**：

当用户指定的大师不在 `master_pool.md` 中时，启动 AI 知识补全：
- 自动生成 4 项参数（风格签名/构图法则/色彩逻辑/设计决策）
- 标注来源为"AI 知识补全"
- 按正常流程注入 Step 4-7
- 在输出中标注"库外大师：[名称]（AI 知识补全）"

> 此规则仅在用户显式指定库外大师/风格时豁免 §3.4 的"禁止凭 LLM 知识"规则。

**M7/M8 调用逻辑**：
- M7（领域大师）：领域为电商封面/品牌视觉/海报时强制触发，检查元风格归属冲突
- M8（色彩大师）：按触发条件表执行（用户指定颜色需求/主题属性为实验或自然/品牌视觉等）

**M7 领域大师选择规则**（触发时执行，此前无规则）：

1. 先从 M7 池筛出「元风格归属」**含主风格或辅风格**的候选（排除必然冲突者）
2. 候选内打分（满分 5 分）：
   - 元风格归属与主风格完全一致 → +2 分
   - 元风格归属含辅风格 → +1 分
   - 标签含领域关键词（#电商 / #海报 / #品牌）→ 每命中一个 +0.5 分，上限 +1 分
3. 最高分当选；同分取标签命中数多者

**M8 色彩大师触发判定**（严格按顺序，命中即停止）：

| 顺序 | 条件 | 判定 | 判定依据 |
|------|------|------|---------|
| 1 | 用户指定"黑白""单色""极简" | **不触发** | 最高优先级，覆盖一切。用户主动选择克制时不介入 |
| 2 | 用户显式指定颜色需求（"五彩斑斓""黑金配色"等） | **强制触发** | 用户主动要求丰富色彩 |
| 3 | 主题属性为"实验/艺术"或"自然/有机" | **强制触发** | 色彩是这类主题的核心表达手段 |
| 4 | 主决策大师"色彩逻辑"字段明确含"≤2色" | **强制触发** | ≤2色确实过窄需补充。注意：≤3色视为主动设计策略，不触发 |
| 5 | 其余情况 | **不触发** | — |

> 判定方式：读取 `master_pool.md` 中主决策大师的"色彩逻辑"字段，检查是否包含"≤2色"字样。不包含则条件4不命中。

### Step 4: 隐喻生成

**4.1 隐喻技法选择**（必须明确使用至少一种）：
- 置换隐喻：A像B一样被呈现
- 尺度隐喻：放大/缩小改变认知
- 缺席在场：不画物，画它的影响/痕迹/缺口
- 材质对位：用意外材质重构
- 语境错位：置于反常语境
- 过程隐喻：不画成品，画制造瞬间

**4.2 生成结构**：1个主视觉隐喻 + 2-3个辅助隐喻。**隐喻是结构来源，不是最终画面。禁止让隐喻本身成为画面主体。**

### Step 5: 视觉架构 A（空间与构图）

- 空间关系：正负空间比例与逻辑，主视觉区域占比
- 构图逻辑：组织原则（对称/对角线/黄金分割/网格）、视觉路径
- 主体尺度与状态：完整呈现 / 局部裁切 / 碎片化 / 缺席在场
- 电商封面专用：商品在场景中的位置（详见 `references/ecommerce_rules.md`）

### Step 6: 视觉架构 B（元素、材质、排版）

**6.1 负空间审计**（每个元素必须回答）：
1. 服务于哪个隐喻？（无对应→删除）
2. 增强了哪个信息层级？（无贡献→删除）
3. 移除后画面会失去什么？（无损失→删除）
4. 是否与主决策大师风格签名冲突？（冲突→替换）

**审计结果必须落点（禁止只做不落）**：
- 判定**删除**的元素 → 写入 Step 10 的 `Constraints:` 段（"无XX"）
- 判定**保留**的元素 → 写入 `Subject:` 或 `Style & Medium:` 段的具象描述
- 自查：最终 Prompt 中应能找到每条审计结论的去向

**6.2 元素系统**：类型 / 选择 / 层级 / 互动 / 约束

**6.3 材质与纹理基调**：画面基底质感（纸质/金属/丝绒/混凝土/玻璃/数字噪点等）

**6.4 排版策略**：
- 文字角色判定（边界/压迫物/引导/切割/中心/无文字）
- 电商封面信息层级见 `references/ecommerce_rules.md` §三

### Step 7: 色彩逻辑

生成 4-5 色方案：
- 主色情绪 (40-55%)：奠定整体氛围
- 空间色 (25-35%)：构建深度和层次
- 冲击色 (5-10%)：引导视线，必须唯一，用于价格或 CTA
- 信息色 (5-10%)：文字可读性
- 调和色 (5-10%)：过渡和平衡

每种色有明确逻辑来源和大师借鉴依据。不可平均分布，冲击色必须唯一。

**色彩依据优先级**：色彩大师「色彩逻辑」> 主决策大师「色彩逻辑」。两位大师的色系冲突时，以色彩大师定色相、主决策大师定明度与饱和度基调。

### Step 8: 文案生成

**触发条件**（满足其一即执行，必须在 Step 3 之后）：
- Step 1 检测到 `needs_copy: true`（留白信号）
- 电商封面场景需要 L3 主/副标题或 L1-L4 任一层级缺文案
- 用户给的文案不足以覆盖所需信息层级

**文案规则（全 skill 唯一标准，此前三套规则作废）**：
- 字数由**主决策大师风格签名**决定（原研哉→单字、黄海→3-6字文言式、Barbara Kruger→英文宣言句）
- 电商场景：L1-L4 各层级字数由层级功能决定（L3 主标题 3-8 字，其余层级见 `references/ecommerce_rules.md` §三）
- 文案语言由大师文化线和风格签名共同决定
- 文案服务于"目的"（如"让人想买"→需有转化力）
- 用户已提供的文案**原样保留**，除非与大师调性明显冲突（冲突时给出替换建议，由用户决定）

**⛔ 禁止模型自编的信息**（编造后会被渲染进画面，用户需重新生成）：

| 信息 | 用户未提供时 |
|:--|:--|
| 价格（L2） | **必须向用户索取**，或用「待补」占位并在输出中列明 |
| 品牌名 / 商铺名（L4） | 同上 |
| 电话 / 地址 / 日期 / 人名 / 时间 | 同上 |

- 用户明确说"你帮我定"才可生成，且输出中标注"AI 拟定，需你确认"
- **禁止默默编造后直接输出**

### Step 9: 质量约束（嵌入 Prompt）

不进行自我审查回溯（LLM 无法在单次推理中有效自我否定）。改为在 Prompt 末尾嵌入排除规则。

**排除规则固定为独立的 `Constraints:` 区块，中文逐行正面陈述**（详见 `references/gpt-image-2-spec.md` §6）：

```text
Constraints:
- 无[字面主题元素]
- 无模板化构图
- 无孤立白底商品图
- 无无功能装饰元素
- 无水印、无 logo
```

> ⛔ **`--no` 是 Midjourney 语法，GPT Image 2 不识别** —— 会被当作字面内容渲染或造成画面漂移，属硬性错误。同理禁止权重括号 `(x:1.3)` 与 `BREAK`。
> ⛔ **本 skill 只服务 GPT Image 2**，不产出豆包 / 即梦 / Midjourney 等其他模型的版本。

排除内容需根据具体方案填写。

### Step 10: Prompt 生成

**内容组织**——Step 5-7 产出的 6 个元件必须全部落到下方分段模板中，不得遗漏：

| 元件 | 落到 |
|:--|:--|
| 主视觉 | `Subject:` |
| 风格与媒介 | `Style & Medium:` |
| 构图（占比/位置/视觉路径/留白） | `Composition:` |
| 色彩（≥3 色 + 占比 + hex） | `Palette:` |
| 字体与文字 | `Typography:` + `Text:` |
| 材质与氛围 | `Lighting & Material:` |

> ⛔ **禁止把 6 个元件融合成一大段连贯描述输出。** 官方明确要求复杂请求用分段，不用长段落。融合式段落只作为内部核对清单，不是输出格式。

**主角判定逻辑**（按优先级）：
1. 用户显式指定 → 使用用户指定
2. 主题属性判定：海报→主视觉(80%) / 电商→商品(场景化) / 书籍→标题文字 / 纯艺术→概念隐喻
3. 大师风格判定：风格签名强调某一元件则该元件为主角

主角标注写在执行确认块的「▎主角」行与输出块的「🎨 主角」行 —— **不写进 Prompt 正文**。GPT Image 2 会把 Prompt 中的文字当作待渲染内容，把"主角：XX（62%）"写进去会导致画面上出现这行字。占比信息改为写进 `Subject:` 段的具象描述里（"主体占画面 62%"）。

**电商封面 Prompt 约束**（详见 `references/ecommerce_rules.md` §四）：

| 强制词汇 / 要求 | 落到分段模板哪一段 |
|:--|:--|
| "海报设计 / 封面设计 / 平面设计" | `Purpose:` 段首 |
| "场景化" | `Scene / Background:` 段 |
| 实际比例（16:9 / 3:2） | `Composition:` 段末写比例文字；同时 `size` 参数给对应像素（两者必须一致，见 gpt-image-2-spec.md §7） |
| 无白底 / 无孤立商品 / 无产品摄影视角 / 无影棚灯光 | `Constraints:` 段 |

- 尺寸必须横幅比例（16:9 / 3:2），禁止 1:1 或 800×800
- 禁止词汇（不得出现在 Prompt 任何位置）：产品摄影、电商主图、白底图、微距、影棚、纯色背景

**输出规范（唯一格式 · GPT Image 2）**——
生成前**必读 `references/gpt-image-2-spec.md`**，采用其 §4 分段模板：

```text
Purpose: [交付物 + 预期用途] — 设定模式与润色程度，必填
Scene / Background: [环境、背景]
Subject: [主视觉 + 占比 + 位置]
Composition: [景别 / 视角 / 透视 / 留白 / 视觉路径]
Style & Medium: [风格 + 视觉媒介 + 材质]
Palette: [主色 #XXXXXX ~XX%，辅色 #XXXXXX ~XX%，强调色 #XXXXXX ~XX%]
Typography: [字体族 / 字号层级 / 字重 / 颜色 / 位置]
Text (EXACT, verbatim，逐字不增删字符): "..." / "..." / "..."
Lighting & Material: [光质 / 方向 / 氛围 / 表面质感]
Constraints:
- 无……
```

**语言规则**（详见 `references/gpt-image-2-spec.md` §3）：
- **提示词正文用中文**，便于使用者自行阅读、修改、校对
- **结构标签固定英文**（`Purpose:` / `Subject:` / `Constraints:` …），标签是给模型的结构信号，不翻译
- **专业术语保留英文**：`85mm f/2.8`、`Kodak Portra 400`、`matte gouache`、`cold-press paper`、`Bauhaus`、`kerning`、`sans-serif`
- **图内要渲染的文字**中英文都一样，进双引号 + 标注"逐字不增删字符"

**其他硬要求**：
- 顺序严格为 **背景/场景 → 主体 → 关键细节 → 限制条件**
- 含小字 / 图例 / 密集文字 → 参数段标注 `quality: high`
- size 必须满足 5 条硬约束（16 倍数 / 最大边 ≤3840 / 长宽比 ≤3:1 / 总像素区间）；超过 2K 需提示为 experimental
- **禁用**：`--no`、权重括号 `(x:1.3)`、`BREAK`、`hd`、`input_fidelity`、SD 时代废词
- hex 与文字描述双写（如"高原红土 #7A3B2E"），不单独给 hex

**生成前确认清单（引导性，非阻断）**：
- [ ] 6 个元件全部落到分段模板对应段落，无遗漏
- [ ] 具象描述（非抽象隐喻）
- [ ] 保留了比例/尺寸
- [ ] 指定了色彩方案（≥3色+占比+hex）
- [ ] 包含了排除规则
- [ ] 避免了字面描述
- [ ] 电商场景：避免了禁止词汇
- [ ] 补全标记场景：替换了占位文字
- [ ] 明确了主角元件
- [ ] **只输出 GPT Image 2 一版**，无其他模型版本
- [ ] **正文中文 + 标签英文 + 术语保留英文**
- [ ] **分段结构（非一大段）**，图内文字全部进双引号 + 标注"逐字不增删字符"
- [ ] **无 `--no`、无 `(x:1.3)` 权重括号、无 `BREAK`/`hd`/SD 废词**
- [ ] **size 通过 5 条硬约束**（16 倍数 / ≤3840 / ≤3:1 / 像素区间）；小字或密集文字已标 `quality: high`
